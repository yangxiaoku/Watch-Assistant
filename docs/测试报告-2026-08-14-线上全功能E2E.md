## 二、测试过程中发现并修复的问题（均已发布上线）

| # | 严重度 | 问题 | 修复 |
|---|---|---|---|
| 1 | **高** | **ToastStack 组件只 import 未挂载**：所有成功/失败 toast 只进 store、页面完全不渲染——部署版 aae965f 上"操作成功/失败无任何通知"，是通知体验差的主因 | 挂载 `<ToastStack />`（e59fe90） |
| 2 | **高** | **`/subscriptions` 深链 404**：后端 SPA 回退路由白名单漏了订阅页，直接访问/刷新该页返回原始 JSON 错误 | 补 `@application.get("/subscriptions")`（e59fe90） |
| 3 | 中 | 断网恢复后无"网络已恢复"提示（仅缓存读取过才有） | 恢复即提示（e59fe90） |
| 4 | 中 | 静默时段保存、通知接收开关无成功反馈 | 补 success toast（b5b3431） |
| 5 | 中 | 订阅创建/暂停/恢复无成功反馈 | 补 success toast（b5b3431） |

发布链：`aae965f → e59fe90 → b5b3431`，均已部署并验证（健康检查 release 正确、
新 bundle 生效、`/subscriptions` 返回 HTML、离线/恢复 toast 实测出现）。

## 四、遗留发现（未修复，待决策）

1. **「取消订阅」按钮是死按钮**（中等）：订阅卡片上的"取消"按钮无 @click 处理器，且后端
   `subscriptions` 模块没有 DELETE 端点（只有 create/list/get/check/pause/resume/observations）。
   当前点击无任何反应。建议二选一：
   - 后端补 `DELETE /api/v1/subscriptions/{id}`（服务层删除订阅 + 关联检查/观察记录，
     前端接按钮并加确认与 toast）；或
   - 前端暂时隐藏该按钮，避免"看似可点、点了没反应"。
2. **推送/整理/STRM/扫描类按钮在生产为启用态**（属预期，非缺陷）：按安全约束未点击，
   门禁与真实写链路不在本次范围；生产永久删除仍关闭。
3. 数据库中残留的 `cancelled` 状态测试订阅（tmdb 99228877/66733001/99229999 等）为历史
   测试数据，非本次产生，未做处理。
4. 本次测试产生的 2 条订阅（tmdb 27205、603）已从数据库删除（删除前已备份
   `watch-assistant.db.bak-20260814-090401`）。
