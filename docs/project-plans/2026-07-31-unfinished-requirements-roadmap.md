## 1. 总体判断

项目已经形成“资源发现 -> 检测/筛选 -> 任务/workflow -> 115 整理与 STRM”的主要骨架，但生产媒体库闭环尚未关闭。以下能力不能因为已有代码、接口或测试夹具就描述为已上线：

- 生产 115 自动整理、生产库存和生产 STRM。
- 自动订阅推送、洗版、隔离或永久删除。
- 稳定播放入口、真实媒体服务器兼容和元数据联动。
- 外部通知渠道、真实 Webhook 接收端、PWA Push。
- CLI/MCP 的完整写操作、跨平台和远程 HTTPS 验收。
- 实际数据库恢复、升级执行和跨需求自动化闭环。

所有涉及 115 写入、移动、重命名、隔离、清理和删除的动作继续遵守：契约验证、计划预览、人工确认、幂等、审计、receipt-before-verify，以及 `uncertain` 只读核对门禁。永久删除和生产 STRM 清理默认关闭。

## 2. 优先级和分组

### P0：先完成可独立验收的基础闭环

这些工作不要求立即打开生产写开关，适合当前继续开发：

| 顺序 | 需求 | 下一交付 | 依赖和退出条件 |
|---|---|---|---|
| 1 | REQ-009 端到端任务中心 | 运行中子任务取消、跨任务关联、完整阶段事件矩阵 | 先冻结各子系统可中止契约；取消必须可恢复、可审计，不能把已提交的远端写操作伪装成可取消 |
| 2 | REQ-012 通知中心 | 完整业务事件矩阵、静默时段、渠道健康模型和外部渠道适配边界 | 复用通知偏好、去重、Outbox 和死信；外部渠道必须有受控接收端和真实验收证据 |
| 3 | REQ-003 Agent CLI | 通知读写命令、STRM 查询/写入命令、整理计划生成和高风险 Web 批准 | CLI 只能调用版本化 API；高风险操作必须使用 digest/confirm、Scope、幂等键和统一退出码 |
| 4 | REQ-019 Webhook | 完整事件矩阵和真实 HTTPS 接收端验收 | 至少完成签名篡改、重放、服务重启恢复、重试/死信和端点禁用场景；未验收前保持自动投递受限 |
| 5 | REQ-017 备份恢复 | 实际恢复预览之后的停机恢复、失败回滚和恢复后校验 | 先完成恢复前快照、任务排空、迁移兼容矩阵和 Secret 重配提示；恢复不得隐式覆盖 115 文件 |

P0 的共同完成标准：离线测试、API/CLI 契约、结构化日志、中文错误映射和审计证据齐全；没有真实外部接收端或设备时，状态只能标记为待验收/阻断。

## 3. 建议里程碑

### M1：治理和入口闭环

完成 P0 中 REQ-009、REQ-012、REQ-003、REQ-019 的离线契约和受控外部验收；通知、Webhook、CLI、MCP 共用同一权限、Scope、幂等、状态机和审计语义。REQ-017 的实际恢复继续单独门控。

### M2：生产库存基线

由管理员明确配置生产目标 CID，完成一次新鲜、完整、可复核的只读扫描，建立稳定文件/目录身份、扫描完整度和增量账本。未达到 M2，不允许把生产目录当作可整理或可清理库存。

### M3：人工确认的媒体库闭环

完成整理计划、STRM 受管清单和稳定播放入口的受控验收；首个版本只允许人工确认、可恢复隔离和清理预览，禁止自动洗版、永久删除和未完整扫描清理。

### M4：自动追更闭环

接入订阅、质量、库存去重、缺集、通知和 workflow。自动模式默认关闭，先运行观察账本和待确认队列，再依据真实失败率和重复执行证据决定是否开启局部自动化。

### M5：外部兼容和发布治理

完成 HTTPS/Webhook、MCP、PWA Push、媒体服务器、升级回滚和跨平台验收。所有发布必须从唯一 `codex/publish-main` 基线构建，并在提交后运行规定的验证脚本；缺少外部环境时记录为阻断，不用 fake 结果替代。

## 4. 每个需求的通用完成门槛

1. 需求主文档状态更新为实际状态，并在 `BLOCKERS.md` 记录剩余阻断和继续条件。
2. API、Web、CLI、MCP 共用认证、Scope、幂等键、状态机和错误码；用户可见文字保持中文。
3. 新增状态变化写入结构化日志、持久审计和必要的站内/外部通知，且敏感字段脱敏。
4. SQLite 迁移向前、幂等；发布前完成在线备份，恢复路径可演练。
5. 变化范围有单元、集成或契约测试；涉及前端交互补桌面和 360px 移动端回归。
6. 外部写操作使用专用低风险夹具、功能开关、receipt-before-verify 和回滚记录。
7. 真实环境验收不得把 Cookie、Token、磁力、pickcode、完整播放 token 或真实直链写入代码、日志、文档、截图、fixture 或命令输出。

## 5. 当前不应做的事情

- 不因接口已存在就开启生产 115 整理、STRM 生成、清理、洗版或自动推送。
- 不用测试目录、fake 来源、假接收端或抽样媒体服务器结果替代生产验收。
- 不在第三方契约未验证时猜测外部 API，不调用内部 `.pyc`，不修改第三方数据库。
- 不在扫描不完整、身份不稳定或操作状态为 `uncertain` 时执行删除、隔离或重复写入。
- 不创建与 `REQ-013` 冲突的新目录或复用该编号。

## 6. 更新规则

每完成一个独立切片，先补测试和证据，再更新对应 REQ、`BLOCKERS.md` 和 `PROGRESS.md`；若依赖或环境发生变化，更新本路线图的排序和退出条件。未合入 `codex/publish-main` 的分支只表示开发中，不表示需求完成或已发布。
