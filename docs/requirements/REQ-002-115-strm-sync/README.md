## 2. 背景与问题

仅支持手工或定期全量生成 STRM 无法满足持续变化的影视库：扫描成本高、变化反馈慢、字幕和 NFO 容易不同步、云端文件删除后本地残留失效 STRM。项目需要从“一次性生成器”升级为持久的目录对账系统。

## 3. 产品目标

- 对指定 115 媒体库完成可取消、可续跑的 STRM 全量生成。
- STRM 使用稳定播放入口和 pickcode/受管标识，播放时快速获取最新直链。
- REQ-001 整理后只更新实际变化目录。
- 同步字幕、封面、NFO、独立音轨和允许的其他元数据。
- 安全清理失效 STRM 和系统创建的空目录。
- 同目录任务去重，处理中再次变化时自动重入队。
- 保证清单、STRM 和云端目录最终一致。

## 4. 非目标

- 不转码、不代理完整视频流作为默认模式。
- 不在 STRM 中保存 115 Cookie 或有时效真实直链。
- 不清理非系统受管文件。
- 不在扫描不完整时执行删除阶段。
- 不允许通过播放接口访问媒体库范围外的任意 pickcode。

## 5. 用户场景

### 5.1 首次建立媒体库

用户选择一个 115 媒体库执行全量生成。系统分页扫描视频、建立清单、原子写入 STRM、同步元数据，并输出成功、失败、跳过和待重试数量。

### 5.2 整理后自动更新

REQ-001 移动或重命名一部电影。系统把源目录和目标目录标记为 dirty，只更新相关 STRM 和元数据，不重扫整库。

### 5.3 目录处理中再次变化

同一目录正在同步时再次新增文件。系统不启动第二个并发任务，而是增加目录版本并标记 dirty；当前任务完成后再执行一次。

### 5.4 失效项维护

云端文件被删除或移入隔离区。系统在扫描完整的前提下删除对应受管 STRM；含用户文件的目录不会被删除。

## 7. 详细需求

### 7.1 输出映射与受管清单

每个 115 媒体库映射一个本地 STRM 根目录，默认镜像云端相对目录结构。

清单至少记录：

- 媒体库、云端目录 ID和文件 ID。
- pickcode、云端相对路径、大小和修改版本。
- 本地 STRM 和元数据相对路径。
- 内容摘要、同步状态、最后核对时间和来源任务。

同一云端视频在同一媒体库只能有一个 current 清单条目。系统后续只能修改清单内或带系统受管标记的本地文件。

### 7.2 全量生成

全量任务流程：

1. 分页扫描允许范围内的目录和视频。
2. 建立本轮扫描快照并标记 `complete=false`。
3. 读取文件 ID、pickcode、路径、大小和修改时间。
4. 先创建或更新 STRM 与元数据。
5. 扫描全部分页成功后标记 `complete=true`。
6. 仅在 `complete=true` 时生成清理计划。
7. 输出统计并保存 checkpoint。

要求：

- 支持取消和断点续跑。
- 取消或失败不得留下半写文件。
- 使用临时文件和原子替换。
- 不一次性把整库加载到内存。
- 任务重启后从持久 checkpoint 恢复。

### 7.3 STRM 内容与动态直链

STRM 不保存真实直链和 115 Cookie，而是指向 Watch Assistant 的稳定播放入口。播放入口使用受管清单中的不透明 ID 解析 pickcode；是否在 STRM 内携带 play token 必须经过安全评审。

示意：

```text
https://watch-assistant.example.ts.net/api/v1/strm/play/<opaque-manifest-id>
```

播放要求：

- 按需用 pickcode 向 115 获取最新直链。
- 成功后返回 HTTP 重定向，不默认代理完整媒体流。
- 支持媒体服务器常用的 `HEAD`、`GET` 和 Range 场景。
- 使用安全短时缓存和并发单飞，减少重复请求。
- Cookie 失效、文件失效和上游限流返回稳定错误码。
- 库外、已撤销、已失效或越权标识必须拒绝。
- 日志不得记录真实直链、Cookie、完整 token 或原始 pickcode。

### 7.4 目录级增量

变化与动作映射：

| 云端变化 | 本地动作 |
|---|---|
| 新增视频 | 创建 STRM 和清单 |
| 视频重命名 | 创建新路径并清理旧受管路径 |
| 视频移动 | 更新源目录和目标目录 |
| 视频删除或隔离 | 标记失效并进入清理计划 |
| pickcode 变化 | 更新清单，STRM 稳定入口不变 |
| 新增或修改元数据 | 增量下载或生成 |
| 删除元数据 | 按受管清单和配置生成清理动作 |

REQ-001 的整理事务必须同时标记源目录和目标目录。外部人工修改由周期补偿扫描发现。增量任务不得无条件扩展为整库扫描。

### 7.5 元数据同步

支持：

- 字幕：`srt`、`ass`、`ssa`、`sub`、`vtt`。
- 图片：`jpg`、`jpeg`、`png`、`webp`。
- NFO：电影、剧集、季度和单集。
- 独立音轨：`mka`、`aac`、`ac3`、`eac3`、`dts`、`flac`、`mp3`。
- 用户配置允许的其他扩展名。

规则：

- 扩展名、单文件大小和总并发可配置。
- 115 已有元数据默认优先，缺失时可由 TMDB 生成 NFO、poster 和 fanart。
- 同名字幕保留语言、forced 和 SDH 标记。
- 使用文件 ID、大小、修改时间或摘要判断变化。
- 未变化文件不得重复下载。
- 写入失败保留旧版本，且不影响主 STRM 可用性。
- 独立音轨默认关闭自动同步。

### 7.6 清理

可以清理：

- 云端文件已删除、移出媒体库或进入隔离区的受管 STRM。
- 路径变化后被新路径替代的旧 STRM。
- 已删除且允许镜像删除的受管元数据。
- 由系统创建且不含任何文件的空目录。

保护规则：

- 默认先生成清理计划，不直接删除。
- 扫描不完整、上游分页异常或目录版本变化时禁止执行计划。
- 不删除非受管文件。
- 不删除含非受管文件的目录。
- 不删除 STRM 根目录、媒体库根目录或保护目录。
- 清理必须记录计划 ID、清单版本、数量和结果。
- 本地回收站或延迟删除作为 Should 能力。

### 7.7 目录去重与 dirty 状态

去重键为“媒体库 ID + 稳定云端目录 ID”，不得只使用路径。

```text
clean -> queued -> running -> clean
                   |   ^
                   v   |
                 dirty-+
running -> failed -> retry_wait -> queued
```

- 同目录同一时刻最多一个任务。
- 已 queued 再变化只增加目录版本。
- running 再变化标记 dirty。
- 任务完成后如果版本前进，立即再执行。
- 失败采用指数退避和最大重试次数。
- Cookie 失效等全局错误暂停同类任务。
- 重启恢复 queued、dirty 和 retry_wait；遗留 running 先核对清单和输出。

### 7.8 校验和修复

校验任务检查：

- 清单与云端文件是否一致。
- STRM 是否存在、内容是否符合模板。
- 元数据是否缺失或过期。
- 是否存在失效项、孤儿清单或非预期重复项。

校验默认只读。修复前生成动作计划，清理类修复仍需明确确认。

当前已实现受保护的只读校验 API 和 `watchctl strm verify`：它基于最新完整扫描，对当前
受管清单逐项检查 STRM 是否存在、路径是否一致、内容是否为稳定播放入口，并报告孤儿
manifest。该能力不会修复本地文件、退休清单或执行 115 写入；生产播放入口、元数据
联动和三种媒体服务器验收仍未完成。

## 8. 管理界面与 API 要求

工作台展示：

- 每个媒体库最近全量、最近增量和下次补偿扫描时间。
- STRM 总数、有效数、失效数、元数据数和失败数。
- 当前目录、完成进度、dirty 队列和重试时间。
- 全量生成、目录同步、校验、清理预览和失败重试入口。

API 必须异步返回任务 ID。危险操作采用计划 ID + 摘要 + 目录版本确认。REQ-003 通过同一 API 管理，不提供 CLI 专用绕过路径。

## 9. 数据与审计要求

需要持久化：

- STRM 媒体库映射。
- 受管清单和扫描快照。
- 目录版本、dirty 状态和任务租约。
- 全量 checkpoint、增量事件和重试状态。
- 元数据同步和清理计划。
- 直链短时缓存的非敏感索引。

日志和审计遵循 REQ-004。播放日志只记录请求 ID、媒体库 ID、不透明清单 ID、结果、耗时和错误码。

## 10. 非功能要求

- 100 个以内文件变化的增量任务，95% 在触发后 5 分钟内完成，最终按真实环境校准。
- 直链缓存命中时 95% 在 500ms 内返回重定向。
- 同一目录并发固定为 1，不同目录并发可配置。
- 未变化目录不重写 STRM、不重复下载元数据。
- 任意单目录失败不阻塞其他目录。
- 本地路径必须防止穿越、符号链接逃逸和越根操作。

## 11. 验收标准

- 指定媒体库全部支持视频都生成唯一有效 STRM。
- STRM 不包含 Cookie、真实直链、原始 pickcode 或完整敏感 token。
- Emby、Jellyfin、Plex 完成扫描、开始播放、拖动和续播验证。
- 新增、移动、重命名和删除只更新受影响目录。
- running 期间再次变化会自动再执行一次且无并发重复。
- 字幕、封面和 NFO 按配置同步，未变化文件零重复下载。
- 扫描不完整时不会执行任何删除。
- 非受管文件和含非受管文件的目录零误删。
- 服务重启后任务和 dirty 状态恢复。
- Cookie 失效时播放和同步返回明确中文错误，不泄漏凭据。

## 12. 分期建议

1. 115 列目录、pickcode、元数据下载和动态直链契约验证。
2. 受管清单和全量生成。
3. 三种媒体服务器兼容性验证。
4. REQ-001 事件驱动的目录增量。
5. 元数据增量和安全清理。
6. 校验、修复、通知和性能优化。

## 13. 风险与依赖

| 风险 | 缓解措施 |
|---|---|
| pickcode 稳定性不明确 | 验证移动、重命名、复制；以文件 ID为主标识 |
| 媒体服务器行为差异 | 三端 HEAD/GET/Range/续播矩阵 |
| 115 限流 | 缓存、单飞、限流和退避 |
| 全量扫描分页不完整 | complete 标记，不完整禁止清理 |
| 本地目录含用户文件 | 受管清单、保护目录和清理计划 |
| 播放入口泄漏 | 不透明 ID、网络限制、脱敏日志 |
