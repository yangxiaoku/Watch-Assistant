## 1. 一句话定义

用户点击电影或剧集后立即进入并展示已有影视资料，详细资料和资源搜索分别渐进加载；磁力与 115 分享只在资料下方的独立区域加载、失败和重试，不再阻塞整个详情页。

## 2. 背景与缺陷现状

当前详情流程把影视资料与资源聚合绑定在同一个结果对象上：

1. 用户点击影视条目。
2. 前端清空已有 `result`。
3. 页面进入整页“正在聚合资源”。
4. 前端等待 `/api/v1/search` 同时返回 TMDB 资料和资源结果。
5. 请求完成后才渲染海报、标题、简介和资源列表。

这导致：

- 列表中已经存在的海报、标题、年份和简介被主动丢弃。
- PanSou、缓存或资源标准化越慢，用户看到空白加载页越久。
- 资源搜索失败时，影视资料也无法展示。
- 用户不能先阅读简介、查看季度或执行收藏等不依赖资源的操作。
- 切换电视剧季度会再次清空详情，产生重复整页跳转感。
- “资料是否加载成功”和“资源是否找到”无法独立表达。

后端已经存在独立的影视资料读取和资源分页入口，但当前主交互仍使用组合搜索结果作为详情页渲染前置条件，需要重新定义页面状态和接口职责。

## 3. 产品目标

- 从已有列表进入详情时，首帧立即展示该条目的已知资料。
- 在不阻塞资料区的情况下刷新完整 TMDB 详情。
- 资源区位于影视资料下方，拥有独立加载、空状态、错误和重试。
- 资源搜索失败、超时或部分成功时，影视资料和其他功能保持可用。
- 切换季度时保留剧集主体资料，只更新季度内容和资源区。
- 返回浏览列表时恢复原筛选、分页和滚动位置。
- 避免旧请求覆盖新打开的影视或新选择的季度。
- 对首屏呈现时间、资料加载时间和资源加载时间分别度量。

## 4. 非目标

- 不要求影视资料和资源必须串行发起网络请求；要求的是展示和错误边界解耦。
- 不在列表页预先搜索所有影视的资源。
- 不因追求首屏速度而展示错误影视或跨影片缓存。
- 不取消资源缓存、分页、筛选、检测和刷新能力。
- 不让资源加载失败自动返回上一页。
- 不在本需求中重做详情页整体视觉设计。

## 5. 用户场景

### 5.1 从首页进入电影

用户点击电影卡片后立即看到海报、片名、年份、评分和已有简介。资料区下面显示“正在查找磁力和 115 分享”，完成后就地显示资源。

### 5.2 资源搜索失败

TMDB 资料正常展示，资源区显示“暂时无法加载资源”和中文原因，并提供“重新查找资源”。返回、收藏和查看资料不受影响。

### 5.3 直接打开详情链接

浏览器没有列表缓存。页面先显示与最终布局一致的资料骨架，影视资料返回后立即替换；资源区独立加载，不出现只写“正在聚合资源”的整页中转页。

### 5.4 切换季度

用户从第一季切换到第二季，剧集标题和主体页面保持稳定，季度资料区显示第二季骨架或缓存内容，资源区只加载第二季资源。

### 5.5 快速切换多个影视

用户连续打开 A、返回、再打开 B。A 的迟到响应不得覆盖 B 的资料或资源。

## 7. 目标加载流程

### 7.1 从列表点击进入

```text
点击影视卡片
  -> 写入详情路由和浏览返回状态
  -> 立即用列表已有数据渲染影视资料
  -> 并行刷新完整影视资料
  -> 在资料下方启动资源搜索
  -> 分别更新资料区和资源区
```

列表已有数据至少包括内部/TMDB ID、媒体类型、标题、年份、海报和可用简介。字段不足时使用稳定占位，不清空整个详情容器。

### 7.2 直接链接进入

```text
解析详情路由
  -> 渲染资料布局骨架
  -> 请求影视资料
  -> 身份确认后启动或恢复资源搜索
  -> 影视资料先到则立即展示
  -> 资源结果独立填充下方区域
```

影视资料请求失败时，资源搜索不得使用未经确认的媒体身份继续执行；页面保留返回和重试入口。

### 7.3 网络并行规则

- 从可信列表项进入时，已知 TMDB ID和媒体类型足以并行请求资料和资源。
- 视觉上必须先渲染资料，不要求等待浏览器下一次网络请求才显示。
- 深链参数通过校验后可以并行请求，但资源响应只能应用到相同路由版本。
- 资源请求较快返回时也必须填入资料下方区域，不替换整个页面。

## 8. 独立状态模型

影视资料状态：

- `summary_ready`：已显示列表摘要，完整资料仍在刷新。
- `metadata_loading`：没有可用摘要，正在加载资料。
- `metadata_ready`：完整资料已加载。
- `metadata_stale`：显示缓存资料，刷新失败或数据过期。
- `metadata_failed`：没有可展示资料，请求失败。

资源状态：

- `idle`：尚未开始或不应搜索。
- `loading`：正在查询来源或读取快照。
- `partial`：部分来源成功，可以展示部分结果。
- `ready`：搜索完成并有结果。
- `empty`：完整搜索完成但没有结果。
- `stale`：使用旧缓存或上游不完整。
- `failed`：无法取得可展示资源。

两个状态机独立。资源状态变化不能把 `metadata_ready` 重置为加载中。

## 9. 影视资料区要求

- 页面顶部稳定展示返回、海报、标题、原名、年份、媒体类型、评分和收藏。
- 列表摘要可先显示，完整资料返回后按字段更新，不重建整个页面。
- 更新字段时避免海报、标题和按钮发生明显布局跳动。
- 缓存资料刷新失败时继续展示缓存，并标注最后更新时间。
- 资料完全失败时显示“影视资料暂时无法加载”，提供重试和返回。
- 不在资料区展示“正在查询磁力”作为主标题。
- 电视剧季度资料遵循 REQ-029，不重复使用剧集总资料冒充分季资料。

## 10. 资源区要求

资源区固定在影视资料和简介之后，包含：

- 清晰区块标题，例如“可用资源”。
- 独立加载状态，例如“正在查找磁力和 115 分享”。
- 已完成来源、仍在等待来源和缓存时间的渐进摘要。
- 资源类型、质量、名称、排序和分页控制。
- 空结果、部分结果、使用旧缓存、失败和检测状态。
- “重新查找资源”“只重试失败来源”等安全动作。

规则：

- 加载时保持资料区和资源区标题可见，只在资源内容位置使用骨架或进度。
- 已有缓存资源时后台刷新不得清空列表；显示刷新状态并在完成后更新。
- 切换筛选和分页只影响资源列表，不重载影视资料。
- 手动刷新资源不重新请求无变化的影视资料。
- 资源失败不影响收藏、返回、季度浏览和资料阅读。

## 11. 接口职责

### 11.1 影视资料接口

`GET /api/v1/media/{media_type}/{tmdb_id}` 只负责返回影视资料，不触发 PanSou 或其他资源搜索。响应包含版本、新鲜度和缓存时间。

### 11.2 资源搜索接口

资源发现必须使用独立操作，产品语义为“为指定媒体身份查找资源”。可以采用同步响应、异步任务或渐进快照，但不得让影视资料接口等待资源完成。

建议契约：

- `POST /api/v1/media/{media_type}/{tmdb_id}/resource-search`：创建或复用搜索任务/快照。
- `GET /api/v1/media/{media_type}/{tmdb_id}/resources`：读取已产生的快照并分页。
- 返回资源状态、查询计划版本、参与来源、缓存年龄和任务 ID。

正式技术设计可以复用现有 `/search` 过渡，但前端不得再以组合 `SearchResponse` 作为渲染资料的唯一条件。

### 11.3 错误契约

资料和资源分别返回 REQ-027 结构化错误。错误必须说明失败的是“影视资料”还是“可用资源”，不能都显示“请求失败”。

## 12. 缓存与数据一致性

- 详情缓存键使用媒体类型、TMDB ID、语言和资料版本。
- 资源缓存键继续包含媒体类型、TMDB ID、季度、查询计划和筛选快照。
- 列表摘要、详情缓存和资源快照具有不同 TTL，不互相覆盖。
- 完整资料字段只覆盖对应影视 ID和路由版本。
- 缓存存在时先展示缓存，再后台验证；失败时标记 stale。
- 资源手动刷新只失效资源快照，不清除海报、简介和收藏状态。

## 13. 请求并发与竞态保护

- 每次详情导航生成不可重复的 `detail_request_id` 或前端版本号。
- 每次季度变化生成新的资源请求版本。
- 旧路由的资料和资源响应到达时必须丢弃。
- 浏览器取消等待不等于取消共享服务端搜索任务。
- 相同媒体和查询计划的并发资源搜索应由服务端合并。
- 页面卸载后停止无必要轮询，服务端任务可继续并在再次进入时恢复。
- 切换资源分页不得取消正在刷新影视资料。

## 14. 路由、返回与恢复

- 点击条目后立即更新可分享详情 URL。
- 浏览器刷新可以从路由恢复媒体类型、TMDB ID、季度和资源筛选。
- 返回浏览恢复来源页面、搜索词、筛选、分页和滚动位置。
- 详情资料加载失败仍保留当前 URL，方便重试和复制请求 ID。
- 季度切换使用同一详情页局部路由，不产生中转加载页。
- 前进/后退时可以使用缓存资料即时恢复，再按新鲜度刷新。

## 15. 加载、错误和空状态文案

遵循 REQ-027：

| 场景 | 标题 | 说明/动作 |
|---|---|---|
| 深链资料加载 | 正在加载影视资料 | 保留详情布局骨架 |
| 资源查询 | 正在查找可用资源 | 显示参与来源或阶段 |
| 完整空结果 | 暂未找到可用资源 | 提供刷新或补充关键词 |
| 资源部分成功 | 已显示部分资源 | 说明失败来源并可重试 |
| 资源失败 | 可用资源暂时无法加载 | 资料仍可查看，提供重试 |
| 缓存回退 | 当前显示缓存资源 | 显示缓存时间和刷新状态 |

不得使用整页“正在聚合资源”遮挡已经拥有的影视资料。

## 16. 性能与可观测性

分别记录：

- 点击到详情框架呈现时间。
- 点击到首个有意义影视资料呈现时间。
- 完整影视资料加载时间。
- 资源首批结果时间和资源完整时间。
- 详情缓存命中率和资源缓存命中率。
- 资源失败但资料成功的比例。
- 迟到响应被丢弃数量和请求取消数量。

建议目标：

- 从含摘要的列表进入时，95% 在 200 毫秒内呈现影视资料首屏，不包含海报图片网络解码时间。
- 缓存命中时资源区 95% 在 500 毫秒内显示已有结果或明确状态。
- 上游慢请求不得阻塞返回、收藏和资料阅读。

## 17. 无障碍与响应式要求

- 资料刷新和资源加载使用独立 `aria-busy` 区域。
- 屏幕阅读器不会因资源轮询反复朗读整个详情页。
- 资料骨架保留稳定尺寸，避免焦点和按钮位置跳动。
- 资源错误使用页面内 `role="alert"`，但不抢走正在阅读资料的焦点。
- 移动端先展示核心资料，再展示资源状态，不出现占满首屏的中转提示。

## 18. 日志与审计

遵循 REQ-004，记录：

- 资料读取、缓存命中、刷新失败和 stale 回退。
- 资源搜索创建、幂等复用、部分成功、完成、失败和取消等待。
- 详情/资源请求关联 ID、媒体身份、季度和耗时。
- 迟到响应丢弃、路由版本冲突和前端状态不一致。

不记录完整搜索词、资源链接、完整文件名或用户浏览历史正文。

## 19. 验收标准

### 19.1 首屏行为

- 从首页、搜索、收藏和历史列表点击影视后，立即显示已有海报、标题和摘要。
- 页面不再先进入整页“正在聚合资源”再跳到详情。
- 深链进入只显示资料布局骨架，资源加载不遮挡资料区域。

### 19.2 独立加载

- 影视资料和资源请求可以独立成功、失败和重试。
- 资源搜索超时或失败时，资料、返回和收藏仍可使用。
- 手动刷新资源不会让海报、标题和简介消失。
- 已有资源后台刷新时不会先清空当前结果。

### 19.3 导航与竞态

- 快速切换 A/B 影视时，A 的迟到响应不会覆盖 B。
- 切换季度只更新季度资料和资源区，不清空剧集主体页面。
- 返回浏览恢复原分页、筛选和滚动位置。
- 刷新详情 URL可以恢复正确影视和季度。

### 19.4 体验与性能

- 含摘要入口的首个有意义资料呈现达到第 16 节目标。
- 加载、空、部分、失败和缓存回退均有明确中文提示。
- 360 CSS 像素宽度下资料与资源加载状态无重叠和横向溢出。
- 屏幕阅读器可分别识别资料刷新和资源加载状态。

## 20. 分期建议

1. 拆分前端影视资料状态和资源状态，停止以组合结果阻塞详情。
2. 从列表项即时渲染资料，补充独立详情读取。
3. 将资源搜索移入独立区域，完善错误、重试和缓存。
4. 修复季度切换、深链、返回和迟到响应竞态。
5. 建立性能指标、无障碍和桌面/移动端回归测试。

## 21. 风险与依赖

| 风险 | 缓解措施 |
|---|---|
| 摘要与完整资料短暂不一致 | 标记版本，字段就地更新，不跨 ID合并 |
| 并行请求增加上游压力 | 服务端请求合并、独立缓存和查询预算 |
| 状态拆分增加前端复杂度 | 明确两个状态机和单向数据边界 |
| 旧响应覆盖当前页面 | 请求版本、AbortController 和路由身份校验 |
| 资源接口仍隐式依赖组合搜索 | 冻结独立资源搜索/快照契约 |

## 22. 待确认项与建议默认值

| 决策项 | 建议默认值 |
|---|---|
| 从列表进入 | 立即显示列表摘要 |
| 资料与资源请求 | 可并行，展示和错误边界独立 |
| 资源加载位置 | 影视资料和简介下方 |
| 资源刷新 | 保留当前结果直到新结果可用 |
