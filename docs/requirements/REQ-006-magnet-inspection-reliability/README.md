## 1. 一句话定义

降低磁力元数据检测的失败率，并把“资源本身不可检测、环境不可用、超时、已存在任务、兼容性问题”准确区分，让系统可以安全重试、复用结果和指导运维处理。

## 2. 现状与问题

当前检测流程使用隔离 qBittorrent sidecar，将磁力以 `stopCondition=MetadataReceived` 添加到 qB，等待元数据后读取文件列表，再清理临时任务。

当前实现和体验存在以下风险：

- 默认单条元数据超时为 30 秒，而检测契约文档仍描述 60 秒，配置与契约不一致。
- 默认并发为 8，弱网络、DHT 冷启动或受限服务器上可能同时放大超时。
- `metadata_timeout` 会缓存 30 分钟；用户立即点击重试可能直接得到相同负缓存，实际上没有重新检测。
- qB 已存在相同 torrent 时返回 `unsupported/existing_torrent`，即使已有任务已经取得完整元数据，用户仍看到“无法检测”。
- qB 不支持 `stopCondition=MetadataReceived` 时，会在每个资源上重复失败，而不是在 readiness 阶段提前禁用能力。
- 部分 qB 状态只被识别为 `pausedDL` 或 `stoppedDL`；版本状态差异可能被判为停止失败。
- DHT、PEX、LSD、UDP、DNS、出口网络和 qB 监听状态缺少明确健康诊断。
- 批次日志只提供粗粒度状态和数量，无法统计具体失败原因。
- 前端主要展示“检测失败、检测超时、无法检测”，没有原因和下一步建议。
- 适配器异常可能统一折叠为 `internal_error`，丢失可行动信息。
- 检测失败会造成用户对资源本身质量的误判，尽管失败可能只是环境问题。

## 3. 产品目标

- 建立可测量的检测成功率基线和失败原因分布。
- 在检测开始前验证 qB 版本、API、停止条件和网络 readiness。
- 对 DHT 冷启动和低活跃磁力采用分阶段、可配置等待策略。
- 手动重试明确绕过负缓存。
- 安全复用已存在且元数据完整的 qB torrent，不删除非本系统任务。
- 按错误类型决定是否重试、何时重试和是否暂停全局检测。
- 前端展示中文失败原因和处理建议。
- 检测失败不隐藏资源，也不自动把资源判定为坏资源。
- 通过缓存和相同 infohash 单飞减少重复检测。

## 4. 非目标

- 不保证没有任何活跃节点的死种可以取得元数据。
- 不为了提高成功率下载完整媒体内容。
- 不删除或修改用户现有 qBittorrent torrent。
- 不把检测失败等同于磁力无效。
- 不绕过网络安全策略开放任意出口。
- V1 不新增第二套 BT 引擎，除非 qB 方案经过数据证明无法达到目标。

## 5. 用户场景

### 5.1 DHT 冷启动

服务刚启动，qB API 可用但 DHT 节点数不足。系统显示“检测环境正在连接网络”，延迟批次或降低并发，而不是把所有资源记为失败。

### 5.2 低活跃磁力超时

30 秒未取得元数据后进入延长等待阶段，达到最终上限仍失败时显示“暂未获取到磁力元数据”，并允许稍后重新检测。

### 5.3 手动重试

用户点击“重试失败项”，系统绕过短期超时缓存并真正发起新检测，不直接复用 30 分钟内的失败结果。

### 5.4 qB 已存在相同 torrent

如果已有 torrent 已取得完整元数据，系统只读文件列表并返回检测结果，不删除现有 torrent；如果仍在获取元数据，则只读等待或明确显示“已有任务正在获取元数据”。

### 5.5 qB 版本不兼容

启动探针发现停止条件不支持，检测能力整体标记为不可用，设置页提供中文升级建议，不再让每条磁力重复失败。

## 7. 可靠性基线

在修改策略前必须采集至少 7 天或足够样本的基线：

- 提交磁力数量。
- verified、timeout、failed、unsupported 数量。
- 每个错误码数量和比例。
- 元数据取得耗时 P50/P90/P95。
- 检测时 qB 连接状态、DHT 节点数和并发数。
- 首次检测与重试成功率。
- 正缓存、负缓存和真实检测命中率。
- 不同来源站点的成功率，仅记录脱敏来源名。

没有基线数据前，不把所有失败统一归因于“死种”。

## 8. 检测环境 readiness

### 8.1 启动探针

启动和周期探针检查：

- qB API 可达和认证。
- qB 版本处于支持矩阵。
- `stopCondition=MetadataReceived` 能力。
- 临时 category/tag 创建和清理。
- 配置的临时保存目录可写且隔离。
- DHT、PEX、LSD 是否按要求启用。
- qB 网络连接状态和 DHT 节点数达到最低阈值。
- DNS、HTTP API 和必要 BT 出口是否可用。

探针不得使用用户真实 torrent；使用安全测试夹具或只读能力端点。

### 8.2 能力状态

```text
disabled -> starting -> ready
                    -> degraded
                    -> incompatible
                    -> needs_auth
                    -> unavailable
```

- `starting`：qB 可达但 DHT 等尚未就绪。
- `degraded`：可以检测，但网络或性能低于阈值。
- `incompatible`：版本或停止条件不支持。
- `needs_auth`：认证失败。
- `unavailable`：API 或 sidecar 不可用。

只有 ready/degraded 可以接收批次。starting 短暂排队，其他状态立即返回明确环境错误，不创建大量单项失败。

## 9. 分阶段元数据等待

建议默认策略：

1. 快速阶段：等待 30 秒。
2. 延长阶段：仍有网络活动时继续至 90 秒。
3. 最终上限：低活跃但仍有发现进展时最多 120 秒。

最终参数由基线数据确定。判断“仍有进展”可参考 torrent 状态、已连接 peer、DHT 节点和元数据进度；不能只用固定 sleep。

要求：

- 每条资源有明确最终 deadline。
- API 单请求超时与元数据总等待分离。
- 批次取消立即停止新任务，已添加任务完成安全清理。
- 超时返回 `metadata_timeout`，中文描述为“暂未获取到元数据”，不描述为磁力失效。

## 10. 并发与背压

- 保留最大并发配置，但加入当前有效并发。
- 默认有效并发建议从 4 开始，基线验证后再调整。
- DHT starting/degraded、API 延迟升高、连续超时或限流时自动降并发。
- 连续成功且环境健康时逐步恢复，不超过配置上限。
- 单个 infohash 同时只允许一个真实检测，其他请求等待并复用结果。
- 不同批次相同 infohash 也必须单飞。
- 设置页展示配置并发、当前并发、队列长度和近 15 分钟成功率。

## 11. 缓存与重试

### 11.1 正缓存

- verified 结果按 infohash 长期缓存，默认 30 天。
- 缓存包含检测器版本和 Schema 版本。
- 检测器规则升级时按版本决定是否失效。

### 11.2 负缓存

- 只缓存明确的 `metadata_timeout`，默认 10 分钟，而不是 30 分钟。
- starting、needs_auth、API 不可用、版本不兼容、添加失败和清理失败不得作为资源负缓存。
- 负缓存记录超时阶段、环境快照和下次可重试时间。

### 11.3 手动重试

- “重试失败项”必须绕过 `metadata_timeout` 负缓存。
- 已 verified 正缓存仍可复用，除非用户明确请求重新检测。
- 同一资源短时间连续手动重试受限流保护。
- 自动重试采用退避，不在环境不可用时反复提交。

## 12. 已存在 torrent 的安全复用

发现相同 infohash 已在 qB 中时：

1. 判断是否属于本系统当前或历史临时任务。
2. 判断元数据是否已经完整。
3. 完整时只读 `torrents/files` 并生成 verified 结果。
4. 仍在获取时可以在不改变用户任务的前提下只读观察至 deadline。
5. 无法安全读取时返回 `existing_torrent_unreadable`，不删除、不暂停、不改标签。

任何情况下都不得删除非本系统创建的 torrent。检测结果标记 `result_source=existing_torrent`，便于审计。

## 13. 错误分类与动作

| 错误码 | 类型 | 默认动作 | 中文说明 |
|---|---|---|---|
| `invalid_magnet` | 资源 | 不重试 | 磁力格式无效 |
| `metadata_timeout` | 暂时 | 退避或手动重试 | 暂未获取到磁力元数据 |
| `existing_torrent_unreadable` | 冲突 | 人工检查 | qB 中已有相同任务但暂时无法读取 |
| `authentication_failed` | 环境 | 暂停全局 | qB 登录失败，请检查账号配置 |
| `incompatible_qbittorrent` | 环境 | 禁用能力 | 当前 qB 版本不兼容 |
| `metadata_stop_unsupported` | 环境 | 禁用能力 | qB 不支持元数据停止条件 |
| `api_unavailable` | 环境 | 退避重试 | qB API 暂时不可用 |
| `add_failed` | 环境/请求 | 有限重试 | 添加检测任务失败 |
| `metadata_stop_failed` | 兼容性 | 暂停并诊断 | qB 未按预期停止元数据任务 |
| `ownership_conflict` | 安全 | 不自动重试 | 检测任务所有权不一致 |
| `cleanup_failed` | 安全 | 暂停新任务 | 临时检测任务清理失败 |
| `malformed_response` | 兼容性 | 暂停并诊断 | qB 返回了无法识别的数据 |
| `internal_error` | 系统 | 有限重试并告警 | 检测服务发生内部错误 |

环境类错误不应计入资源失败率，应单独统计“检测基础设施失败率”。

## 14. 状态和用户体验

资源状态建议：

- 等待检测
- 正在连接检测环境
- 正在获取元数据
- 已检测
- 暂未获取到元数据
- 环境暂不可用
- qB 版本不兼容
- 已有任务，正在复用
- 检测失败

前端每项展示：

- 中文状态。
- 中文原因。
- 是否检测过、是否来自缓存。
- 检测耗时和下次可重试时间。
- 可执行建议：重试、检查设置、等待环境恢复。

批次展示 verified、timeout、资源错误、环境错误和等待数量，不把 unsupported 计作成功，也不笼统计作失败。

检测失败不得隐藏资源、禁用推送或把质量分降为零；仅表示未取得内容元数据。

## 15. 清理与所有权

- 每次添加使用唯一 batch marker 和 infohash 锁。
- 只清理同时匹配本系统 marker 和本次所有权记录的 torrent。
- 取消和超时后的清理使用 shielded 任务。
- cleanup_failed 时暂停领取新任务，避免积累临时 torrent。
- 启动时扫描遗留 marker，只处理可以证明属于本系统的任务。
- 临时下载目录设置容量上限和告警。

## 16. 日志与指标

遵循 REQ-004，记录：

- readiness 状态变化和原因。
- 批次创建、开始、完成、取消、恢复。
- 各状态和错误码数量。
- 元数据等待耗时分布。
- 配置并发、有效并发和队列长度。
- 正缓存、负缓存、绕过负缓存和单飞复用。
- 已存在 torrent 复用和所有权冲突。
- 清理成功、失败和遗留任务。

日志不记录完整磁力、infohash、tracker、文件名和 qB 凭据。

## 17. 管理界面与配置

设置中心增加：

- qB 版本、API、认证、停止条件、DHT 和网络状态。
- 当前能力状态及中文原因。
- 快速/延长/最终超时。
- 最大并发和当前有效并发。
- 负缓存 TTL 和正缓存 TTL。
- 近 15 分钟、24 小时检测成功率。
- 按错误码分类的失败统计。
- 安全的 readiness 重测和失败项重试。

配置变更必须校验范围并记录中文审计。

## 18. 验收标准

### 18.1 样本集

至少覆盖：

- 高活跃、低活跃和无活跃节点磁力。
- qB 冷启动和 DHT 未就绪。
- API 超时、认证失败和不兼容版本。
- 已存在且元数据完整/不完整的 torrent。
- 批次取消、服务重启和清理失败。
- 同 infohash 并发和跨批次重复。

### 18.2 核心验收

- 在冻结的可获取元数据样本集上，首次检测成功率达到 90%以上，首次加一次安全重试累计达到 95%以上。
- 无活跃节点样本返回“暂未获取到元数据”，不误报为无效磁力。
- 手动重试会绕过超时负缓存并产生真实检测。
- qB 已存在且元数据完整时可以只读复用，且不修改或删除原任务。
- qB 不兼容在 readiness 阶段被识别，不产生大量单项失败。
- 环境错误和资源错误分别统计。
- 同 infohash 并发只执行一次真实检测。
- cleanup_failed 会暂停新任务并产生中文告警。
- 检测失败不影响资源展示和推送能力。
- 前端每个失败状态都有中文原因和处理建议。

成功率目标只统计经样本确认“可以取得元数据”的磁力，不用死种抬高或压低指标。

## 19. 分期建议

1. 增加错误分布、耗时和环境快照，不改变行为。
2. 上线 readiness 探针和环境错误分流。
3. 修复负缓存、手动重试和契约参数不一致。
4. 实现分阶段等待、自适应并发和 infohash 单飞。
5. 实现已存在 torrent 的只读复用。
6. 完善中文 UI、告警和长期基线调优。

## 20. 风险与依赖

| 风险 | 缓解措施 |
|---|---|
| 延长等待增加资源占用 | 分阶段等待、进展判断、并发背压 |
| 读取已有 torrent 误操作 | 只读、不改标签、不删除、所有权测试 |
| 动态并发行为不稳定 | 上下限、渐进恢复、指标和功能开关 |
| DHT 网络环境不可控 | readiness、环境分类和明确降级 |
| 成功率指标被死种扭曲 | 冻结可获取样本集和分母定义 |
| 日志泄漏磁力信息 | 结构化允许字段和敏感扫描 |
