## 1. 一句话定义

为自托管用户提供首次部署检查、组件兼容诊断、升级预检、数据库迁移、升级后验证和可恢复回滚，降低外部依赖变化与版本升级造成的停机和数据风险。

## 2. 背景与问题

项目依赖 TMDB、PanSou、qBittorrent、115、SQLite、前后端构建和多个 Secret。当前部署需要用户手工创建 Secret、准备 Docker 外部网络并判断外部服务是否兼容。随着整理、STRM、任务中心、CLI 和 MCP 上线，数据模型与组件版本会快速增加，主要风险包括：

- 配置缺失或网络不通时只能通过日志逐项排查。
- p115client、qB、PanSou 或上游 API变化可能导致部分能力失效。
- 数据库迁移失败可能让旧版本和新版本都无法正常启动。
- 用户升级前未备份，失败后缺少可靠回退路径。
- 前端、后端、Worker、CLI 和 MCP 版本不一致时仍可能提交写操作。
- 容器内应用不适合直接获得 Docker 或宿主机控制权限。

需要建立产品化升级流程，但不能为了“一键升级”扩大系统权限边界。

## 3. 产品目标

- 首次部署后可以通过中文向导完成核心依赖检查。
- 系统持续展示应用、数据库和外部组件的兼容状态。
- 升级前输出配置、容量、任务、备份和兼容性预检报告。
- 数据库迁移可验证、可追踪并具备失败恢复方案。
- 升级期间安全停止新任务并保护 uncertain 操作。
- 升级后自动执行只读冒烟验证并生成中文报告。
- 支持回退到明确兼容的应用和数据库检查点。

## 4. 非目标

- 不让 Web 应用执行任意 Shell、Docker、SSH 或系统包管理命令。
- 不默认从未知镜像仓库或第三方地址下载更新。
- 不保证不受管理的定制镜像可以自动回滚。
- 不在没有备份和兼容声明时执行破坏性迁移。
- 不替代宿主机、Docker Engine、操作系统和存储本身的运维。
- 不把遥测数据默认发送到外部服务。

## 5. 用户场景

### 5.1 首次部署检查

用户启动服务后打开向导，依次确认数据库、Secret、TMDB、PanSou、qB、115 和存储目录状态。未配置能力显示为“未启用”，配置错误显示中文修复建议。

### 5.2 升级前预检

用户准备从 V1.2 升级到 V1.3。系统检查备份、数据库空间、进行中任务、迁移路径和外部组件版本，生成可执行与阻塞项列表。

### 5.3 迁移失败

数据库迁移在验证阶段失败。系统停止启动新版本，保留失败证据，并按照已验证方案恢复升级前检查点或指导用户回退。

### 5.4 组件不兼容

qB 或 p115client 版本超出兼容范围。相关写能力自动降级为只读或停用，其他不依赖该组件的功能继续运行。

## 7. 组件清单与兼容矩阵

清单至少包含：

- Watch Assistant 后端、前端资源、Worker 和数据库 Schema 版本。
- REQ-003 CLI 与 REQ-020 MCP 的兼容范围。
- Python、SQLite、p115client 和 qBittorrent 版本。
- PanSou API能力或契约版本。
- TMDB API连通性和凭据状态。
- 115 只读、写入、直链和目录操作能力。
- 部署方式、镜像摘要和配置 Schema 版本。

兼容状态统一为：`supported`、`degraded`、`unsupported`、`unknown`。`unknown` 不得被当作可安全执行写操作。

## 8. 首次部署向导

向导按顺序检查：

1. 应用版本、数据库路径和可写容量。
2. 加密密钥、Web 认证和必要 Secret 是否可读取。
3. TMDB 连通性、凭据和限流状态。
4. PanSou 地址、契约和搜索样例。
5. qB sidecar 版本、认证和元数据停止能力。
6. 115 凭据、只读目录和可选写能力。
7. 媒体库、入库、隔离、STRM 和备份目录安全边界。
8. 时区、通知和备份计划。

检查只返回状态和修复建议，不显示 Secret 原文。危险写能力必须单独启用并经过最小测试目录验证。

## 9. 升级元数据与来源

- 每个正式版本提供版本号、镜像摘要、配置 Schema、数据库迁移范围和兼容矩阵。
- 更新元数据必须来自配置的可信发布源并验证签名或固定摘要。
- 系统展示当前版本、可升级版本、变更摘要、破坏性变化和预计维护时间。
- 预发布版本默认不可见，用户显式加入测试通道后才能使用。
- 镜像或包摘要不匹配时必须阻止升级。
- Web 只生成升级计划；实际替换容器由受控部署工具或用户执行，除非另行启用经过验证的更新器。

## 10. 升级前预检

预检至少判断：

- 是否存在最近且校验成功的 REQ-017 备份。
- 备份和数据库所在存储是否有足够空间。
- 当前数据库版本是否存在连续迁移路径。
- 是否有运行中、等待远端结果或 uncertain 的写任务。
- 是否存在未执行或执行中的整理、清理和恢复计划。
- 外部组件是否满足目标版本最低要求。
- 配置中是否使用已删除、重命名或语义变化的字段。
- 前端、CLI、MCP 和 Webhook Schema 是否兼容。

结果分为“通过”“警告”“阻塞”。阻塞项不得通过普通 `force` 绕过。

## 11. 维护模式和任务排空

- 进入维护模式后拒绝创建新的写任务，只读查询继续可用。
- 已领取任务运行到定义的安全点，未领取任务保持排队。
- 远端结果 uncertain 的任务必须先核对或明确带入升级后恢复清单。
- Web、CLI、MCP 和 PWA 显示维护状态和预计恢复时间。
- 超过排空等待时间时，由用户选择继续等待或取消可安全取消的任务。
- 维护模式本身必须可在升级失败后解除，不能依赖已失败的新版本。

## 12. 数据库迁移与检查点

- 每个迁移具有稳定 ID、来源版本、目标版本、是否可逆和预计影响。
- 升级前使用 SQLite 在线备份创建不可省略的检查点。
- 先对备份副本执行迁移预演和完整性检查，再允许修改正式数据库。
- 正式迁移使用事务或明确的分阶段恢复点。
- 迁移不得访问 115 或执行媒体文件写操作。
- 大表迁移必须评估额外空间、锁定时间和中断恢复。
- 迁移完成后验证 Schema、外键、关键计数、任务状态和清单一致性。

## 13. 升级后验证

自动验证至少覆盖：

- 数据库连接、Schema 和迁移版本。
- 认证、CSRF 和基础 API。
- TMDB、PanSou、qB 和 115 readiness。
- 任务领取、Outbox 和定时调度状态。
- 媒体库、库存和 STRM 清单只读检查。
- 前端资源版本与后端 API兼容。
- CLI/MCP 写操作兼容范围。

验证默认只读。需要写入的合成测试只能使用专用测试目录和无价值 fixture，并必须显式启用。

## 14. 回退规则

- 回退目标必须同时包含应用版本、镜像摘要、配置版本和数据库检查点。
- 数据库发生不可逆迁移时，只能恢复升级前检查点，不能直接用旧程序打开新 Schema。
- 回退前保留失败版本的脱敏诊断和数据库副本摘要。
- 升级后已经产生真实业务写入时，系统必须警告恢复检查点可能丢失这些记录。
- 回退成功后重新执行旧版本只读验证，并保留升级失败事件。
- 自动回退只允许在尚未恢复业务写入且方案已通过演练时启用。

## 15. 界面、CLI 与诊断包

管理界面提供：

- 当前版本、部署方式、组件状态和兼容性。
- 可用更新、变更摘要和目标版本要求。
- 预检、检查点、维护模式、迁移和验证时间线。
- 阻塞项、中文修复建议和回退状态。

REQ-003 CLI 提供只读 `version`、`compatibility`、`upgrade check` 和诊断导出。实际升级或回退需要独立高风险 Scope、有效计划和 Web 批准。

诊断包只包含版本、状态、错误码、脱敏配置摘要和相关日志，不包含数据库正文、Cookie、Token、密钥、完整路径或资源链接。

## 16. 安全与审计

- 应用容器保持只读文件系统和最小权限，不挂载 Docker Socket。
- 更新源、签名公钥和允许通道只能由管理员修改。
- 遵循 REQ-004，记录预检、维护模式、检查点、迁移、验证、回退和权限拒绝。
- 高风险操作记录操作者、来源/目标版本、计划 digest、批准人和最终结果。
- Secret 只记录“已配置、缺失、无效或需要轮换”，不记录原文。
- 版本查询和更新检查失败不能影响正常业务，但必须显示数据新鲜度。

## 17. 验收标准

- 全新部署可通过向导定位缺失 Secret、网络和不兼容组件。
- 预检可以阻止无有效备份、迁移路径缺失和 uncertain 写任务场景。
- 进入维护模式后不能创建新写任务，安全的只读查询继续工作。
- 迁移先在备份副本预演，失败不会修改正式数据库。
- 升级后验证能识别前后端版本不一致和关键依赖降级。
- 不兼容组件只关闭相关能力，不导致全部服务无解释崩溃。
- 数据库迁移失败可恢复到升级前检查点。
- 镜像摘要或更新签名不匹配时升级被拒绝。
- Web 应用无法执行任意 Docker、Shell、SSH 或宿主机命令。
- 升级和回退全过程具有中文报告和可靠审计。

## 18. 分期建议

1. 组件清单、兼容矩阵和只读部署诊断。
2. 首次部署向导、配置 Schema 和中文修复建议。
3. 升级元数据、预检、维护模式和 REQ-017 检查点。
4. 迁移预演、升级后验证和人工回退流程。
5. CLI 诊断包和可选受控更新器。

## 19. 风险与依赖

| 风险 | 缓解措施 |
|---|---|
| 自动升级扩大权限 | 默认只生成计划，不挂载 Docker Socket |
| 数据库迁移损坏 | 副本预演、强制检查点、事务和一致性验证 |
| 回退丢失升级后数据 | 恢复写入前验证，明确恢复点和差异警告 |
| 兼容矩阵过期 | 版本化清单、契约测试和 unknown 保守降级 |
| 更新源被篡改 | 可信源、签名或固定摘要验证 |
| 维护模式无法解除 | 独立状态与旧版本兼容的解除路径 |
