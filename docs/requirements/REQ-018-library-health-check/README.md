## 1. 一句话定义

定期检查 115 库存、整理结构、STRM、元数据、字幕和任务一致性，形成问题清单和安全修复计划。

## 当前验收状态（2026-08-05）

- 服务器部署版本为 `249aa582`，当前发布线为 `5df17fb003ae8ea3a4774592d1fc81cb4aa78ead`。部署版本上的生产只读库存快照为 54 页、12 个目录、43 个文件和 54 个唯一对象；历史/受限受管视频夹具曾有 STRM 全量生成 40 个并 verify 40/40，
  但生产 full 终态为 `failed`，只读 verifier 为 `checked=40`、`valid=0`、`invalid=40`。
- 上述结果只证明受限只读/清单校验范围或失败关闭路径；媒体服务器真实播放兼容、稳定生产库存基线、STRM/空目录清理和整理写入仍未验收或保持关闭，本需求继续为“待验收”。

## 2. 目标与非目标

目标：

- 发现已失效、缺失、冲突和不一致问题。
- 区分可自动修复、需确认和仅提示问题。
- 提供健康分数、趋势和修复结果。

非目标：

- 不把健康分数作为删除依据。
- 不默认读取或播放完整媒体内容。
- 不在扫描不完整时执行修复清理。

## 4. 问题等级

- 严重：越权路径、清单损坏、批量失效、凭据泄漏风险。
- 错误：STRM 无效、文件身份冲突、任务长期 uncertain。
- 警告：缺字幕、缺元数据、命名不标准、索引过期。
- 提示：存在更优版本、未识别花絮或可优化规则。

健康分数按问题权重计算，但必须同时展示原始数量和原因。

## 5. 修复规则

- 只读体检与修复分开执行。
- 自动修复仅限重建受管 STRM、补齐缺失清单等可逆动作。
- 移动、重命名、隔离和清理必须生成对应需求的计划。
- 修复后执行定向复检，不重新全库扫描。
- 上游不完整时禁止生成删除类修复。

## 6. 界面要求

- 展示总健康分、各模块分数和趋势。
- 问题按严重度、媒体库、类型和是否可修复筛选。
- 每项显示中文原因、影响和建议。
- 支持选择问题生成修复计划和查看复检结果。

## 7. 验收标准

- 人工构造的孤儿清单、失效 STRM、缺字幕、错误命名和 uncertain 任务均能发现。
- 扫描不完整时不产生删除类修复。
- 自动修复不修改非受管文件。
- 修复前后问题数量可追踪。
- 严重问题触发 REQ-012 通知。
- 体检本身失败不会改变业务数据。

## 8. 分期建议

1. 库存、STRM 和任务一致性检查。
2. 整理、剧集、字幕和元数据检查。
3. 修复计划、复检和健康趋势。
