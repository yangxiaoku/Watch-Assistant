## 1. 一句话定义

建立覆盖完整、字段结构化、前端中文可读、敏感信息安全、关键操作不可遗漏的日志与审计体系，让用户能从日志直接回答“发生了什么、影响了什么、为什么失败、下一步怎么办”。

## 2. 现状与问题

### 2.1 已有基础

当前项目已经具备：

- JSONL 文件日志存储。
- 按大小轮转、按保留天数清理。
- 日志等级设置和分类筛选。
- 游标分页和前端日志列表。
- 磁力、分享链接、Cookie、Token、查询参数、infohash 和绝对路径脱敏。
- 少量业务事件桥接，不让日志写入失败影响业务。

### 2.2 已确认缺口

当前业务日志只登记少量事件，事件白名单主要覆盖：应用启动、预热、搜索、缓存命中、资源分页、内容检测、115 readiness、推送任务和设置修改。

主要问题：

- 认证、会话、CSRF、限流、API 异常、退出登录等关键事件缺失。
- TMDB、PanSou、115、Cookie 同步等上游调用缺少完整的开始、结果、降级和耗时记录。
- 推送任务只记录少量状态，重试、恢复、取消、needs_auth、uncertain 等过程不完整。
- 设置变更只显示简单状态，不清楚修改了哪一项、是否生效。
- 未登记事件会被静默忽略，研发容易误以为已经记录。
- 允许字段很少，很多日志只能显示 count/status，无法定位任务或请求。
- 消息是 `search.completed count=...` 等英文键值串，用户理解成本高。
- 运维日志和高风险审计没有明确区分；普通文件日志失败时，关键操作可能没有可靠审计。
- 前端只能按分类分页，缺少等级、时间、状态、事件、请求 ID、任务 ID和 Agent 筛选。
- 缺少事件覆盖率验收，新增功能容易忘记接入日志。

## 3. 产品目标

- 建立统一事件目录，覆盖用户操作、业务流程、后台任务、上游依赖和安全事件。
- 保留稳定英文 `event_code` 供程序和 Agent 使用，同时向用户展示中文标题和中文详情。
- 日志必须提供请求、任务和业务资源的关联标识。
- 高风险操作使用更可靠的审计记录，不因普通日志文件写入失败而丢失。
- 前端提供实用的中文查询、筛选、详情和错误建议。
- 新增业务功能必须先定义事件，再允许进入完成状态。
- 敏感信息保护不得因“日志更详细”而降低。

## 4. 非目标

- 不记录 Cookie、密码、完整 Token、磁力链接、分享密码或真实签名直链。
- 不默认记录完整影视文件名、完整云端路径和用户搜索词。
- 不把日志作为业务数据库或任务真实状态来源。
- 不要求用户理解英文事件码或 Python 堆栈。
- 不在 INFO 级别记录高频轮询、健康检查和每个文件的冗余成功事件。
- V1 不建设外部 ELK、Loki 或云日志平台。

## 5. 用户场景

### 5.1 搜索结果异常

用户看到某次搜索只有部分结果，日志显示“PanSou 部分来源失败，已返回缓存结果”，并提供媒体类型、TMDB ID、成功查询数、失败查询数、耗时和请求 ID。

### 5.2 115 推送失败

用户查看日志后能分辨 Cookie 失效、上游拒绝、超时未确认和本地任务失败，并得到“请在设置中重新验证 115 Cookie”等中文建议。

### 5.3 Agent 操作追踪

用户按 Agent 名称筛选，看到 Agent 生成了哪个计划、执行了哪个任务、影响多少项目以及最终状态，不暴露 Agent Token。

### 5.4 安全审计

登录连续失败、CSRF 拒绝、越权访问或高风险计划被拒绝时，系统留下可靠审计，可按请求 ID和来源查询。

## 7. 日志模型

### 7.1 稳定事件码与中文显示

每条日志同时包含：

- `event_code`：稳定英文机器码，例如 `search.completed`。
- `title_zh`：简短中文标题，例如“资源搜索完成”。
- `message_zh`：完整中文描述，例如“已完成电影资源搜索，共返回 24 条结果，其中 6 条来自缓存”。
- `suggestion_zh`：必要时提供下一步，例如“请检查 PanSou 服务状态后重试”。

英文事件码不直接作为前端主文案。中文模板由服务端事件目录统一管理，禁止各模块随意拼接面向用户的英文日志。

### 7.2 结构化 Schema

每条操作日志至少支持：

```json
{
  "id": 123,
  "timestamp": "2026-07-26T05:30:00Z",
  "level": "INFO",
  "category": "search",
  "event_code": "search.completed",
  "event_version": 1,
  "title_zh": "资源搜索完成",
  "message_zh": "已完成电影资源搜索，共返回 24 条结果",
  "suggestion_zh": null,
  "status": "success",
  "request_id": "req_...",
  "correlation_id": "corr_...",
  "actor_type": "web",
  "actor_id": "session_...",
  "resource_type": "movie",
  "resource_id": "tmdb:movie:123",
  "task_id": null,
  "duration_ms": 842,
  "counts": {"result": 24, "warning": 1},
  "error_code": null,
  "context": {"cached": false}
}
```

字段要求：

- 不适用字段可以为 `null`，不得使用含义不明的空字符串。
- `event_code + event_version` 决定结构化契约。
- `title_zh`、`message_zh` 和 `suggestion_zh` 必须由已登记模板生成。
- `actor_id` 使用会话 ID、Token ID或系统 worker ID，不使用用户名密码。
- `resource_id` 使用 TMDB ID、任务 ID、媒体库 ID等稳定非敏感标识。
- `context` 只能使用事件目录允许的字段，未知字段不得静默丢弃。

### 7.3 等级定义

| 等级 | 使用场景 |
|---|---|
| DEBUG | 开发诊断、分页、轮询和重试细节，默认生产不展示 |
| INFO | 用户操作成功、业务流程开始/完成、重要状态变化 |
| WARNING | 降级、重试、部分失败、配置风险、临近阈值 |
| ERROR | 终态失败、数据不一致、无法自动恢复、关键依赖不可用 |

不得把可恢复的正常分支全部记为 ERROR，也不得把终态失败只记为 INFO。

## 8. 事件覆盖矩阵

### 8.1 系统与生命周期

必须记录：

- 应用启动开始、启动完成、启动失败。
- readiness 从可用到降级及恢复。
- 应用正常停止和异常退出恢复。
- 数据库初始化、迁移、清理和失败。
- 后台 worker 启动、停止、崩溃恢复和积压告警。
- 备份成功、失败、保留清理。
- 功能能力开关变化。

### 8.2 认证与安全

必须记录：

- Web 登录成功、失败、限流。
- 登出、会话创建、过期、撤销。
- Bearer/Agent Token 成功认证的安全摘要和认证失败。
- CSRF 拒绝、权限不足、越媒体库访问。
- API 限流命中。
- 高风险计划批准、拒绝和过期。
- Token 创建、暂停、撤销；不记录 Token 原文。

成功认证日志应控制频率，避免每个轮询请求产生一条日志。安全拒绝不得因去重而完全消失。

### 8.3 搜索、TMDB 与 PanSou

必须记录：

- 媒体搜索开始、完成、失败和取消。
- TMDB 查询成功、无结果、限流、超时和解析失败。
- PanSou 查询开始、完成、部分来源失败、全部失败和超时。
- 缓存命中、新鲜缓存、过期回退和强制刷新。
- 结果规范化、去重、内容策略过滤和资源分页摘要。
- 后备标题或季度查询被采用。

默认记录 TMDB ID、媒体类型、季号、查询数量、结果数和耗时，不记录完整用户搜索词和资源名称。

### 8.4 内容检测

必须记录：

- 批次创建、开始、完成、部分失败、失败、取消和恢复。
- 提交数量、成功数量、超时数量、失败数量和耗时。
- qBittorrent readiness 变化、认证失败、限流和元数据停止不兼容。
- 单项失败只在 WARNING/ERROR 或 DEBUG 下记录，避免大量成功明细。

### 8.5 115、凭据与推送任务

必须记录：

- 115 readiness 变化和恢复。
- Cookie 来源、同步开始、成功、失败、验证和过期；不记录 Cookie 值。
- 磁力提交、分享转存、远端接受、拒绝、needs_auth、uncertain。
- 任务创建、幂等复用、领取、提交、完成、失败、取消、重试和重启恢复。
- 远端状态查询成功、超时和结果不一致。
- 115 限流、接口契约不兼容和客户端版本不兼容。

必须按任务 ID和 request ID串联完整生命周期。

### 8.6 设置与内容策略

必须记录：

- 设置读取失败。
- 设置修改成功、冲突、校验失败和限流。
- 修改者、设置分组、修改字段列表和安全的前后值摘要。
- 内容策略过滤数量和规则版本。
- 敏感凭据更新只记录“已配置/已清除/验证结果”，不记录原文。

### 8.7 REQ-001 影视库整理

必须记录：

- 目录扫描、解析、TMDB 匹配、待确认和冲突。
- 计划生成、过期、批准、执行、失败和 uncertain。
- 移动、重命名、分类、地区归档的汇总。
- 洗版比较、隔离、恢复和清理结果。
- 整理完成事件及受影响目录数量。

默认不记录完整云端路径和文件名，使用媒体库 ID、目录 ID、文件 ID和 TMDB ID。

### 8.8 REQ-002 STRM

必须记录：

- 全量扫描开始、分页进度摘要、完成、取消和失败。
- 增量目录入队、去重、dirty、再次执行和失败重试。
- STRM 创建、更新、失效和清理汇总。
- 元数据下载、跳过、失败和重试汇总。
- 播放直链解析成功、失效、needs_auth、限流和越权拒绝。
- 扫描不完整导致清理被禁止。

播放成功事件需要采样或聚合，失败和安全拒绝完整记录。

### 8.9 REQ-003 Agent CLI

必须记录：

- Agent Token 认证、撤销和权限拒绝。
- CLI/API 版本不兼容。
- Schema 和能力发现失败。
- Agent 生成、查看、批准或执行计划。
- 幂等复用、目录版本冲突和 uncertain。
- 命令、Agent ID、Scope、媒体库、请求 ID、计划 ID和任务 ID。

不得记录命令行中的 Token 或敏感参数原文。

### 8.10 REQ-005 至 REQ-012 资源发现与任务闭环

必须记录：

- 搜索召回策略、来源降级、候选合并和漏召回复查结果。
- 磁力检测批次、qB 会话、重试、超时、部分成功和最终置信状态。
- 订阅创建、检查、匹配、去重、确认、自动推送、暂停和停止。
- 上映/播出日历同步、日期变化、发布宽限期和检查调度调整。
- 质量策略创建、版本变更、硬条件拒绝、软条件评分和选片依据。
- 端到端任务的阶段变化、人工确认、恢复、取消、失败和 uncertain。
- 库存全量/增量索引、完整性、新鲜度、重复层级和推送前检查。
- 剧集完整度计算、缺集变化、特殊集规则和数据不完整状态。
- 站内通知创建、聚合、已读、渠道投递、重试和死信。

以上事件必须使用 subscription ID、quality profile ID、workflow/task ID、媒体库 ID和 TMDB ID关联，不记录完整搜索词、磁力或路径。

### 8.11 REQ-014 至 REQ-018 媒体库治理

必须记录：

- 字幕发现、匹配、语言判断、下载、转换、冲突和人工选择。
- 手工导入校验、预览、重复检测、提交、拒绝和 uncertain；不得记录完整磁力、分享地址或提取码。
- 存储统计、阈值告警、清理计划、隔离、恢复和永久删除审计。
- 备份创建、校验、保留、恢复预检、执行和恢复后验证。
- 媒体库体检开始、规则版本、问题汇总、修复计划和复检结果。

永久删除、恢复覆盖和批量修复属于高风险审计，必须与计划、批准人、digest 和执行结果关联。

### 8.12 REQ-019 至 REQ-021 自动化与移动端

必须记录：

- Webhook 端点创建、验证、订阅变化、签名投递、重试、死信和 SSRF 拒绝。
- MCP 连接、能力协商、工具调用、Scope 拒绝、幂等复用、计划提交和版本冲突。
- PWA Push 订阅、设备撤销、离线回退、缓存版本、深链失败和弱网 uncertain。

Webhook Secret、Agent Token、Push 端点和完整工具参数不得进入日志。自动化调用必须保留 actor、客户端版本、请求 ID、幂等键和任务 ID。

### 8.13 REQ-022 合集与系列

必须记录：

- TMDB 合集发现、成员同步、同步失败和差异摘要。
- 自定义合集创建、成员和顺序调整、人工覆盖和删除。
- 完整度变化、库存未知、缺失作品订阅和批量去重。
- 合集 NFO、图片或逻辑目录输出计划、执行和清理保护。

默认记录合集 ID、TMDB Collection ID、成员数量和状态计数，不记录完整目录或影片文件名。

### 8.14 REQ-023 至 REQ-026 搜索扩展与专项能力

必须记录：

- 多搜索源配置、契约验证、查询阶段、跨源去重、部分成功、限流、熔断和恢复。
- 部署诊断、升级预检、维护模式、任务排空、备份检查点、数据库迁移、升级验证和回退。
- 动漫作品匹配、集序映射、来源冲突、人工确认、锁定和规则版本变化。
- 媒体技术检测的任务等级、工具版本、读取预算、技术字段冲突、抽样结果和稳定失败原因码。

来源凭据、更新 Secret、真实直链、完整文件名、媒体片段、字幕正文和探测工具原始输出不得进入日志。升级、回退、动漫批量映射和高成本完整检测必须关联操作者、计划、批准、请求和任务 ID。

### 8.15 REQ-027 中文交互反馈

必须记录：

- 未登记用户错误码、中文消息模板缺失、模板参数不匹配和安全兜底启用。
- 用户执行重试、刷新、重新认证、加载最新设置和任务核对等关键恢复动作。
- UI 展示结论与任务真实状态不一致的检测结果。
- 文案目录版本、前后端契约不兼容和英文泄漏自动检查结果。

界面提示与日志使用相同错误码、请求 ID和关联 ID。不得把用户看到的完整表单内容、原始异常或第三方响应复制到日志；日志失败也不得导致界面展示错误的业务结果。

### 8.16 REQ-028 与 REQ-029 详情加载和分季元数据

必须记录：

- 影视摘要首屏、完整资料读取、资料缓存命中、stale 回退和读取失败。
- 资源搜索独立创建、快照复用、部分成功、完成、失败和取消等待。
- 详情路由版本、季度切换、迟到响应丢弃和状态边界不一致。
- 季度详情读取、语言回退、海报回退、字段缺失和缓存新鲜度。
- TMDB 季度身份、集数或日期变化，以及触发的缺集/映射复核。

详情加载指标必须区分首个影视资料呈现、完整资料加载、资源首批结果和资源完整时间。不得记录完整剧情简介、完整图片 URL查询参数、资源链接或用户浏览历史正文。

### 8.17 REQ-030 内容分类与筛选导航

必须记录：

- 分类目录读取、版本更新、配置变更和保存视图兼容性检查。
- 发现查询使用的主分区、筛选维度数量、缓存状态、结果数量和耗时。
- 不支持条件组合、参数校验、上游降级和本地索引不完整。
- 浏览分类与归档分类版本不一致、人工锁定保护和分类待确认状态。

分类使用指标只保存受控枚举和聚合计数，不记录用户完整保存视图名称、敏感搜索词、资源链接或可还原个人完整浏览轨迹的数据。

## 9. 操作日志与审计分层

### 9.1 操作日志

用于诊断运行状态，可继续使用文件轮转和保留策略。日志写入失败不得阻塞普通业务，但必须通过独立系统指标或降级告警暴露。

### 9.2 可靠审计

以下行为必须进入持久审计：

- 登录安全事件和权限变更。
- Agent Token 创建、授权、暂停和撤销。
- 设置和规则修改。
- 115 移动、重命名、隔离、恢复和永久删除。
- 整理、洗版和清理计划的批准与执行。
- 高风险批量操作和 Web 人工批准。

审计记录必须与业务操作在同一事务或可靠 Outbox 中持久化。审计写入失败时，高风险写操作不得伪装成功；应中止操作或进入可核对的失败状态。

审计记录不可由普通 Web 用户或 Agent Token 删除，默认至少保留 180 天。

## 10. 中文文案规范

### 10.1 消息结构

每条面向用户的日志遵循：

```text
标题：发生了什么
详情：对象 + 动作 + 结果 + 关键数量/耗时
建议：用户下一步操作，仅在需要时出现
```

示例：

| 事件码 | 中文标题 | 中文详情示例 |
|---|---|---|
| `application.startup` | 服务启动完成 | Watch Assistant 已启动，数据库和后台任务均已就绪 |
| `search.completed` | 资源搜索完成 | 已完成电影资源搜索，共返回 24 条结果，耗时 842 毫秒 |
| `search.stale_fallback` | 已使用缓存结果 | PanSou 暂时不可用，已返回 3 小时前的缓存结果 |
| `inspection.batch_failed` | 内容检测失败 | 本批次 8 条资源全部检测失败，可稍后重试 |
| `p115.credentials_expired` | 115 登录状态已失效 | 当前 Cookie 无法继续使用，请前往设置重新验证 |
| `task.uncertain` | 推送结果待确认 | 请求已超时，暂时无法确认 115 是否接受任务，系统不会自动重复提交 |
| `organize.needs_review` | 资源需要人工确认 | 找到多个相近 TMDB 条目，请选择正确影片后继续整理 |
| `strm.cleanup_blocked` | 已阻止 STRM 清理 | 本次云端扫描不完整，为避免误删已跳过清理阶段 |
| `agent.permission_denied` | Agent 权限不足 | 当前 Agent 缺少 cleanup:execute 权限，未执行清理计划 |

### 10.2 用词要求

- 使用“电影、剧集、资源、任务、目录、推送、转存、内容检测”等项目统一术语。
- 不向用户直接展示 Python 异常名、HTTPX 错误或英文堆栈。
- 错误建议必须可执行，不使用“发生未知错误”作为终态描述。
- 时间统一按用户配置时区显示，详情中明确绝对时间。
- 计数使用中文量词，状态名称保持全站一致。
- 技术字段可在详情面板展示，但中文标题和说明必须完整。

## 11. 前端日志中心

### 11.1 列表

每行展示：

- 中文标题。
- 中文分类和等级。
- 状态标记。
- 中文摘要。
- 本地时间。
- 任务 ID或请求 ID的短标识。

### 11.2 筛选

支持：

- 时间范围。
- 日志等级。
- 中文分类。
- 成功、警告、失败、待确认等状态。
- 事件码。
- 请求 ID、关联 ID、任务 ID。
- 媒体库、TMDB ID。
- Web、系统、用户脚本、Agent 等操作者类型。

### 11.3 详情

详情抽屉展示：

- 中文标题、详情和处理建议。
- 时间、耗时、分类、等级和状态。
- 请求、关联、任务和资源标识。
- 安全上下文字段。
- 同一 correlation ID的前后事件时间线。
- 复制请求 ID和任务 ID。

默认不展示原始 JSON；DEBUG 或管理员模式可以查看已经脱敏的结构化字段。

### 11.4 操作

- 对可重试任务提供跳转，不在日志页面重复实现业务操作。
- 支持刷新和可选自动刷新。
- Should：导出当前筛选结果为脱敏 JSONL 或 CSV。
- Should：保存常用筛选条件。

## 12. API 与数据要求

日志查询 API 增加：

- `level`
- `category`
- `status`
- `event_code`
- `request_id`
- `correlation_id`
- `task_id`
- `actor_type`
- `actor_id`
- `resource_type`
- `resource_id`
- `from` / `to`
- 游标分页

查询条件必须参数化，不接受任意文件路径或正则表达式。API 返回中文展示字段和结构化字段；不返回未经脱敏的原始消息。

建议把高风险审计保存于数据库，操作日志继续使用受控 JSONL 或后续可替换存储。前端可统一查询，但必须清楚标识“运行日志”和“审计记录”。

## 13. 未知事件与覆盖治理

- 所有允许事件在集中目录登记事件码、版本、分类、默认等级、中文模板和允许字段。
- 开发和测试环境调用未登记事件必须失败测试或产生显式错误。
- 生产环境不得静默忽略，应记录一次聚合后的 `observability.unknown_event` 并增加指标。
- 事件允许字段不匹配必须在测试中失败；生产中丢弃敏感未知字段并记录 Schema 错误指标。
- 每个 Epic 的 Definition of Done 必须包含事件矩阵更新和日志验收。
- CI 扫描代码中的事件调用，与事件目录对比，防止漏登记和无调用事件。

## 14. 脱敏与安全

禁止记录：

- 115 Cookie、Set-Cookie 和二维码授权内容。
- Web 密码、Bearer Token、Agent Token、CSRF Token、play token。
- 完整磁力链接、infohash、tracker、115 分享地址和提取码。
- 真实签名直链及其查询参数。
- 完整本地绝对路径和完整 115 路径。
- 请求/响应正文中的未审核第三方数据。

允许记录：

- TMDB ID、内部媒体 ID、媒体库 ID、目录 ID和任务 ID。
- 脱敏后的来源服务名、HTTP 状态、错误码和耗时。
- 结果数量、失败数量、分页和重试次数。
- 经事件目录允许的布尔状态和枚举。

所有结构化字段、中文模板参数、异常消息和第三方错误正文都必须经过同一脱敏管线。消息最长 4096 字符，截断后明确标记“内容已截断”。

## 15. 可靠性与性能

- 日志写入不得成为普通搜索和读取请求的单点故障。
- 关键审计必须持久可靠，写入失败阻止高风险操作成功提交。
- 日志轮转过程中不能丢失已确认写入的完整记录。
- 单条损坏 JSONL 不影响其他记录读取，并产生存储健康告警。
- 高频成功事件支持采样、聚合和去重；安全失败、终态失败和审计不得采样丢弃。
- 常规日志附加开销目标：业务请求 P95 增量低于 5 毫秒，最终按基准测试校准。
- 日志目录容量达到 80%/95% 阈值时产生中文 WARNING/ERROR。

## 16. 验收标准

### 16.1 覆盖率

- 本需求第 8 节所有 Must 事件都有成功、失败和必要中间状态测试。
- 登录、搜索、检测、115、推送、设置的端到端流程可通过 correlation ID还原。
- 所有已纳入需求（REQ-001 至 REQ-012、REQ-014 至 REQ-030）上线前完成各自事件矩阵。
- 未登记事件不会被静默忽略。

### 16.2 中文化

- 日志列表和详情的标题、分类、状态、描述和建议均为中文。
- 不再把 `search.completed count=1` 作为用户主消息。
- 所有 ERROR 事件具有中文失败原因；可处理错误具有中文建议。
- 英文事件码只作为辅助技术字段展示。

### 16.3 关联与查询

- 可以按请求 ID、任务 ID、事件、等级、分类、状态、时间和 Agent 查询。
- 同一业务链路的事件可按时间线查看。
- 分页和筛选组合不会漏项或重复项。

### 16.4 安全

- 自动敏感信息扫描覆盖日志文件、API、前端、导出和审计表，命中数为零。
- 第三方异常和响应正文不能绕过脱敏。
- 普通 Agent 和普通日志查看权限无法读取安全审计中的受限字段。

### 16.5 可靠性

- 普通 LogStore 写入失败不影响读取业务，并产生独立健康告警。
- 高风险审计持久化失败时，对应操作不会显示成功。
- 轮转、保留、损坏行、磁盘满和重启场景通过集成测试。
