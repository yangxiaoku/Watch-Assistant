## 1. 一句话定义

解决“相同资源在 PanSou 直接搜索可以找到，但 Watch Assistant 搜不到”的漏召回问题，在保持结果相关性的同时提高查询覆盖、解析兼容、缓存时效和过滤可解释性。

## 2. 现状与问题

当前搜索链路为：TMDB 媒体信息 → 自动生成关键词 → 并发查询 PanSou → 结果标准化 → 标题/年份/季度校验 → 排序与截断 → 缓存 → 前端展示。

代码核对发现以下高概率漏召回点：

- 新鲜缓存有效期为 24 小时，缓存命中后不会访问 PanSou；早期空结果或少量结果会持续到缓存失效。
- 查询词主要来自 TMDB 中文名、原名及年份，其他译名和常用别名仅在“主查询全部成功且一个候选都没有”时补查。
- 已找到少量结果时不会继续查询其他别名，容易遗漏使用不同译名发布的资源。
- 任一查询失败且存在旧缓存时，系统可能直接返回旧缓存，而不是合并本轮已经成功取得的新结果。
- 单次 PanSou 请求超时为 12 秒，较慢插件可能被视为失败。
- 电影结果遇到剧集标记直接拒绝；年份差超过 1 年直接拒绝。
- 指定季度时要求识别出的季号集合严格等于所选季，合集、季范围和非标准季度名称会被拒绝。
- 资源标题必须命中 TMDB 标题、原名或已启用别名；缩写、音译和发布组命名可能被过滤。
- 只保留有限数量磁力结果，截断信息没有充分呈现给用户。
- 当前日志只给出笼统的 `resource_mismatch_filtered`，无法判断结果在哪一步、因为什么被丢弃。

上述原因需要通过数据和对照测试确认占比，不能仅凭猜测全部放宽。

## 3. 产品目标

- 在相同关键词、相同时间窗口下，尽可能覆盖 PanSou 直接搜索的有效相关资源。
- 查询中文名、原名、常用译名、地区译名和季度表达。
- 当前查询部分成功时保留并合并新结果，不被旧缓存完全覆盖。
- 空结果、部分结果和完整结果使用不同缓存策略。
- 过滤从“不可见黑盒”改为有原因、有计数、可诊断。
- 用户可以在详情页添加一次性的补充关键词重新搜索。
- 严格 URL 安全校验保持不变，相关性放宽采用评分而非无条件接收。
- 建立搜索召回率、过滤率、缓存命中率和上游成功率指标。

## 4. 非目标

- 不保证展示 PanSou 的全部原始结果或明显不相关结果。
- 不放宽磁力 URI、115 分享域名和分享 ID的安全校验。
- 不新增第二个搜索引擎。
- 不记录用户完整搜索词、完整资源名或敏感链接到日志。
- 不以增加超时时间作为唯一解决方案。
- 不让用户通过搜索参数指定任意上游 URL。

## 5. 用户场景

### 5.1 盘搜有结果但详情页无结果

用户点击“搜索诊断”，系统显示本轮使用的查询策略、各查询返回数量、标准化数量、重复数量和各类过滤数量，并允许使用建议别名补查。

### 5.2 资源刚刚出现

此前缓存为空，但 PanSou 已出现新资源。空结果使用短缓存，用户点击“刷新资源”能够明确绕过负缓存并取得新结果。

### 5.3 部分插件超时

四个查询中三个成功、一个超时。系统合并三个成功查询的新结果与仍有效的旧缓存，并标记“部分来源暂不可用”，而不是只返回旧缓存。

### 5.4 季度合集

用户搜索第二季，资源名为 `S01-S03 Complete`。系统识别合集覆盖第二季，保留结果并降低精确度评分，不因季号集合不是 `{2}` 而直接删除。

### 5.5 手工补充关键词

自动查询使用官方中文名，但资源以民间译名发布。用户输入补充关键词后重新查询；该关键词只进入当前媒体的受控查询计划，不作为任意全文搜索或写入敏感日志。

## 7. 查询计划

### 7.1 查询来源

每个媒体的候选词按以下来源生成：

- TMDB 当前语言标题。
- TMDB 原名。
- TMDB alternative titles 中允许地区的译名。
- 用户确认的媒体别名。
- 用户本轮补充关键词。
- 电影年份变体。
- 电视剧季号的中文、英文和 `Sxx` 变体。

所有查询词进行 Unicode 规范化、空格整理、长度限制和去重。

### 7.2 分阶段执行

建议分三阶段：

1. **主标题阶段**：中文名、原名及必要年份。
2. **别名扩展阶段**：常用译名、地区译名、去年份变体。
3. **季度/补充阶段**：季号变体和用户补充关键词。

查询预算必须可配置。达到以下任一条件可停止继续扩展：

- 已获得足够数量的高相关候选。
- 查询预算已用尽。
- 上游达到限流或整体超时。

不得仅以“候选数大于零”作为停止别名扩展的唯一条件。少量结果或结果来源单一时仍应按预算补查。

### 7.3 查询计划版本

缓存键必须包含查询计划版本。标题规则、别名策略、季度规则或过滤规则发生实质变化时升级版本，避免旧缓存掩盖新策略。

## 8. PanSou 查询和结果合并

### 8.1 请求策略

- 保留全局并发限制，避免压垮 PanSou。
- 单查询超时和搜索总预算分开配置。
- 记录每个查询的成功、超时、上游错误、结果数和耗时。
- PanSou 返回部分插件结果时，不把整次查询视为完全失败。
- 上游能力允许时读取插件级状态，区分“零结果”和“插件失败”。

### 8.2 合并策略

- 本轮所有成功查询结果先标准化并按 infohash/分享 ID去重。
- 部分查询失败时，保留本轮成功的新结果。
- 有旧缓存时，按 canonical key 合并本轮新结果与未过期旧结果。
- 同一资源优先保留字段更完整、采集时间更新的版本。
- 本轮完整成功后才允许用新快照替换旧快照。
- 部分成功快照使用短 TTL，并保留 `partial_upstream` 状态。
- 所有查询失败时才回退旧缓存；无缓存则返回明确不可用状态。

## 9. 缓存策略

建议默认值：

| 缓存类型 | 条件 | 默认 TTL |
|---|---|---|
| 正常正缓存 | 完整查询且存在结果 | 24 小时 |
| 完整空缓存 | 完整查询但零结果 | 30 分钟 |
| 部分结果缓存 | 存在成功查询但上游不完整 | 10 分钟 |
| 故障回退缓存 | 全部查询失败时使用旧结果 | 最长 7 天 |

要求：

- 手动“刷新资源”明确绕过正缓存、负缓存和部分缓存。
- 空缓存到期后后台观察任务可自动复查。
- 缓存记录查询计划、查询成功数、失败数、过滤摘要和生成时间。
- 前端必须显示缓存年龄、缓存类型和上游完整性。

## 10. 资源校验与过滤

### 10.1 硬拒绝

以下情况可直接丢弃：

- 无效或危险 URL。
- 缺少有效 BTIH 的磁力。
- 不在允许域名的 115 分享。
- 有强证据表明媒体类型或季集完全不匹配。
- 明确命中内容安全阻止规则。

### 10.2 软评分

以下情况原则上降分而非直接丢弃：

- 标题只命中译名、缩写或音译。
- 资源名没有年份。
- 年份存在轻微或可解释差异。
- 季度合集、季范围或全剧包覆盖目标季度。
- 标题较短且缺少清晰度标签。
- 技术标签或发布年份可能被误识别为影视年份。

### 10.3 原因码

每条被拒绝或降分的资源记录一个主要原因和可选次要原因：

- `invalid_url`
- `missing_infohash`
- `share_domain_not_allowed`
- `title_not_matched`
- `year_conflict`
- `movie_episode_conflict`
- `season_not_covered`
- `ambiguous_title`
- `content_policy_hidden`
- `snapshot_limit`
- `duplicate_resource`

前端默认只展示汇总数量；管理员诊断可查看脱敏原因分布。日志按 REQ-004 输出中文说明。

## 11. 电视剧和季度规则

- 识别 `S02`、`Season 2`、`第2季`、`第二季`。
- 识别 `S01-S03`、`Season 1-3`、全季、全剧和 Complete Collection。
- 指定季度搜索时，只要合集覆盖目标季度即可保留。
- 单集、集范围和季度包分别评分。
- 电影资源中出现 `E01` 不一定直接判定为剧集；需要结合标题、目录标记和其他证据。
- TMDB 季号与资源发布季号存在特殊映射时允许人工覆盖。

## 12. 补充关键词

详情页新增“补充关键词”入口：

- 每次最多添加 3 个关键词。
- 单个关键词长度、字符集和控制字符受限。
- 关键词只能提交给配置中的 PanSou 服务。
- 与当前 TMDB ID、媒体类型和季度绑定。
- 默认只对本次刷新生效；用户可选择保存为媒体别名。
- 保存别名需要明确确认，并记录规则来源。
- 日志不记录完整关键词，只记录是否使用、数量和结果数。

## 13. 搜索诊断

诊断摘要至少包含：

- 查询计划版本和缓存类型。
- 计划查询数、成功数、失败数和总耗时。
- PanSou 原始分类数量。
- 标准化成功、无效 URL、重复、硬拒绝、软降分和截断数量。
- 各拒绝原因计数。
- 是否使用别名、补充关键词、旧缓存和部分上游回退。

普通用户看到中文摘要；详细查询词和资源样本只在安全的管理员诊断中临时展示，禁止写入持久日志。

## 14. 管理界面与 API

详情页增加：

- 当前缓存状态和年龄。
- “刷新资源”与“补充关键词”。
- “搜索诊断”摘要。
- 部分上游、使用旧缓存、结果被过滤和结果被截断提示。

API 建议保持 TMDB ID为主入口，补充受限字段：查询计划版本、补充关键词、诊断开关和刷新标记。任务推送仍只接受 `resource_id`，不得接受任意 URL。

## 15. 日志与指标

遵循 REQ-004，记录：

- 搜索开始、阶段完成、部分失败、缓存命中和故障回退。
- 查询数量、成功/失败数量、耗时和结果数量。
- 标准化、重复、硬拒绝、软降分和截断计数。
- 各原因码聚合，不记录完整关键词和资源名。

核心指标：

- PanSou 查询成功率和 P50/P95 耗时。
- 完整、部分、故障回退和负缓存比例。
- 每阶段新增唯一资源数量。
- 标准化成功率和各拒绝原因占比。
- 与直接 PanSou 对照的有效资源召回率。
- 用户补充关键词的使用率和新增结果数。

## 16. 验收标准

### 16.1 对照样本

建立不少于以下规模的脱敏样本：

- 30 部电影。
- 20 部剧集，覆盖单季、季范围、全剧和特别篇。
- 中文名、原名、港台译名、民间译名和缩写各类样本。
- PanSou 快速响应、部分插件失败和超时场景。

### 16.2 核心验收

- 对相同查询计划直接调用 PanSou 与项目查询，所有 URL 合法且媒体相关的资源召回率达到 95%以上。
- 不能达到 95%的样本必须有明确拒绝原因并经产品确认属于应过滤结果。
- 空缓存 30 分钟后会重新查询；手动刷新立即绕过。
- 主查询有少量结果时仍能按预算查询有效别名。
- 部分查询失败时，本轮成功的新结果不会被旧缓存覆盖掉。
- 年份差异、季范围和合集不再被无解释直接丢弃。
- 补充关键词可以找回自动查询遗漏的有效结果。
- 放宽召回后，抽样前 30 条结果相关准确率不低于现有基线。
- 所有过滤、缓存和上游降级均有中文诊断和日志。

## 17. 分期建议

1. 建立 PanSou 对照样本和漏召回统计。
2. 增加过滤原因码和搜索诊断，不改变结果行为。
3. 拆分正/负/部分缓存并修复部分结果合并。
4. 扩展别名、查询计划和季度覆盖规则。
5. 上线补充关键词和管理员诊断。
6. 根据召回与准确率数据调优软硬过滤边界。

## 18. 风险与依赖

| 风险 | 缓解措施 |
|---|---|
| 放宽过滤导致误匹配 | 硬安全校验不变、软评分、前 30 准确率验收 |
| 查询量增加压垮 PanSou | 分阶段预算、并发限制、停止条件和缓存 |
| 别名过多造成噪声 | 地区白名单、来源权重、用户确认别名 |
| 诊断泄漏查询或资源名 | 默认聚合、临时展示、日志脱敏 |
| 缓存策略复杂 | 明确类型、TTL、查询计划版本和测试矩阵 |
