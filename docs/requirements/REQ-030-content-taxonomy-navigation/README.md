## 1. 一句话定义

建立“内容分区 + 多维筛选 + 专题视图”的中文分类体系，让用户可以按电影、剧集、动漫、纪录片、综艺、地区、年代、语言、题材、状态和个人媒体库状态组合发现内容，同时与 115 实际归档目录保持清晰边界。

## 2. 背景与问题

当前浏览体系的分类能力有限：

- 顶层主要只有电影、剧集和热门入口。
- 类型筛选使用前端硬编码的 TMDB Genre，不能动态更新或按产品术语分组。
- 一次只能选择一个 Genre。
- 年份只展示最近 8 年，无法按年代、任意年份或范围筛选。
- 只有热度、评分和上映时间 3 种排序。
- 没有地区、原始语言、播出/上映状态、评分区间和投票数门槛。
- 动漫、纪录片和综艺虽然是 115 整理主分类，却没有独立浏览分区。
- 收藏、订阅、已拥有、缺集和合集等本地状态没有统一筛选入口。
- 首页板块固定，用户不能快速进入“日韩动漫”“已完结高分剧集”等常用组合。
- 分类条件与 URL、分页和返回状态的契约较弱，复杂筛选难以分享和恢复。

需要扩展分类，但不能把浏览标签直接等同于文件目录：一个内容可以同时属于多个题材、地区或专题，而 115 归档仍需要单一、稳定、可审计的目标位置。

## 3. 产品目标

- 提供电影、剧集、动漫、纪录片和综艺五个稳定内容分区。
- 支持地区、国家、语言、题材、年代、状态和评分等组合筛选。
- 同一内容可以出现在多个浏览标签和专题中。
- 分类名称、解释和互斥规则使用中文统一管理，不散落硬编码。
- 筛选条件可进入 URL、浏览历史和 PWA 深链。
- 支持保存常用筛选视图，并用于首页快捷入口。
- 本地收藏、订阅、库存和缺集状态可以与 TMDB 发现条件组合。
- 不触发对全部 TMDB 内容的资源搜索或 115 全盘扫描。
- 浏览分类变化不自动移动、重命名或重新归档 115 文件。

## 4. 非目标

- 不把每个 Genre、国家或标签创建为 115 实体目录。
- 不建设用户可以执行任意表达式或代码的分类规则引擎。
- 不保证 TMDB Genre 和 Keyword 能准确识别所有短剧、综艺或动漫。
- 不为所有发现结果预先查询磁力与 115 分享。
- 不在 V1 建设个性化机器学习推荐系统。
- 不把内容安全规则与普通浏览分类混为一体。
- 不因增加分类而改变 REQ-001 已锁定的人工归档结果。

## 5. 用户场景

### 5.1 查找日韩动漫

用户进入“动漫”，选择地区“日本/韩国”、年代“2020 年代”、状态“连载中”，按评分排序，得到可分页、可分享的结果。

### 5.2 查找国产纪录片

用户进入“纪录片”，选择“中国大陆”和最近 5 年，不需要在电影和剧集两个页面分别寻找纪录 Genre。

### 5.3 查找已完结高分剧集

用户组合“剧集 + 已完结 + 评分 8 分以上 + 投票数不少于阈值”，避免少量评分导致的虚高结果。

### 5.4 查看个人缺口

用户选择“已订阅但未拥有”，按最近播出排序，进入对应订阅、缺集或资源详情。

### 5.5 保存常用分类

用户把“日韩科幻动画 · 近 3 年 · 评分优先”保存为“近期科幻番”，以后从首页或 PWA 快速打开。

## 7. 分类体系

分类分为三个层级，职责不能混用。

### 7.1 内容分区

默认稳定分区：

- **电影**：普通电影，不含已经归入纪录片或动漫主分区的项目。
- **剧集**：普通电视剧，不含已经归入纪录片、动漫或综艺主分区的项目。
- **动漫**：动画电影和动画剧集，可按配置决定成人动画和混合类型。
- **纪录片**：纪录电影、纪录剧集和纪录系列。
- **综艺**：真人秀、脱口秀、竞演、晚会及配置的电视 Genre/Keyword。

五大分区与 REQ-001 使用同一分类术语和基础规则版本，但浏览结果可以临时展示“分类待确认”，不能在浏览时直接修改 115 归档。

### 7.2 筛选维度

用于缩小结果，可以组合：

- 题材/Genre。
- 地区与国家。
- 原始语言。
- 年份、年代和日期范围。
- 上映、播出、连载和完结状态。
- 评分区间、最低投票数和热度。
- 收藏、订阅、库存和完整度等本地状态。

### 7.3 专题视图

专题是预定义筛选组合，例如：

- 正在热映。
- 即将上映。
- 本周热门。
- 热播剧集。
- 已完结高分剧集。
- 国产纪录片。
- 日韩动漫。
- 儿童与家庭。
- 经典电影。

专题不产生新媒体身份，不改变归档分类。

## 8. 五大分区规则

### 8.1 分类依据

复用 REQ-001 的 TMDB 类型、Genre、Keyword、原产国家和人工锁定结果，优先级为：

1. 用户已锁定的分类。
2. 已登记且版本兼容的特殊覆盖。
3. 纪录片规则。
4. 动漫规则。
5. 综艺规则。
6. 剩余 TV 归入剧集，剩余 Movie 归入电影。

### 8.2 分类边界

- 动画电影默认出现在动漫分区，也可以通过媒体形态筛选查看“动漫电影”。
- 纪录剧集归入纪录片分区，同时保留媒体形态 `tv`。
- 综艺分区可细分真人秀、脱口秀、音乐、竞演和晚会。
- “儿童与家庭”“音乐”“历史”等属于题材或专题，不新增主分区。
- 短剧识别置信度不足时作为 Should 专题，不纳入 V1 强制主分类。
- 同一内容只能有一个主分区，但可以拥有多个题材、地区和专题标签。

## 9. 题材与 Genre

- Genre 列表从 TMDB 配置接口读取并缓存，不继续完全硬编码在前端。
- 服务端维护稳定 Genre ID、中文名称、媒体类型范围和显示顺序。
- 支持一次选择多个 Genre。
- 同一维度默认使用“满足任意一个（OR）”，高级入口可切换“同时满足（AND）”。
- 不同维度之间默认使用 AND，例如“动漫 AND 日本 AND 2020 年代”。
- 电影和剧集共用中文术语时展示一致名称，但保留各自 TMDB ID。
- Genre 被 TMDB 删除或调整时保留已保存视图并提示更新，不静默替换为其他类型。

默认题材至少覆盖：动作、冒险、动画、喜剧、犯罪、纪录、剧情、家庭、奇幻、历史、恐怖、音乐、悬疑、爱情、科幻、惊悚、战争、儿童、新闻、真人秀、脱口秀、肥皂剧、西部和政治。

## 10. 地区、国家和语言

### 10.1 浏览地区

默认浏览地区比 115 目录更细：

- 中国大陆。
- 中国香港。
- 中国台湾。
- 日本。
- 韩国。
- 北美。
- 欧洲。
- 东南亚。
- 印度及南亚。
- 拉丁美洲。
- 中东及非洲。
- 其他/未知。

地区映射由国家代码集合组成并版本化。用户可展开到具体国家筛选。

### 10.2 与归档地区的关系

- 浏览地区用于发现和筛选，可以细分港澳台、日韩和具体国家。
- REQ-001 的目录地区仍使用国产、欧美、日韩、其他等稳定配置。
- 浏览筛选不会改变已归档目录。
- 管理员可以查看两个映射的对应关系，但不能把它们误设为同一个枚举。

### 10.3 原始语言

支持中文、英语、日语、韩语、法语、西班牙语、泰语等常用语言，并允许查看全部 ISO 语言。语言未知单独显示，不根据国家强行猜测。

## 11. 时间和状态

### 11.1 时间筛选

支持：

- 具体年份。
- 自定义起止年份。
- 2020 年代、2010 年代等年代。
- 最近 1 年、3 年、5 年和 10 年。
- 上映/首播日期范围。

年份选择不限制为最近 8 年。无日期内容可以选择是否包含，默认在指定范围时排除并显示排除数量。

### 11.2 电影状态

- 即将上映。
- 正在上映。
- 已上映。
- 日期待定。

状态需要结合 TMDB 日期和地区配置，不把全球首映日期等同用户地区上映日期。

### 11.3 剧集状态

- 尚未开播。
- 连载中。
- 季终待续。
- 已完结。
- 已取消。
- 状态未知。

REQ-007 日历和订阅使用相同状态术语和日期新鲜度。

## 12. 评分、热度与排序

筛选支持：

- 最低和最高评分。
- 最低投票人数。
- 热度范围。

排序至少支持：

- 热度最高。
- 评分最高。
- 投票最多。
- 最新上映/首播。
- 最早上映/首播。
- 标题排序。
- 最近加入个人媒体库（仅本地集合）。
- 最近发现资源（仅有资源快照的本地集合）。

评分优先默认附带最低投票数，避免少量评分造成结果失真。当前排序、投票门槛和数据来源必须可见。

## 13. 本地状态筛选

当用户已启用对应功能时支持：

- 已收藏/未收藏。
- 已订阅/未订阅/已暂停。
- 115 库内已有/其他版本/未拥有/库存未知。
- 剧集完整/缺集/映射未知。
- 已加入合集。
- 有待确认项。

规则：

- 本地状态来自 REQ-007、010、011、022 等内部索引，不向 TMDB 传递。
- TMDB 大范围发现与本地状态组合时，服务端必须定义可计算边界。
- “未拥有”只有在库存索引完整且新鲜时才是确定结论。
- 本地筛选不能触发临时 115 全盘扫描。

## 14. 资源可用性筛选

Should 支持“已有资源快照”“有磁力”“有 115 分享”“已检测”等筛选，但仅适用于：

- 当前搜索结果。
- 已经执行过资源搜索的媒体集合。
- 订阅候选和本地观察列表。

不得为了筛选整个 TMDB 目录而为每一条内容发起 PanSou、多源搜索或磁力检测。没有资源快照必须显示“未搜索”，不能等同“没有资源”。

## 15. 筛选交互

- 桌面端使用紧凑筛选区、下拉菜单或可展开面板，不把几十个选项全部平铺占满首屏。
- 手机端使用筛选抽屉，顶部持续显示已选条件数量。
- 当前条件以可单独移除的筛选摘要展示。
- 提供“清除当前维度”和“清除全部”。
- 条件变化后返回第一页，并取消或丢弃旧请求。
- 结果区显示当前分类名称、结果总数、排序和数据新鲜度。
- 空状态说明是哪个条件导致无结果，并允许逐项放宽。
- REQ-027 负责所有中文提示、禁用原因和错误恢复。

## 16. URL、保存视图和返回恢复

### 16.1 URL 契约

URL 保存：

- 内容分区。
- 媒体形态。
- Genre 列表及匹配方式。
- 地区/国家、语言。
- 年份/日期、状态。
- 评分、投票门槛和排序。
- 本地状态、页码和每页数量。

参数必须有稳定枚举、长度和数量限制，不接受任意 TMDB 查询参数透传。

### 16.2 保存视图

Should 支持保存名称、筛选条件、排序和可选首页固定位置。保存视图引用分类目录版本；目录升级后若含无效条件，提示用户修复，不静默删除。

### 16.3 返回状态

从详情返回时恢复分区、筛选、分页和滚动位置，并与 REQ-028 的详情路由状态兼容。

## 17. 首页与专题导航

首页保留高价值动态板块，并允许增加：

- 五大分区快捷入口。
- 用户固定的保存视图。
- 订阅即将更新。
- 已播但未拥有。
- 媒体库最近入库。
- 合集缺失作品。

首页每个板块必须显示分类依据和“查看全部”目标，不能出现无法复现条件的黑盒推荐。板块加载失败不阻塞其他板块。

## 18. 分类目录与配置

服务端维护版本化分类目录：

- 主分区 ID、中文名称、说明和排序。
- Genre、国家、地区和语言枚举。
- 状态和排序枚举。
- 分类规则版本和来源。
- 可用于前端的组合约束。

管理员可以调整展示顺序、隐藏不用的专题和配置地区集合。五大主分区 ID、机器枚举和人工锁定语义不能随意改名或复用。

分类目录更新时：

- 清理相关缓存版本。
- 验证保存视图。
- 不自动重分类已经人工锁定的 115 媒体。
- 输出影响摘要和可回滚配置版本。

## 19. API 与查询规则

发现 API 建议支持：

- `section`
- `media_type`
- `genre_ids[]` 和 `genre_match`
- `region_ids[]` / `country_codes[]`
- `original_languages[]`
- `year_from` / `year_to`
- `release_status[]`
- `score_min` / `score_max`
- `vote_count_min`
- `local_states[]`
- `sort`
- 游标或受限页码分页

规则：

- 所有参数使用允许枚举、范围和数量上限。
- 不向客户端暴露任意上游 URL或原始 Discover 参数。
- TMDB 条件和本地索引条件分层执行，并在响应中说明结果范围。
- 不支持的组合返回 REQ-027 结构化中文错误和可放宽建议。
- 响应包含分类目录版本、规范化筛选条件和数据新鲜度。

## 20. 性能与缓存

- 分类目录和 Genre 配置使用长缓存并按版本失效。
- Discover 缓存键包含规范化筛选、语言、地区、排序和页码。
- 相同条件的并发请求合并。
- 条件变化取消前端旧请求，迟到响应不得覆盖当前分类。
- 本地状态过滤优先使用 REQ-010 等索引，不逐项调用 115。
- 首页板块独立加载和缓存，单个专题失败不影响首屏。
- 常用组合的 P95 响应目标在真实基准后冻结，首期建议缓存命中低于 500 毫秒。

## 21. 中文提示、日志与指标

遵循 REQ-004 和 REQ-027，记录：

- 分类目录读取、版本更新、配置变化和保存视图失效。
- Discover 查询的分区、维度数量、缓存状态、结果数量和耗时。
- 不支持组合、参数校验、上游降级和本地索引不完整。
- 各分区和筛选维度使用率、零结果率和用户放宽条件行为。

不记录用户完整自定义视图名称、敏感搜索词、资源链接或完整浏览轨迹。指标使用聚合维度和受控枚举。

## 22. 验收标准

### 22.1 分类覆盖

- 电影、剧集、动漫、纪录片和综艺均有独立浏览入口。
- 标准样本按照与 REQ-001 一致的基础规则进入正确主分区。
- 动画电影、纪录剧集和综艺子类型可以正确表达媒体形态与主分区。
- 同一内容可拥有多个题材和专题，但只有一个主分区。

### 22.2 筛选能力

- 用户可以组合主分区、多个 Genre、地区、语言、年代、状态和评分。
- 同维度 OR/AND 与跨维度 AND 语义符合界面说明。
- 可以选择早于最近 8 年的具体年份和年代。
- 评分排序使用可见最低投票数，避免无解释结果。
- 清除单项和全部筛选后结果、URL 和页码一致。

### 22.3 本地联动

- 收藏、订阅、已拥有和缺集状态可以在索引完整时正确筛选。
- 库存不完整时不会把未知错误显示为“未拥有”。
- 资源可用性筛选不会触发对整个 TMDB 目录的批量资源搜索。
- 浏览分类和筛选不会移动、重命名或重新归档任何 115 文件。

### 22.4 导航与体验

- 筛选条件可通过 URL分享并在刷新后恢复。
- 从详情返回恢复原分类、分页和滚动位置。
- 桌面和 360 CSS 像素移动端均可操作复杂筛选，无横向溢出。
- 空结果、上游失败和不支持组合具有明确中文原因和放宽入口。

### 22.5 工程治理

- Genre、地区、语言和状态来自版本化目录，不再完全硬编码于 Vue 页面。
- 新增分类必须有规则、中文名称、数据来源和样本测试。
- 分类目录升级不会覆盖人工锁定的归档结果。
- 分类查询、保存视图和 URL 参数通过边界、并发和缓存测试。

## 23. 分期建议

1. 冻结五大分区与浏览/归档边界，建立分类目录 API。
2. 将 Genre 从前端硬编码迁移到版本化目录，支持多选。
3. 增加地区、语言、年代、评分和状态筛选。
4. 增加 URL、返回恢复、移动端筛选抽屉和中文空状态。
5. 接入收藏、订阅、库存和缺集状态。
6. 增加保存视图、首页专题和聚合指标。

## 24. 风险与依赖

| 风险 | 缓解措施 |
|---|---|
| 分类规则与 115 目录混淆 | 明确浏览标签与归档主分类两个模型 |
| 条件过多导致界面复杂 | 分层筛选、默认折叠、条件摘要和移动抽屉 |
| TMDB 元数据不准确 | 来源标记、人工锁定和分类待确认状态 |
| 查询组合造成缓存爆炸 | 规范化参数、数量限制、分层缓存和热门组合 |
| 本地状态筛选成本高 | 使用库存/订阅索引，不实时遍历 115 |
| 资源筛选制造搜索风暴 | 仅对已有资源快照集合开放 |
