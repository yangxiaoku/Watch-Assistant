## 1. 一句话定义

把现有 Web 管理能力扩展为可安装的 PWA，使用户能在手机上安全查看任务、处理确认、接收通知并执行有限的日常管理操作。

## 2. 背景与问题

资源发现、任务失败、115 凭据失效和高风险计划常在用户离开电脑时发生。仅靠桌面 Web 页面会延迟确认和故障处理；直接开发原生 App 则会带来双端维护和发布成本。

PWA 可以复用现有前端与 API，优先解决移动端的“查看、确认、处理”场景，同时保持高风险操作的服务端权限和审批约束。

## 3. 产品目标

- 支持从浏览器安装到手机桌面并以独立窗口运行。
- 移动端快速查看系统状态、任务、通知、订阅和待确认项。
- 支持安全批准或拒绝计划、重试允许重试的任务。
- 支持 Web Push，通知可跳转到具体业务对象。
- 网络波动时可读取有限缓存，并明确展示数据新鲜度。
- 与桌面端共享业务 API、权限、日志和状态，不形成第二套业务实现。

## 4. 非目标

- 不首期开发 iOS/Android 原生 App。
- 不支持离线创建、修改或排队执行任何写操作。
- 不把完整影视海报、全库文件或日志长期缓存到设备。
- 不允许推送消息携带 Cookie、Token、磁力、完整路径或真实直链。
- 不用客户端隐藏按钮代替服务端权限检查。

## 5. 核心用户场景

### 5.1 查看任务

用户从手机查看正在执行、等待确认、失败和 uncertain 的任务，打开时间线和中文失败原因。

### 5.2 处理确认

用户收到“整理计划待批准”或“找到多个 TMDB 候选”通知，进入详情查看影响范围并批准、拒绝或选择正确条目。

### 5.3 订阅和追更

用户查看订阅最近发现、调整仅提醒/确认模式、暂停或触发一次检查。自动推送仍遵守服务端规则。

### 5.4 弱网巡检

断网时展示最近一次成功同步的只读摘要和明确时间；恢复网络后刷新，离线期间不提交写操作。

## 7. 信息架构与页面

移动端底部主导航建议为：

- **概览**：健康状态、待处理数量、任务摘要和关键告警。
- **任务**：进行中、待确认、失败、已完成，支持筛选和详情。
- **订阅**：订阅状态、最近匹配和快速暂停。
- **通知**：未读、需要处理、错误和全部。
- **更多**：搜索、库存、设置、设备和退出。

主要要求：

- 首屏优先展示需要处理的事项，不复制桌面端密集表格。
- 列表使用摘要和筛选，详情页承载完整字段和时间线。
- 批量操作、永久删除和复杂规则编辑不放入首期移动端。
- 所有按钮具备加载、成功、失败、禁用和重复提交状态。

## 8. PWA 与缓存策略

- 提供有效 Manifest、应用名称、图标、主题色、启动地址和显示模式。
- Service Worker 只缓存应用壳、静态资源和允许的只读 API摘要。
- 任务、通知和系统状态使用网络优先；失败时才显示最近缓存。
- 缓存内容显示“最后更新于”并标记“离线数据”。
- 认证响应、Token、Cookie、敏感设置、审计详情和真实直链禁止进入 Cache Storage。
- 退出登录、撤销设备或版本不兼容时清除用户数据缓存。
- 离线时所有写按钮禁用，不创建本地待发送队列。

## 9. 通知与深链

- 使用 REQ-012 的通知事件、偏好、聚合、静默和重试机制。
- 用户必须主动授权 Web Push，拒绝后仍可使用站内通知。
- 推送只包含中文标题、脱敏摘要、严重度和内部深链。
- 点击推送进入对应任务、订阅、确认项或设置页；登录失效时先认证再恢复目标页面。
- 同一事件在站内和 Push 使用稳定通知 ID，避免重复标记。
- 订阅失效或权限撤销后停止投递并清理设备端点。

## 10. 认证与设备安全

- 复用现有 Web 会话和 CSRF 防护，禁止在 Local Storage 保存长期 Bearer Token。
- 会话 Cookie 使用 `HttpOnly`、`Secure` 和适当 `SameSite` 策略。
- 高风险批准可要求再次验证密码或设备确认，具体阈值由安全设计冻结。
- 设备列表展示设备名称、浏览器、最近活动和 Push 状态，可单独撤销。
- 应用切回前台后，敏感页面根据会话时长重新校验。
- 服务端对每次写请求执行权限、计划版本和幂等校验。

## 11. 弱网、冲突与可靠性

- 写请求必须使用幂等键；按钮提交后立即锁定，收到确定结果再解锁。
- 网络中断且结果不明时显示“结果待确认”，按请求 ID查询，不自动重发。
- 页面数据包含版本或 ETag，过期编辑返回冲突并要求刷新。
- Web Push 失败不影响站内通知和业务任务。
- Service Worker 更新采用可控激活策略，避免正在填写的确认内容丢失。
- API 或前端版本不兼容时禁用写操作并提示刷新升级。

## 12. 无障碍与兼容性

- 支持窄屏、横屏、安全区和系统字体放大。
- 触控目标不小于 44 × 44 CSS 像素。
- 关键状态不只依赖颜色，表单错误与按钮具备可读标签。
- 首期验证 Android Chrome、iOS Safari/添加到主屏幕和桌面 Chromium。
- iOS 不支持的能力必须优雅降级，不阻塞站内通知和页面使用。

## 13. 日志与数据要求

- 遵循 REQ-004，记录安装能力、Push 订阅、设备撤销、离线回退、版本冲突和写操作结果。
- Push 端点作为 Secret 保存，前端和日志只显示设备摘要。
- 记录设备 ID、会话 ID、请求/任务/通知 ID，不记录完整 User-Agent 或设备隐私数据。
- 提供安装成功率、Push 投递率、深链打开率和移动端错误率等聚合指标。

## 14. 验收标准

- 支持的浏览器可安装应用，图标、名称、启动页和独立窗口正确。
- 360 CSS 像素宽度下核心页面无横向溢出和控件重叠。
- 用户可查看并处理任务、通知和待确认项，结果与桌面端一致。
- 离线时只显示带时间戳的缓存数据，所有写操作不可用。
- 认证信息、Token、审计详情和真实直链不会进入离线缓存。
- 同一写操作在弱网和重复点击下只执行一次。
- Push 点击可在认证后恢复到正确业务详情。
- 撤销设备后会话和 Push 均失效。
- Android Chrome、iOS Safari 和桌面 Chromium 完成核心流程测试。

## 15. 分期建议

1. 移动端信息架构、响应式任务和通知页面。
2. Manifest、Service Worker、安装和只读离线缓存。
3. Push、深链、设备管理和安全复核。
4. 订阅管理、待确认操作和弱网专项测试。
5. 可选扫码绑定、系统分享和体验指标。

## 16. 风险与依赖

| 风险 | 缓解措施 |
|---|---|
| iOS PWA 能力差异 | 能力检测、站内通知兜底和兼容矩阵 |
| 缓存泄漏敏感数据 | API 白名单、禁止缓存认证响应、退出时清理 |
| 弱网重复写入 | 幂等键、提交锁和 uncertain 核对 |
| 移动端误触高风险操作 | 详情确认、影响摘要和必要的再次验证 |
| 前后端版本不一致 | 版本协商和不兼容时禁用写操作 |
