## 1. 一句话定义

在 PanSou 之外接入经过验证的搜索来源，通过统一查询、标准化、去重、质量排序和来源健康治理，提高有效影视资源的召回率并降低单一来源故障影响。

## 2. 背景与问题

REQ-005 负责修复“PanSou 直接搜索有结果、项目内却漏掉”的链路问题，但明确不新增第二个搜索引擎。即使 PanSou 链路达到预期召回率，仍会存在以下限制：

- PanSou 本身没有收录的资源无法发现。
- PanSou 故障、限流或插件异常会影响全部搜索。
- 不同来源对国产、欧美、日韩、动漫和冷门内容的覆盖差异较大。
- 相同资源可能以不同标题、磁力格式或分享链接重复出现。
- 缺少来源级健康、质量、失效率和贡献度管理。

因此需要在 REQ-005 稳定后建立多来源聚合层。新增来源不能绕过现有安全校验、内容策略、磁力检测和推送保护。

## 3. 产品目标

- 使用标准适配器接入多个受控搜索来源。
- 单次搜索可以按策略并行或分阶段查询多个来源。
- 把磁力和 115 分享转换为统一资源模型并跨来源去重。
- 保留每条资源的来源、首次发现和字段证据。
- 单一来源失败时仍返回其他来源的有效结果。
- 按来源健康、用户反馈和历史结果调整查询顺序，而不是静默隐藏结果。
- 建立来源级召回、延迟、错误、无效资源和贡献度指标。

## 4. 非目标

- 不建设允许任意代码运行的插件市场。
- 不接受用户输入任意搜索 API 地址或抓取脚本。
- 不绕过来源的访问控制、服务条款、频率限制和法律要求。
- 不因来源数量增加而取消媒体匹配和 URL 安全校验。
- 不保证收录互联网中的全部资源。
- 不在 V1 自动学习并执行不可解释的黑盒排序模型。

## 5. 用户场景

### 5.1 PanSou 无结果

用户搜索某部冷门影片，PanSou 没有结果，备用来源找到两个有效候选。界面显示来源和匹配依据，候选继续经过内容检测和质量策略。

### 5.2 单个来源超时

三个来源中一个超时。系统保留另外两个来源的本轮新结果，标记“部分来源暂不可用”，不把整次搜索降级为失败。

### 5.3 多来源重复资源

多个来源返回同一 BTIH。系统只展示一个 canonical resource，但保留全部来源证据、字段差异和最近可用时间。

### 5.4 来源持续失效

某来源连续超时或返回大量失效分享。系统降低其后台查询优先级并触发中文告警；管理员可以暂停该来源并查看影响。

## 7. 搜索来源适配器契约

每个适配器必须声明：

- 稳定来源 ID、显示名称和适配器版本。
- 支持的媒体类型、查询字段和资源类型。
- 认证方式、凭据字段和 Secret 保存要求。
- 单次超时、并发、速率限制和分页能力。
- 响应 Schema、错误分类和部分成功语义。
- 是否允许按标题、年份、季度、集号和补充关键词查询。
- 数据使用限制和启用前需要用户确认的事项。

适配器只能输出统一的候选结构，不直接写数据库、创建推送任务或访问 115 Cookie。适配器进程不得获得任意文件系统、Shell 或内部管理 API权限。

## 8. 查询计划与调度

### 8.1 查询阶段

建议按以下阶段执行：

1. 查询主来源和低延迟来源。
2. 当高质量候选不足时查询扩展来源。
3. 订阅、补集或用户强制刷新时，按预算查询深度来源。

每个计划必须包含媒体身份、标题变体、季集范围、来源列表、并发限制、总时间预算和计划版本。

### 8.2 调度规则

- REQ-005 的标题、别名和季度查询策略作为所有来源的输入基础。
- 来源可以声明不支持的字段，调度器不得猜测或拼接未定义参数。
- 达到足够高质量候选、总预算耗尽或上游限流时停止扩展。
- 手动刷新可绕过结果缓存，但不能绕过来源限流和熔断。
- 自动订阅使用比人工搜索更保守的频率和并发。
- 同一媒体的并发查询应合并，避免多个用户或任务重复请求上游。

## 9. 统一资源模型

候选至少支持：

- 内部 `resource_id` 和 canonical key。
- 磁力 BTIH 或受支持的 115 分享身份。
- 媒体类型、TMDB ID、季号、集号或覆盖范围。
- 标题摘要、年份、大小、发布时间和技术标签。
- 来源 ID、来源候选 ID、首次发现和最后验证时间。
- 字段证据、匹配得分、质量得分和检测状态。
- 安全校验、内容策略和可用性状态。

原始链接使用现有加密存储，不进入列表日志、Webhook、MCP 或通知。

## 10. 跨来源去重与字段合并

- 磁力优先使用规范化 BTIH 作为精确 canonical key。
- 115 分享使用经过验证的分享身份；不同分享不得仅因名称相同而合并。
- 同一资源的多个来源保留为 source observations，不覆盖来源历史。
- 大小、做种数和发布时间等冲突字段保存来源和采集时间。
- 展示字段优先使用更新、更完整且可信度更高的 observation。
- 无法确定是否相同的候选保持分离，不做激进去重。
- 来源失效不直接删除 canonical resource；只有所有 observation 均失效时才标记整体失效。

## 11. 排序与质量策略联动

聚合排序可以使用：

- 媒体匹配置信度。
- REQ-008 质量策略硬条件和软偏好。
- REQ-006 内容检测结果。
- 来源历史有效率和当前健康状态。
- 字段完整度、发布时间和用户确认反馈。

规则要求：

- 来源权重只能作为排序因素，不能覆盖安全硬拒绝。
- 不得因为某来源权重低而完全隐藏其有效结果，除非用户暂停来源或内容策略拒绝。
- 每条候选提供“为什么排在这里”的中文摘要。
- 自动推送必须满足与单来源相同的检测、库存去重和幂等保护。

## 12. 来源健康、熔断和缓存

来源健康状态建议为：`healthy`、`degraded`、`rate_limited`、`auth_required`、`open_circuit`、`disabled`。

- 按来源记录成功率、P50/P95 延迟、零结果率、解析失败率和无效资源率。
- 连续失败达到阈值后短期开启熔断，探测成功后逐步恢复。
- 认证失效与普通超时分开处理，认证失效需要用户操作。
- 每个来源独立保存完整、部分、空结果和故障回退缓存。
- 聚合缓存保存参与来源、完成状态、计划版本和生成时间。
- 不得用一个来源的空结果覆盖其他来源的有效旧缓存。

## 13. 管理界面

来源管理页提供：

- 已安装来源、版本、能力、启用状态和配置状态。
- 连通性测试、最近成功、错误率、延迟和熔断状态。
- 查询优先级、并发、预算和媒体类型范围。
- 暂停、恢复、凭据更新和安全删除配置。
- 契约测试报告和版本兼容提示。

搜索结果页提供来源筛选、来源数量、部分失败提示和聚合诊断。普通用户不查看来源 Secret、原始响应或敏感链接。

## 14. API、安全与审计

- API 只接受登记的来源 ID，不接受任意 URL、模块路径或代码。
- 来源凭据加密保存，前端只返回是否已配置。
- 适配器出站目标使用固定允许列表，并防止 SSRF 和重定向绕过。
- 解析第三方数据时限制响应大小、内容类型、嵌套深度和字符串长度。
- 遵循 REQ-004，记录来源配置、测试、查询、降级、熔断、恢复和契约不兼容。
- 凭据、原始查询词、完整资源名称和链接不得进入日志。

## 15. 验收标准

- 至少两个独立来源通过相同适配器契约和自动化契约测试。
- 一个来源超时、限流或返回错误时，其他来源的本轮结果正常返回。
- 同一 BTIH 来自多个来源时只展示一个资源，同时可查看来源数量。
- 不同分享仅因名称相同不会被错误合并。
- 部分来源失败不会覆盖其他来源的有效新结果或缓存。
- 熔断来源不会持续拖慢全部搜索，恢复探测成功后可以重新加入。
- 自动推送仍经过质量、内容检测、库存和幂等保护。
- 搜索诊断可以解释各来源的查询数、结果数、去重数和失败原因。
- 任意来源地址、代码、Shell 或未登记适配器无法通过 API注入。
- 新增来源后，现有 PanSou 召回对照和相关准确率不得回退。

## 16. 分期建议

1. 完成 REQ-005，冻结统一候选、原因码和查询计划契约。
2. 抽象 PanSou 为首个标准适配器，行为保持不变。
3. 接入第二个经过验证的来源并完成契约测试。
4. 实现跨来源去重、证据合并和聚合诊断。
5. 增加健康、熔断、来源管理和订阅联动。
6. 根据真实指标评估后续来源，不按数量盲目扩展。

## 17. 风险与依赖

| 风险 | 缓解措施 |
|---|---|
| 新来源质量差 | 契约测试、来源证据、有效率指标和人工暂停 |
| 查询量快速增长 | 分阶段预算、请求合并、限流和独立缓存 |
| 跨来源误去重 | 只对强身份精确合并，弱证据保持分离 |
| 第三方响应攻击 | 出站白名单、大小限制、严格解析和脱敏 |
| 来源条款变化 | 独立开关、版本记录和快速停用 |
| 排序不可解释 | 规则化评分、来源字段证据和中文摘要 |
