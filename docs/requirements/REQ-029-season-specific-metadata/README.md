## 1. 一句话定义

为电视剧每个季度获取和展示独立的海报、名称、简介、播出日期和集数信息，让用户切换季度时能清楚识别当前季，并让资源搜索、缺集和订阅使用一致的季度身份。

## 2. 背景与缺陷现状

当前剧集详情虽然可以选择季度，但季度数据模型只包含：

- 季号。
- 季度名称。
- 集数。
- 首播日期。
- 季度海报路径。

实际页面仍始终显示剧集总海报、总标题和总简介；切换季度只把季号传给资源搜索，没有读取或渲染季度详情。因此：

- 多季剧集切换后视觉和简介没有变化，很难确认当前选择。
- 已经存在的季度海报字段没有用于主展示。
- 数据模型缺少季度简介和 TMDB 季度条目身份。
- 特别篇、分割季度和名称相近的季度更难区分。
- 资源列表是分季的，但页面顶部仍像在展示整部剧，容易误判资源范围。
- TMDB 某季缺少中文简介时，系统没有明确的语言回退和缺失规则。

需要建立“剧集主体资料”和“当前季度资料”两个层级，并让季度路由、资源、缺集和订阅共享同一身份。

## 3. 产品目标

- 获取并保存每个季度独立的 TMDB 详情。
- 季度切换后明确展示该季海报、名称、简介、日期和集数。
- 剧集主体标题和身份保持稳定，当前季信息有清晰层级。
- “全部季度”和“指定季度”使用不同展示语义。
- 缺失分季海报或简介时使用明确回退，不静默伪装成分季内容。
- 季度选择与资源搜索、缺集矩阵、订阅和 URL保持一致。
- 季度详情独立缓存，切换已访问季度可以即时恢复。
- 处理 Season 00、未播出季、分割季度和元数据变化。

## 4. 非目标

- 不为 TMDB 没有的数据自动编写季度简介。
- 不默认把剧集总简介复制为每季简介。
- 不在本需求中改变 TMDB 的官方季号。
- 不把季度切换做成新的整页导航或资源加载中转页。
- 不一次性下载所有季度的完整集级数据和高清图片。
- 不解决动漫绝对集数与季号冲突；该能力由 REQ-025 负责。

## 5. 用户场景

### 5.1 多季电视剧

用户选择第二季，页面显示第二季海报、季度名称、第二季首播年份、集数和第二季剧情简介，资源区明确显示“第二季可用资源”。

### 5.2 某季没有中文简介

系统尝试安全的原语言简介回退，并标注“本季简介来自原语言”；如果仍为空，显示“本季暂无独立简介”，不重复剧集总简介。

### 5.3 某季没有独立海报

页面使用剧集总海报作为视觉回退，并显示“本季暂无独立海报”，用户不会误以为这是该季官方海报。

### 5.4 特别篇

选择 Season 00 时显示“特别篇”名称和独立资料，不把特别篇计入正式季度总数；资源和缺集状态使用 Season 00 范围。

### 5.5 快速切换季度

用户从第一季快速切到第三季。页面保持剧集主体稳定，旧的第一季响应不得覆盖第三季，已缓存的第三季资料可以立即显示。

## 7. 数据模型

### 7.1 季度摘要

剧集主体详情中的季度列表返回：

- `tmdb_season_id`
- `season_number`
- `name`
- `episode_count`
- `air_date`
- `poster_path`
- `overview_available`
- `data_version`

摘要用于季度选择和预加载判断，不要求包含完整集列表。

### 7.2 季度详情

独立季度详情至少包含：

```json
{
  "series_tmdb_id": 123,
  "tmdb_season_id": 456,
  "season_number": 2,
  "name": "第 2 季",
  "overview": "本季独立简介",
  "overview_language": "zh-CN",
  "poster_path": "/season-poster.jpg",
  "air_date": "2025-01-10",
  "episode_count": 12,
  "vote_average": 8.1,
  "source": "tmdb",
  "fetched_at": "2026-07-26T08:00:00Z",
  "data_version": 1
}
```

可选包含轻量集摘要，用于 REQ-011，但首屏不得因完整集列表而阻塞。

### 7.3 身份规则

- 季度主身份使用媒体类型 `tv`、剧集 TMDB ID和 `season_number`。
- `tmdb_season_id` 作为外部条目身份和差异校验字段。
- 季号为 `0` 表示特别篇，不等同未知季度。
- 未知季号使用 `null` 或待确认状态，不得映射为 `0`。
- 外部季度身份变化时保存前后快照并进入映射复核。

## 8. 元数据获取

- 剧集主体请求获取季度摘要列表。
- 用户选择季度时调用受控季度详情接口，例如 `GET /api/v1/media/tv/{tmdb_id}/seasons/{season_number}`。
- 服务端从 TMDB 对应季度详情端点读取，而不是重复返回剧集主体资料。
- 请求包含用户主语言和可配置的回退语言。
- 季度详情与集列表可分别缓存；首屏只等待季度核心详情。
- 相同剧集和季度的并发请求合并。
- TMDB 暂时不可用时返回最近成功缓存并标记 stale。
- 不支持或不存在的季号返回结构化中文错误，不回退到整剧详情冒充成功。

## 9. 语言与缺失回退

### 9.1 季度简介

优先级：

1. 用户主语言的季度简介。
2. 原语言或配置回退语言的季度简介，并标注语言来源。
3. 明确显示“本季暂无独立简介”。

禁止默认使用剧集总简介作为季度简介。产品可以在独立的“剧集简介”区域保留总简介，但必须与“本季简介”分开。

### 9.2 季度海报

优先级：

1. 当前季度海报。
2. 用户为本季选择并锁定的海报。
3. 剧集总海报作为回退，同时显示“本季暂无独立海报”。
4. 统一占位图。

海报回退不能修改季度数据本身，也不能被标记为季度官方海报。

### 9.3 名称和日期

- 季度名称为空时显示“第 N 季”；Season 00 显示“特别篇”。
- 日期为空时显示“播出日期待定”，不使用剧集首播日期冒充。
- 未播出季度可以展示公布信息，但不能计入缺集。

## 10. 详情页展示层级

### 10.1 全部季度

未选择具体季度时：

- 主展示使用剧集总海报、总标题和剧集总简介。
- 下方展示季度导航，包含季度海报缩略图、名称、首播年份和集数。
- 资源区标题为“全部季度资源”。
- 缺集和订阅摘要按整剧维度展示。

### 10.2 指定季度

选择季度后：

- 保留剧集总标题和 TMDB 剧集身份。
- 主视觉或明确的季度资料区切换到当前季海报。
- 显示季度名称、季号、播出日期、集数和本季简介。
- 显示“返回全部季度”或可辨识的当前选择。
- 资源区标题包含具体季度，例如“第 2 季可用资源”。
- 缺集、订阅和日历入口携带相同季度身份。

不能只改变下拉框值和资源查询参数，而让页面资料保持不变。

## 11. 季度导航

- 多季剧集优先使用可横向浏览的季度条带或紧凑列表，而不是只有难辨识的纯文本下拉框。
- 每个季度项显示海报缩略图或占位、名称、年份和集数。
- 当前季度具有文本和视觉双重选中状态。
- 季度数量很多时支持按年份或季号快速定位，不一次加载所有高清海报。
- 特别篇与正式季度视觉上分开，但仍可访问。
- 键盘、触摸和屏幕阅读器均可操作。
- 移动端可以使用选择器加当前季摘要，文字和图片不得溢出。

## 12. 切换季度的加载行为

遵循 REQ-028：

1. 用户选择季度并立即更新路由和选中状态。
2. 已缓存季度资料立即显示，否则只在季度资料区显示稳定骨架。
3. 剧集总标题、返回、收藏和页面框架保持不变。
4. 季度详情与季度资源可以并行加载。
5. 资源区显示该季独立加载状态。
6. 任一请求失败只影响对应区域。

不得把整个 `result` 清空，也不得重新进入整页资源聚合加载页。

## 13. 分季资源、缺集与订阅联动

- 资源搜索使用当前 `season_number`，页面同时显示对应季度资料。
- 全部季度资源和具体季度资源使用不同快照键。
- REQ-011 缺集矩阵使用同一季度身份和 TMDB 集数基线。
- REQ-007 订阅入口默认带入当前季度，但允许用户改为整剧或未来新集。
- 日历展示当前季播出范围、下一集和未播出状态。
- REQ-025 人工集序映射优先于简单季号推断，但不得覆盖已锁定季度资料。
- 季度资源为空不能显示为“本剧没有资源”，必须明确是当前季范围。

## 14. Season 00、未播出和异常季度

- Season 00 使用“特别篇”主文案，并显示独立海报和简介（若有）。
- 特别篇不计入正式季度数量和正式集完整度。
- 未播出季显示预计日期和“尚未播出”，不进入缺失资源告警。
- 集数为 0 可能表示数据未完善，不能直接判断为空季度。
- TMDB 删除、合并或重编号季度时保留旧快照，向 REQ-025/011 产生待复核事项。
- 季号越界、类型错误或数据冲突使用 REQ-027 结构化提示。

## 15. 缓存、刷新与竞态

- 缓存键至少包含 TMDB 剧集 ID、季号、语言和元数据版本。
- 季度摘要和季度详情使用独立 TTL。
- 切换回已访问季度先显示缓存，再按新鲜度后台刷新。
- 手动“刷新资料”只刷新当前剧集和当前季度元数据，不自动刷新资源。
- 手动“刷新资源”不清除季度海报和简介。
- 每次季度选择生成请求版本；旧季度迟到响应不得覆盖当前季度。
- TMDB 失败时保留缓存并标明最后更新时间。

## 16. API 与错误契约

建议接口：

- `GET /api/v1/media/tv/{tmdb_id}`：剧集总资料和季度摘要。
- `GET /api/v1/media/tv/{tmdb_id}/seasons/{season_number}`：季度核心详情。
- `GET /api/v1/media/tv/{tmdb_id}/seasons/{season_number}/episodes`：可分页或独立缓存的集级详情。

返回：

- 数据版本、语言、来源、新鲜度和缓存时间。
- 字段级回退标记，例如 `poster_fallback=series`。
- 结构化错误码，例如 `season_not_found`、`season_metadata_unavailable`、`season_mapping_conflict`。

后端不得用剧集总详情构造虚假的季度成功响应。

## 17. 中文提示与无障碍

遵循 REQ-027：

- “正在加载第 2 季资料”和“正在查找第 2 季资源”分开表达。
- 季度资料失败说明当前显示的是缓存、回退还是没有资料。
- 回退海报的替代文本注明“剧集海报（本季暂无独立海报）”。
- 季度导航使用 `aria-current` 或等价状态标记当前季。
- 切换完成后播报季度名称，不重复播报整个详情页。
- 长季度名称、原语言简介和多位季号在移动端正常换行。

## 18. 日志与指标

遵循 REQ-004，记录：

- 季度详情读取、缓存命中、语言回退、字段缺失和 stale 回退。
- 季度切换、路由恢复、资源快照范围和迟到响应丢弃。
- TMDB 季度身份变化、集数变化和映射冲突。
- 季度详情加载耗时、缓存命中率、海报缺失率和简介缺失率。

不记录完整季度简介、完整图片 URL查询参数或用户浏览历史正文。

## 19. 验收标准

### 19.1 分季内容

- 至少三部多季剧集样本在切换季度后显示不同的季度海报和简介。
- 页面明确显示当前季名称、季号、日期和集数。
- 全部季度模式正确显示剧集总海报和总简介。
- 指定季度模式不会继续把剧集总简介冒充本季简介。

### 19.2 缺失和回退

- 季度中文简介缺失时按规则使用标记后的语言回退。
- 所有语言简介都缺失时显示“本季暂无独立简介”。
- 季度海报缺失时回退有明确标记，不伪装为季度海报。
- 日期未知、集数为 0和未播出季不会产生错误缺集判断。

### 19.3 加载与导航

- 切换季度不会清空剧集主体页面或进入整页资源加载屏。
- 季度资料和季度资源独立加载、失败和重试。
- 快速切换季度时旧响应不会覆盖当前季度。
- 刷新带季号的详情 URL能恢复正确季度。
- 返回全部季度后恢复剧集总资料和全部季度资源范围。

### 19.4 业务一致性

- 页面当前季、资源查询、缺集矩阵、订阅入口和日历使用相同季号。
- Season 00 与正式季度分开，不污染正式季数量和完整度。
- TMDB 季度身份变化可以追踪并进入映射复核。
- 桌面和 360 CSS 像素移动端均能区分季度且无布局溢出。

## 20. 分期建议

1. 扩展季度摘要和独立季度详情 Schema。
2. 接入 TMDB 季度详情、语言回退和独立缓存。
3. 改造详情页为剧集主体 + 当前季度资料层级。
4. 改造季度导航、局部加载和路由恢复。
5. 接入资源、缺集、订阅、日历和动漫映射。
6. 增加多季、特别篇、缺失元数据和移动端回归测试。

## 21. 风险与依赖

| 风险 | 缓解措施 |
|---|---|
| TMDB 季度中文数据缺失 | 明确语言回退和缺失状态，不伪造简介 |
| 大量季度请求增加上游压力 | 摘要/详情分离、按需加载和独立缓存 |
| 季号与动漫发布顺序冲突 | REQ-025 映射层和人工锁定 |
| 快速切换产生错季展示 | 季度请求版本、路由身份和迟到响应丢弃 |
| 海报回退再次造成难区分 | 显式回退标记、季度名称/日期/集数共同识别 |

## 22. 待确认项与建议默认值

| 决策项 | 建议默认值 |
|---|---|
| 全部季度模式 | 显示剧集总资料 |
| 指定季度模式 | 显示季度独立资料 |
| 季度简介回退 | 主语言 -> 原语言 -> 明确暂无 |
| 剧集总简介冒充分季简介 | 禁止 |
| 季度海报回退 | 可使用剧集海报，但必须标记 |
| 季度数据加载 | 按需加载并缓存 |
| Season 00 | 显示为特别篇，独立统计 |
