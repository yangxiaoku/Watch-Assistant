## 1. 一句话定义

建立 115 影视库的可查询库存索引，在推送和整理前识别已经存在的影片、剧集、版本和文件，减少重复下载与重复归档。

## 2. 目标与非目标

目标：

- 持续索引允许范围内的 115 文件和媒体身份。
- 判断同一文件、同一逻辑媒体和不同质量版本。
- 推送前提示“已存在、存在其他版本、部分缺失”。
- 为缺集、洗版、清理和库体检提供可靠数据。

非目标：

- 不索引账号全部私人目录。
- 不仅凭同名就判定重复。
- 不在检测到重复时自动永久删除。
- 不把索引当作 115 的唯一真实状态。

## 4. 重复层级

- **精确重复**：相同 115 文件 ID、可用内容摘要或可信的 infohash。
- **媒体重复**：相同 TMDB ID的电影。
- **剧集重复**：相同 TMDB ID、季号和集号。
- **版本重复**：逻辑媒体相同，但分辨率、来源、编码、杜比或体积不同。
- **目录重复**：多个目录被识别为同一媒体，需人工确认。

只有精确重复可以自动阻止重复推送。媒体或版本重复默认提示，并交由 REQ-008/REQ-001 决定是否升级或洗版。

## 5. 索引规则

- 使用稳定文件 ID和目录 ID，不只依赖可变化路径。
- 保存 pickcode、大小、修改时间和脱敏相对位置。
- 复用 REQ-001 的 TMDB 身份和命名解析。
- 全量扫描保存 complete 标记；不完整索引不能得出“库内不存在”的确定结论。
- 增量事件和周期补偿扫描共同维护最终一致。
- 删除、移动、隔离和恢复都更新索引版本。

## 6. 推送前检查

返回以下结论之一：

- 库内不存在。
- 已有完全相同资源。
- 已有相同媒体的其他版本。
- 剧集部分存在，列出缺失范围。
- 索引过期或不完整，无法确认。

自动订阅只有在“库内不存在”或质量升级规则明确允许时才能推送。索引不完整时默认要求确认。

## 7. 界面要求

- 资源列表显示“库内已有”“已有其他版本”“部分缺集”。
- 详情页展示已拥有版本的安全摘要。
- 库存页支持按分类、地区、质量和更新时间筛选。
- 展示索引最后完整时间、增量积压和数据新鲜度。

## 8. 验收标准

- 相同文件不会重复推送。
- 同电影不同版本不会误判为精确重复。
- 相同剧集季集号可以正确识别。
- 索引不完整时不会错误断言“库内不存在”。
- 移动和重命名不产生重复库存项。
- 隔离和恢复会更新可用状态。
- 推送前检查在索引新鲜时 95% 于 1 秒内完成。

## 9. 分期建议

1. 只读全量索引和文件身份。
2. 媒体身份与重复层级。
3. 推送前检查和资源标记。
4. 增量更新、统计和其他需求联动。
