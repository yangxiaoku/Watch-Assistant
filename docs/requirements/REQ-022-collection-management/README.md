## 1. 一句话定义

基于 TMDB 合集和项目自定义系列，把分散影片聚合成可查看、可补齐、可订阅的系列视图，并可选生成合集目录或展示元数据。

## 2. 背景与问题

影视库按电影、剧集和地区归档后，同一系列的多部作品仍会散落在普通目录中。用户难以判断某个系列已经拥有哪些影片、缺少哪些影片，也无法一次订阅整个系列的后续作品。

合集管理应建立在媒体身份和库存索引之上，默认只提供逻辑聚合，避免为了展示合集而强制移动已经整理好的文件。

## 3. 产品目标

- 自动读取 TMDB Collection 并建立合集身份。
- 展示系列内已拥有、已订阅、缺失、未上映和忽略的作品。
- 支持订阅缺失或未来新增的合集作品。
- 支持自定义合集，解决 TMDB 不覆盖的专题和系列。
- 可选生成媒体服务器可识别的合集目录、NFO 或展示资产。
- 合集变更与文件整理分离，默认不改变 115 文件位置。

## 4. 非目标

- 不默认移动、复制或重命名现有媒体文件。
- 不把名称相似的作品自动并入同一合集。
- 不保证 TMDB 合集定义符合所有用户偏好。
- 不在 V1 建设通用标签、播放列表或推荐系统。
- 不因合集缺失自动推送未通过质量和库存检查的资源。

## 5. 用户场景

### 5.1 查看系列完整度

用户打开“碟中谍合集”，看到已拥有 6 部、缺少 1 部、另有 1 部未上映，并能进入每部影片详情。

### 5.2 一键订阅缺失作品

用户选择“订阅缺失和未来作品”，系统为合集内符合条件的影片创建 REQ-007 订阅，并沿用指定质量策略。

### 5.3 自定义系列

用户把 TMDB 未归入同一 Collection 的关联影片添加到自定义合集，并设置排序、名称和封面。

### 5.4 输出合集展示

用户选择为某媒体库生成合集 NFO、封面或逻辑目录。系统先预览影响范围，不改动源文件。

## 7. 合集与成员模型

合集分为：

- **TMDB 合集**：以 TMDB Collection ID作为外部身份，定期同步成员。
- **自定义合集**：以内部 ID作为身份，由用户维护成员和顺序。

每个成员以 TMDB 电影 ID作为身份，并记录：

- TMDB 顺序、用户覆盖顺序和上映日期。
- 库存状态、拥有版本数量和索引新鲜度。
- 订阅状态和最近搜索结果。
- 是否被用户忽略及原因。
- 是否未上映、上映日期是否确定。

同一影片可以属于多个自定义合集，但同一 TMDB 合集内不得重复。

## 8. 自动识别与同步规则

- REQ-001 成功匹配电影 TMDB ID后，读取其 Collection ID并关联合集。
- REQ-010 库存索引变化后重算已拥有状态，不重复扫描全盘。
- TMDB Collection 成员变化以外部快照保存，新增和移除需记录差异。
- TMDB 暂时不可用时保留最近成功快照，不把全部成员标记为缺失。
- 用户人工移除的成员保存覆盖规则，后续同步不得自动加回，除非用户清除覆盖。
- 无可靠 TMDB 身份的资源不自动进入合集，进入待确认流程。

## 9. 完整度与状态规则

成员状态：

- `owned`：库存中存在至少一个已识别版本。
- `subscribed`：尚未拥有，但存在有效订阅。
- `missing`：已上映、未拥有且未忽略。
- `upcoming`：未上映或处于配置的上映宽限期。
- `ignored`：用户明确不纳入完整度。
- `unknown`：库存或 TMDB 数据不完整，无法确定。

完整度仅使用 `owned / (owned + missing)`，`upcoming`、`ignored` 和 `unknown` 单独展示，不制造虚假的 100%。库存索引不完整时必须显示“状态待确认”。

## 10. 订阅联动

- 用户可订阅单个缺失作品、全部已上映缺失作品或未来新增成员。
- 批量创建前展示作品数量、质量策略和自动动作模式。
- 默认使用“仅提醒”模式，用户可选择 REQ-007 支持的其他模式。
- 已拥有、已订阅、忽略或 TMDB 身份不确定的成员不重复创建订阅。
- TMDB 合集新增未来作品时，只有启用“自动订阅新增成员”才创建订阅。
- 所有资源仍需经过质量策略、库存去重、检测和推送保护。

## 11. 合集输出与文件规则

Should 支持以下输出：

- 合集 NFO、海报、背景图和摘要元数据。
- 指向现有 STRM 的逻辑合集目录或媒体服务器集合清单。
- 按合集命名模板生成的预览计划。

规则：

- 默认仅写入受管元数据目录，不移动 115 源文件。
- 任何移动、复制、重命名必须转交 REQ-001 生成独立计划并明确确认。
- 同一影片属于多个合集时不得复制源文件，可使用逻辑引用或多份轻量元数据。
- TMDB 合集名称变化不得静默重命名用户自定义目录。
- 清理合集输出前必须确认本轮扫描完整，遵守 REQ-002 清理保护。

## 12. 管理界面

### 12.1 合集列表

展示封面、名称、成员数、已拥有数、缺失数、未来作品数、完整度和最近更新时间。支持按完整度、类型、订阅状态和数据异常筛选。

### 12.2 合集详情

- 按 TMDB 顺序、上映时间或用户顺序展示成员。
- 每个成员显示拥有、缺失、订阅、未上映、忽略或待确认状态。
- 展示拥有版本摘要和最近库存更新时间。
- 提供订阅缺失、忽略、调整顺序、刷新元数据和生成输出计划。

### 12.3 自定义合集

支持创建、改名、选择封面、添加/移除影片、拖动排序和删除。删除合集只删除逻辑关系和受管元数据，不删除媒体文件。

## 13. API 与数据要求

- API 支持合集列表、详情、成员分页、状态筛选和完整度统计。
- 所有批量修改使用幂等键和版本号，避免并发覆盖。
- TMDB 快照、用户覆盖和库存状态分开保存，不能用外部同步覆盖用户选择。
- 合集输出计划包含路径摘要、文件数量、覆盖项、冲突和规则版本。
- 对外返回内部媒体 ID和 TMDB ID，不泄漏完整 115 路径。

## 14. 日志与通知

- 遵循 REQ-004，记录合集发现、成员同步、人工覆盖、完整度变化、订阅创建和输出计划。
- TMDB 成员变化产生差异摘要，不为每个未变化成员记录 INFO。
- 合集出现新成员、缺失作品找到资源或同步失败时，可通过 REQ-012 通知。
- 通知默认聚合，不在正文中包含资源链接和完整路径。

## 15. 验收标准

- 已识别电影能正确关联 TMDB Collection，未关联电影不误入合集。
- 合集详情正确区分已拥有、缺失、订阅、未上映、忽略和未知。
- 库存索引不完整时不会错误显示“全集齐全”。
- TMDB 同步失败时保留最近成功数据，不清空成员。
- 一键订阅不会为已拥有或已订阅作品创建重复订阅。
- 用户人工覆盖不会被下一次 TMDB 同步覆盖。
- 默认启用合集后不移动、复制或重命名任何 115 文件。
- 删除自定义合集不会删除媒体文件。
- 合集输出可预览、可追踪，清理受扫描完整性保护。

## 16. 分期建议

1. TMDB Collection 模型、自动识别和只读合集详情。
2. 库存状态、完整度和异常状态。
3. 缺失/未来作品订阅与通知。
4. 自定义合集、排序和人工覆盖。
5. 合集 NFO、图片和逻辑目录输出。

## 17. 风险与依赖

| 风险 | 缓解措施 |
|---|---|
| TMDB 合集不完整或定义变化 | 保存快照、人工覆盖和差异确认 |
| 库存索引不完整导致误判 | 新鲜度标记和 unknown 状态 |
| 批量订阅制造重复任务 | 库存检查、订阅幂等和默认仅提醒 |
| 合集目录破坏现有整理结构 | 默认逻辑聚合，不移动源文件 |
| 多合集造成重复文件 | 使用逻辑引用和轻量元数据 |

| 批量订阅模式 | 仅提醒 |
| 未上映作品 | 单独展示，不计入缺失 |
| 删除合集 | 仅删除逻辑关系和受管元数据 |
