# REQ-012：通知中心

| 字段 | 内容 |
|---|---|
| 版本 | V1.0 |
| 状态 | 开发中 |
| 优先级 | P1 |
| 依赖 | REQ-004、任务系统 |
| 使用方 | REQ-007、REQ-009、REQ-016、REQ-018 |

## 1. 一句话定义

将资源发现、任务完成、授权失效、失败和高风险操作通过站内通知及可配置渠道可靠送达用户。

## 2. 目标与非目标

目标：

- 用户无需持续打开页面观察任务。
- 通知内容中文、可行动、可跳转。
- 重复事件聚合，避免通知轰炸。
- 渠道失败可重试并有健康状态。

非目标：

- 不在通知中包含 Cookie、Token、完整磁力或真实直链。
- 不让第三方通知渠道直接执行高风险操作。
- 不保证所有外部渠道永久可用。

## 3. 功能范围

| 编号 | 功能 | 优先级 |
|---|---|---|
| NTF-001 | 站内通知中心 | Must |
| NTF-002 | 事件订阅和通知偏好 | Must |
| NTF-003 | 聚合、去重和静默时段 | Must |
| NTF-004 | 失败重试和渠道健康 | Must |
| NTF-005 | Webhook 渠道 | Must |
| NTF-006 | Bark、Telegram 等适配器 | Should |
| NTF-007 | 浏览器/PWA 推送 | Should |

## 4. 通知事件

必须支持：

- 订阅发现符合条件资源。
- 任务等待确认、完成、失败或 uncertain。
- 115 Cookie、qB 或关键依赖失效。
- 整理需要人工确认或发生冲突。
- STRM 清理被阻止或增量持续失败。
- 存储达到阈值。
- Agent 高风险计划等待批准。
- 备份、恢复或库体检发现严重问题。

## 5. 通知规则

- 事件使用稳定事件码和 REQ-004 中文模板。
- 相同对象、事件和状态在去重窗口内合并。
- needs_auth 等全局问题发送一次聚合通知，不为每个任务重复发送。
- INFO 可配置静默时段；ERROR 和安全事件可选择突破静默。
- 每条通知包含标题、摘要、时间、严重度和站内跳转目标。
- 外部渠道只发送必要的脱敏信息。

## 6. 渠道管理

- 渠道凭据作为 Secret 保存，前端只显示已配置状态。
- 提供测试通知和健康检查。
- 失败采用指数退避和最大重试次数。
- 永久失败进入通知死信列表，可手动重试。
- 一个渠道失败不阻塞其他渠道和业务任务。

## 7. 界面要求

- 顶部通知入口显示未读数量。
- 支持全部、未读、需要处理、错误分类。
- 支持标记已读、全部已读和跳转关联任务。
- 设置页配置事件、渠道、静默时段和严重度。

## 8. 验收标准

- 同一事件在去重窗口内不会重复轰炸。
- 全局 Cookie 失效只产生聚合通知。
- 外部渠道失败不影响业务成功。
- 通知重试不会重复创建站内通知。
- 所有内容为中文且不含敏感信息。
- 点击通知可定位到对应任务、订阅或设置页。
- 用户可完全关闭非安全类外部通知。

## 9. 分期建议

1. 站内通知、未读和偏好。
2. 聚合、静默和任务跳转。
3. Webhook、Bark、Telegram。
4. PWA 推送和运营统计。

## 10. 待确认项与建议默认值

| 决策项 | 默认值 |
|---|---|
| 站内通知 | 开启 |
| 外部渠道 | 关闭，用户配置 |
| 去重窗口 | 30 分钟 |
| 静默时段 | 23:00-08:00 |
| ERROR 突破静默 | 开启 |
| 站内保留 | 90 天 |

## 11. 当前实现证据（2026-07-31）

- 站内通知已支持统一业务事件目录、中文标题/摘要、可行动对象、偏好禁用/静默事件和 30 分钟
  去重聚合；普通启动和读取日志不会生成通知。
- workflow 阶段在事务提交后发出 `workflow.stage_changed`，可行动状态会生成站内通知，并与
  workflow ID 关联；同一事件仍通过现有 Webhook Outbox 投递，不阻塞业务事务。
- 搜索 `discovery` 和内容检测 `inspection` 子任务现在在各自状态事务提交后发出同一事件，
  通知只对完成、失败、跳过、不确定和取消等可行动状态生效，运行中状态不会生成用户通知。
- 推送任务的 `push` 阶段也在创建、重试、取消、终态和恢复后发出同一事件；任务事件仍保留，
  但 workflow 通知使用 workflow/correlation ID 作为跳转和去重主体。
- 整理 operation 的状态事件和 `organization` 阶段事件现在带 operation/workflow/correlation ID，
  取消请求仍只记录本地中止意图，不伪造远端撤回。
- 无 workflow 关联的整理 operation 失败现在使用独立的 `organize.operation.failed` 事件生成
  错误级站内通知，并跳转整理工作台；关联 workflow 的失败继续只由 `workflow.stage_changed`
  通知，避免同一次失败重复提醒。错误详情仅使用白名单错误码。
- STRM dirty worker 在重试耗尽或增量结果明确含失败项时，为无 workflow 的媒体库生成
  `strm.dirty_failed` 错误通知并跳转设置；关联 workflow 时仍只保留 `workflow.stage_changed`
  通知，错误详情同样只使用稳定错误码。
- 订阅搜索失败在持久化退避时间和 `search_unavailable` 后生成 `subscription.check_failed` 错误
  通知并跳转设置；正常无匹配检查不会进入错误通知链。
- 无 workflow 关联的内容检测批次失败现在生成错误通知并跳转资源检测设置；已关联 workflow 的
  批次失败只保留 workflow 阶段通知，避免同一失败重复提醒。
- qBittorrent 内容检测依赖不可用时，检测 worker 额外发出全局
  `inspection.dependency_failed` 事件；通知以 `dependency:qbittorrent` 作为固定聚合主体，30 分钟内
  的多批次失败合并为一条错误通知，并抑制对应的逐批 `inspection.batch_failed` 重复提醒。
- 整理预览进入 `needs_review` 时，API 预览和自动预览都会发出 `organize.needs_review`；同一计划的重复预览复用 30 分钟去重并累加次数，通知可跳转整理工作台。
- 任务 worker 的远端 `uncertain` 现在发出 `task.uncertain`（不再误报为失败），并携带任务
  ID；任务失败、115 不可用、订阅发现新资源、备份失败和异常恢复预览已接入通知过滤。
- Webhook 管理接口提供单端点测试通知；测试载荷只包含 `webhook.test`、版本和中文摘要，
  不包含 Secret 或业务资源，且复用持久投递、签名、重试和死信状态。
- `watchctl` 已接入通知列表、未读筛选、单条已读和全部已读命令；命令只调用正式通知 API，复用认证、权限、错误码和 JSON/JSONL envelope。
- 通知偏好已支持默认 `23:00-08:00` 静默时段、IANA 时区、错误/安全事件突破静默，以及前端设置控件；配置通过版本号并发控制和 046 幂等迁移保存。
- Webhook 端点列表已提供持久投递的运营统计：总数、成功数、待重试数、死信数、终态失败率和下一次重试时间；这只是可靠渠道运营 API 的第一阶段。
- 当前仍未宣称 REQ-012 完成：完整事件矩阵、外部渠道真实接收端验收、通知渠道统一运营闭环、Bark/Telegram
  和 PWA Push 仍按需求状态保持待实现或待验收。
