# REQ-012：通知中心

| 字段 | 内容 |
|---|---|
| 版本 | V1.0 |
| 状态 | 待验收 |
| 优先级 | P1 |
| 依赖 | REQ-004、任务系统 |
| 使用方 | REQ-007、REQ-009、REQ-016、REQ-018 |

## 1. 一句话定义

将资源发现、任务完成、授权失效、失败和高风险操作通过站内通知及可配置渠道可靠送达用户。

## 2. 目标与非目标

目标：

- 用户无需持续打开页面观察任务。
- 通知内容中文、可行动、可跳转。
- 重复事件聚合，避免通知轰炸。
- 渠道失败可重试并有健康状态。

非目标：

- 不在通知中包含 Cookie、Token、完整磁力或真实直链。
- 不让第三方通知渠道直接执行高风险操作。
- 不保证所有外部渠道永久可用。

## 3. 功能范围

| 编号 | 功能 | 优先级 |
|---|---|---|
| NTF-001 | 站内通知中心 | Must |
| NTF-002 | 事件订阅和通知偏好 | Must |
| NTF-003 | 聚合、去重和静默时段 | Must |
| NTF-004 | 失败重试和渠道健康 | Must |
| NTF-005 | Webhook 渠道 | Must |
| NTF-006 | Bark、Telegram 等适配器 | Should |
| NTF-007 | 浏览器/PWA 推送 | Should |

## 4. 通知事件

必须支持：

- 订阅发现符合条件资源。
- 任务等待确认、完成、失败或 uncertain。
- 115 Cookie、qB 或关键依赖失效。
- 整理需要人工确认或发生冲突。
- STRM 清理被阻止或增量持续失败。
- 存储达到阈值。
- Agent 高风险计划等待批准。
- 备份、恢复或库体检发现严重问题。

## 5. 通知规则

- 事件使用稳定事件码和 REQ-004 中文模板。
- 相同对象、事件和状态在去重窗口内合并。
- needs_auth 等全局问题发送一次聚合通知，不为每个任务重复发送。
- INFO 可配置静默时段；ERROR 和安全事件可选择突破静默。
- 每条通知包含标题、摘要、时间、严重度和站内跳转目标。
- 外部渠道只发送必要的脱敏信息。

## 6. 渠道管理

- 渠道凭据作为 Secret 保存，前端只显示已配置状态。
- 提供测试通知和健康检查。
- 失败采用指数退避和最大重试次数。
- 永久失败进入通知死信列表，可手动重试。
- 一个渠道失败不阻塞其他渠道和业务任务。

## 7. 界面要求

- 顶部通知入口显示未读数量。
- 支持全部、未读、需要处理、错误分类。
- 支持标记已读、全部已读和跳转关联任务。
- 设置页配置事件、渠道、静默时段和严重度。

## 8. 验收标准

- 同一事件在去重窗口内不会重复轰炸。
- 全局 Cookie 失效只产生聚合通知。
- 外部渠道失败不影响业务成功。
- 通知重试不会重复创建站内通知。
- 所有内容为中文且不含敏感信息。
- 点击通知可定位到对应任务、订阅或设置页。
- 用户可完全关闭非安全类外部通知。

## 9. 分期建议

1. 站内通知、未读和偏好。
2. 聚合、静默和任务跳转。
3. Webhook、Bark、Telegram。
4. PWA 推送和运营统计。

## 10. 待确认项与建议默认值

| 决策项 | 默认值 |
|---|---|
| 站内通知 | 开启 |
| 外部渠道 | 关闭，用户配置 |
| 去重窗口 | 30 分钟 |
| 静默时段 | 23:00-08:00 |
| ERROR 突破静默 | 开启 |
| 站内保留 | 90 天 |

## 11. 当前实现证据（2026-07-31）

- 站内通知已支持统一业务事件目录、中文标题/摘要、可行动对象、偏好禁用/静默事件和 30 分钟
  去重聚合；普通启动和读取日志不会生成通知。
- workflow 阶段在事务提交后发出 `workflow.stage_changed`，可行动状态会生成站内通知，并与
  workflow ID 关联；同一事件仍通过现有 Webhook Outbox 投递，不阻塞业务事务。
- 任务 worker 的远端 `uncertain` 现在发出 `task.uncertain`（不再误报为失败），并携带任务
  ID；任务失败、115 不可用、订阅发现新资源、备份失败和异常恢复预览已接入通知过滤。
- Webhook 管理接口提供单端点测试通知；测试载荷只包含 `webhook.test`、版本和中文摘要，
  不包含 Secret 或业务资源，且复用持久投递、签名、重试和死信状态。
- `watchctl` 已接入通知列表、未读筛选、单条已读和全部已读命令；命令只调用正式通知 API，复用认证、权限、错误码和 JSON/JSONL envelope。
- 通知偏好已支持默认 `23:00-08:00` 静默时段、IANA 时区、错误/安全事件突破静默，以及前端设置控件；配置通过版本号并发控制和 046 幂等迁移保存。
- 当前仍未宣称 REQ-012 完成：完整事件矩阵、外部渠道真实接收端验收、渠道健康/重试/死信、Bark/Telegram
  和 PWA Push 仍按需求状态保持待实现或待验收。
