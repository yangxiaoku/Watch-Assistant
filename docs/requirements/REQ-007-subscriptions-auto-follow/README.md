# REQ-007：影视订阅与自动追更

| 字段 | 内容 |
|---|---|
| 版本 | V1.0 |
| 状态 | 待验收 |
| 优先级 | P0 |
| 依赖 | TMDB 上映/播出元数据、REQ-005、REQ-008、REQ-009、REQ-012 |

## 1. 一句话定义

允许用户订阅电影、剧集、季度或具体集数，系统定期搜索新资源并按策略提醒、待确认推送或自动推送。

## 2. 背景与目标

当前无资源观察列表主要服务后台复查，不是用户可管理的订阅产品。收藏也只保存在浏览器，无法表达质量要求、追更范围和自动动作。

目标：

- 用户可明确订阅和取消订阅。
- 电影资源出现、剧集更新或更优版本出现时自动发现。
- 用户可通过日历查看待上映、待播出、已播未入库和延期内容。
- 不重复通知或推送相同 canonical resource。
- 与质量策略、任务中心、整理和通知形成闭环。

## 3. 非目标

- 不默认开启全自动推送。
- 不将普通收藏自动转换为订阅。
- 不在资源尚未通过基本校验时自动推送。
- 不承诺上游不存在时一定找到资源。

## 4. 功能范围

| 编号 | 功能 | 优先级 |
|---|---|---|
| SUB-001 | 电影、剧集、季度和集数订阅 | Must |
| SUB-002 | 定时搜索和立即检查 | Must |
| SUB-003 | 新资源识别与去重 | Must |
| SUB-004 | 关联质量策略 | Must |
| SUB-005 | 仅提醒、确认推送、自动推送三种模式 | Must |
| SUB-006 | 暂停、恢复、取消和到期 | Must |
| SUB-007 | 追更进度和最近结果 | Must |
| SUB-008 | 剧集完结自动停止 | Should |
| SUB-009 | 上映与追更日历 | Should |
| SUB-010 | 播出延期、变更和数据新鲜度 | Should |

## 5. 业务规则

- 订阅对象使用 TMDB ID、媒体类型、季度和可选集号，不使用自由文本作为身份。
- 每个订阅绑定一个 REQ-008 质量策略；无策略时使用安全默认策略。
- 新资源按 canonical key 去重；已经通知、拒绝、推送或库内存在的资源不重复处理。
- 电影订阅在首次符合条件资源出现后可自动完成，也可继续等待更高质量版本。
- 剧集订阅按 TMDB 播出日和已发现集数持续检查。
- 自动推送只允许启用已验证的资源类型和 115 能力。
- 自动推送前必须经过库内重复检测和幂等检查。
- 连续失败采用退避，115 needs_auth 时暂停所有自动推送。
- 用户手动拒绝的资源保存拒绝原因，除非资源版本实质变化，否则不再推荐。

## 6. 订阅状态

```text
active -> matched -> awaiting_confirmation -> submitted -> completed
   |          |               |                  |
   v          v               v                  v
paused      no_match        rejected           failed
   |
   v
cancelled / expired
```

后台检查和资源推送是独立任务，检查成功不代表推送成功。

## 7. 界面要求

- 详情页提供“订阅”按钮和模式选择。
- 电视剧可选整剧、指定季度或仅未来新集。
- 订阅中心展示下一次检查、质量策略、最近发现、推送状态和失败原因。
- 提供“立即检查”“暂停”“修改策略”“取消订阅”。
- 新资源以中文说明匹配了哪些质量条件。

## 8. 上映与追更日历

### 8.1 日历范围

日历聚合以下事件：

- 已订阅电影的院线、流媒体或数字发行日期；来源不能区分时显示通用上映日期。
- 已订阅剧集的下一集播出时间和季度首播/完结时间。
- 已播出但库存中仍缺失的集数。
- REQ-022 合集中已经公布的未来作品。
- 用户设置的订阅检查、暂停到期和质量等待截止时间。

支持月历、周列表和“未来 30 天”视图，并按电影、剧集、动漫、订阅状态和是否缺失筛选。

### 8.2 状态规则

日历事件统一标记：

- `upcoming`：尚未到公布时间。
- `airs_today`：按用户时区当天播出或上映。
- `aired_waiting`：已经播出但仍处于资源发布宽限期。
- `missing`：宽限期结束后库存仍不存在。
- `acquired`：库存已存在符合条件的版本。
- `delayed`：上游日期明确推迟。
- `date_unknown`：只有计划信息，没有可靠日期。

日期来自 TMDB 或登记的可信元数据快照，并显示最后更新时间。上游删除或修改日期时保留前后差异，不能把未知日期默认为当天。

### 8.3 自动动作保护

- 到达播出日期只触发订阅检查，不直接创建 115 推送任务。
- 检查结果仍需通过资源匹配、质量策略、磁力检测和库存去重。
- 电影和剧集可以配置独立资源发布宽限期，避免播出后立即产生重复空搜索。
- 上游日期变化时重新安排检查，但不重复创建已经存在的计划。
- 用户时区变化只影响展示和未来调度，不篡改原始 UTC 时间。
- 延期和日期未知默认只提醒，不视为订阅失败。

### 8.4 通知

- 支持“即将播出”“今日更新”“已播仍缺失”和“播出延期”通知。
- 默认不为每一集发送多条渠道通知；同一剧集在配置窗口内聚合。
- 通知可直接进入日历日期、订阅详情或缺集矩阵。
- 静默时段、渠道和去重遵循 REQ-012。

## 9. 日志与通知

遵循 REQ-004，记录订阅创建、修改、检查、匹配、去重、自动推送、停止、日历同步、日期变化和调度调整。通知使用 REQ-012，不记录完整查询词或资源链接。

## 10. 验收标准

- 电影、整剧、季度和未来新集订阅均可创建和取消。
- 同一资源不会重复通知或重复推送。
- 暂停状态不执行搜索和推送。
- 仅提醒模式绝不创建 115 任务。
- 确认模式必须由用户批准。
- 自动模式仍受质量、重复检测、能力和幂等保护。
- needs_auth 会暂停自动推送并发送一次聚合通知。
- 服务重启后订阅计划和下一次检查时间可恢复。
- 月历、周列表和未来视图能正确展示订阅事件和本地时区。
- 到达播出日期只触发资源检查，不绕过质量、检测和库存保护。
- 已播未入库与尚在发布宽限期可以明确区分。
- 上游日期延期后调度会更新，原日期差异可追踪且不会重复创建任务。

## 11. 分期建议

1. 服务端订阅模型和手动检查。
2. 定时调度、新资源去重和订阅中心。
3. 质量策略和确认推送。
4. 自动推送、剧集完结和运营指标。
5. 上映/播出日历、延期差异和聚合通知。

## 12. 待确认项与建议默认值

| 决策项 | 默认值 |
|---|---|
| 默认模式 | 仅提醒 |
| 检查频率 | 电影 12 小时，剧集 6 小时 |
| 自动推送 | 关闭 |
| 电影首次命中后 | 完成订阅，可选继续洗版 |
| 剧集完结后 | 自动停止检查 |
| 默认日历范围 | 未来 30 天 |
| 电影资源宽限期 | 上映后 24 小时 |
| 剧集资源宽限期 | 播出后 2 小时 |
| 日期变化 | 更新调度并记录差异，不重复任务 |

## 13. 当前实现证据（2026-07-31）

- 搜索依赖失败会持久化稳定错误码 `search_unavailable`，保留下一次退避检查时间，并发出
  `subscription.check_failed` 业务事件供 REQ-012 通知链消费。
- 正常 `no_match` 检查仍只记录 `subscription.checked`，不会生成错误级通知。
- 本项不改变默认关闭的订阅调度、自动推送、日历或真实上游验收状态。
