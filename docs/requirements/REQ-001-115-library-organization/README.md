## 1. 一句话定义

根据 115 中的文件名自动匹配 TMDB，完成分类、地区归档、标准化命名和可控洗版，把转存资源自动整理成可被 Emby、Jellyfin、Plex 稳定识别的影视库。

## 2. 背景与问题

项目当前主要解决“发现资源并推送到 115”，资源进入 115 后仍需人工判断片名、年份、媒体类型、季集号、目标目录和保留版本。目录和命名不一致会降低媒体服务器识别率，同一影片多个版本也会长期占用空间。

当前缺口：

- 没有受控入库目录和媒体库目录模型。
- 没有针对云端文件的文件名解析、TMDB 候选匹配和人工确认流程。
- 没有电影、剧集、动漫、纪录片、综艺的稳定分类规则。
- 没有国产、欧美、日韩、其他的二级地区规则。
- 没有媒体服务器兼容的命名模板和冲突保护。
- 没有可解释、可回滚的洗版策略。

本需求描述的是拟新增能力，完成验收前不得描述为已上线功能。

## 当前集成验收状态

- 离线验收：已完成本轮集成验收，覆盖 fake 115 网关、整理门禁、人工确认、候选补搜、操作状态和前端工作台。
- live/生产验收：未完成；未执行真实 115 写操作、真实媒体库整理或生产部署，因此本需求仍未上线。

## 3. 产品目标

- 自动识别 115 指定入库目录中的影视文件。
- 高置信度资源自动匹配 TMDB，低置信度资源进入待确认。
- 自动归入五大主分类，并按地区进行可选二级分流。
- 使用统一命名模板，提高媒体服务器识别成功率。
- 按用户偏好比较同一逻辑媒体的版本，安全完成洗版。
- 整理任务具备预览、审计、幂等、失败重试、崩溃恢复和回滚能力。
- 整理完成后向 REQ-002 发出准确的受影响目录事件。

## 4. 非目标

- 不进行视频转码、重新封装或内容编辑。
- 不自动整理配置范围之外的 115 目录。
- 不对低置信度匹配执行无确认移动。
- 不允许静默覆盖同名目标。
- V1 不默认永久删除任何 115 文件。
- 不以文件名关键字作为唯一分类依据。

## 5. 用户场景

### 5.1 新电影自动入库

电影下载到入库目录后，系统识别片名和年份，匹配 TMDB，归入“电影/地区/片名 (年份) {tmdb-id}”，同步移动字幕和 NFO，并记录完整整理结果。

### 5.2 剧集持续更新

新一集进入入库目录后，系统识别 `SxxExx`，将其移动到正确剧集和季度目录，不重复整理已有集。

### 5.3 无法可靠识别

系统发现同名不同年份、季集号缺失或多个候选分差过小，不执行写操作，而是在待确认工作台展示候选和依据。

### 5.4 新版本触发洗版

同一电影或单集出现新版本。系统按配置比较杜比标记和正片体积，先生成替换计划；启用自动洗版时把旧版本移入隔离区，而不是直接删除。

## 7. 详细需求

### 7.1 目录模型

每个媒体库必须配置：

- 一个或多个入库目录。
- 一个正式媒体库根目录。
- 一个待确认目录。
- 一个隔离目录。
- 是否启用地区二级目录。

系统只能处理允许根目录内的稳定目录 ID。目录重叠、循环映射、媒体库根目录作为隔离目录等危险配置必须被拒绝。

触发来源：

- 推送或转存任务完成后的定向扫描。
- 周期补偿扫描。
- 用户手动扫描。
- Agent 通过 REQ-003 提交的授权扫描任务。
- 系统重启后的遗留任务核对。

### 7.2 文件发现

默认支持 `mkv`、`mp4`、`avi`、`mov`、`ts`、`m2ts`、`wmv`、`flv`、`webm`。

系统必须区分：

- 单文件电影和电影目录。
- 单集、集范围、季度包和多季度合集。
- 正片、样片、预告片、花絮。
- 字幕、图片、NFO、独立音轨等伴随文件。

样片、预告片和花絮不得参与正片洗版。无法判断时保留原文件并进入待确认。

### 7.3 文件名解析

解析器应提取：

- 中文名、原名、别名和年份。
- 季号、集号、集范围和特别篇。
- 分辨率、来源、视频编码。
- HDR、HDR10+、Dolby Vision。
- 音频编码、声道、Dolby Atmos。
- 语言、字幕、版本组和发布组。

必须保留原始文件名、解析字段、解析器版本和匹配依据。解析失败不得伪造字段。

### 7.4 TMDB 匹配

匹配流程：

1. 根据片名、年份和媒体类型查询候选。
2. 比较中文名、原名、别名、年份和类型。
3. 剧集进一步校验季号和集号范围。
4. 记录最高候选、第二候选、得分和分差。
5. 只有达到高置信度阈值才能自动生成可执行整理计划。

处理规则：

- 高置信度：允许自动整理。
- 中置信度：默认进入待确认。
- 低置信度或无结果：必须进入待确认。
- 同名不同年份、电影与剧集同名、季集越界和候选分差过小必须降级。
- 用户确认的 TMDB ID、分类和地区可锁定，后续不得被自动规则覆盖。
- 支持保存“名称别名到 TMDB ID”的受控映射。

### 7.5 主分类

主分类固定为：电影、剧集、动漫、纪录片、综艺。

默认优先级：

1. TMDB 纪录片 Genre 命中归入纪录片。
2. 动画 Genre 命中且符合配置归入动漫。
3. Reality、Talk、News 等配置的电视 Genre 命中归入综艺。
4. 其余 TV 归入剧集。
5. 其余 Movie 归入电影。

规则要求：

- 使用 TMDB 类型、Genre、Keyword、国家和用户规则组合判断。
- 优先级和 Genre 映射可配置并版本化。
- 人工结果优先于自动规则。
- 动画电影默认归入动漫，可按媒体库关闭。

### 7.6 地区归类

默认地区：国产、欧美、日韩、其他。

- 国产：中国大陆、香港、澳门、台湾。
- 日韩：日本、韩国。
- 欧美：北美、欧洲和用户配置的国家集合。
- 其他：未命中规则或国家信息缺失。

多国合拍默认采用 TMDB 首个有效原产国家。国家映射、优先级和人工结果必须可配置、可锁定。地区二级目录可按媒体库整体关闭。

### 7.7 命名标准化

推荐默认模板：

```text
电影目录：{title} ({year}) {tmdb-id}
电影文件：{title} ({year}) {tmdb-id}{technical-tags}.{ext}
剧集目录：{title} ({year}) {tmdb-id}
季度目录：Season {season:02d}
单集文件：{title} - S{season:02d}E{episode:02d} - {episode-title}{technical-tags}.{ext}
```

要求：

- `{tmdb-id}` 使用媒体服务器兼容格式，技术验证后冻结。
- 支持多集 `S01E01-E03` 和特别篇。
- 清理不受支持字符，统一空格和标点。
- 保留扩展名，不修改媒体内容。
- 伴随文件随主视频移动并按媒体服务器约定重命名。
- 同名冲突不得覆盖，必须进入冲突流程。
- 相同规则重复执行不得产生二次改名。
- 默认保留分辨率、来源、HDR/DV 和音频标签。

### 7.8 整理计划与执行

真实写操作必须采用两阶段流程：

1. 生成不可变计划，包含源快照、目标路径、动作、依据、风险、规则版本和计划摘要。
2. 用户或具备权限的 Agent 提交计划 ID、摘要和确认参数后执行。

源目录版本变化、计划过期、规则变化或目标冲突时，旧计划失效，必须重新生成。执行过程中发生超时且无法确认远端结果时进入 `uncertain`，先核对 115，不直接重做。

建议状态：

```text
discovered -> parsing -> matching -> planned -> organizing -> organized
                         -> needs_review
                         -> skipped
                         -> failed
organizing -> uncertain
```

### 7.9 洗版策略

只在逻辑对象相同时比较：

- 电影：相同 TMDB ID。
- 单集：相同 TMDB ID、季号和集号。
- 集范围或季度包：覆盖范围一致，或完成逐集覆盖分析。

可配置维度：

- 杜比优先、非杜比优先、不参与比较。
- 大文件优先、小文件优先、不参与比较。
- 杜比和体积的比较优先级。
- 最低差异阈值。
- 仅提示、移入隔离区、永久删除。

规则：

- 默认关闭自动洗版，仅展示比较结果。
- 字段未知时保留旧版或进入确认，不把未知视为较差。
- 新版必须严格胜出才允许替换。
- 体积基于正片视频总大小，不含字幕和花絮。
- Dolby Vision、Dolby Atmos 和普通 Dolby Audio 分开识别。
- 多集资源不能因部分集更优而删除未覆盖集。
- 自动处置默认移入隔离区，保留 7 天。
- 永久删除必须单独开启并二次确认。

### 7.10 完成事件

整理成功必须在持久化操作结果的同一事务或可靠 Outbox 中记录：

- 来源目录 ID。
- 目标目录 ID。
- 新增、移动、重命名、隔离和恢复的文件 ID。
- 目录快照版本。
- 关联整理任务和计划 ID。

REQ-002 消费该事件进行增量同步。事件投递必须幂等，崩溃后不得丢失。

## 8. 管理界面与 API 要求

管理界面至少包含：

- 媒体库和规则配置。
- 扫描、待整理、待确认、冲突、失败、隔离和已完成统计。
- 原路径、目标路径、TMDB 候选、分类、地区和洗版依据。
- 仅预览、人工确认、批量确认、重试和恢复。
- 规则版本与生效范围。

API 只接受系统资源 ID、稳定目录 ID和计划 ID，不接受任意 115 URL、任意绝对路径或原始 Cookie。

## 9. 数据与审计要求

需要持久化：

- 媒体库和目录配置。
- 云端目录/文件稳定 ID、pickcode、路径和快照版本。
- 解析结果、TMDB 候选、置信度和依据。
- 媒体身份、分类、地区和人工锁定。
- 整理计划、步骤、摘要、规则版本和状态。
- 洗版比较、隔离记录和恢复结果。
- Outbox 事件及消费状态。

高风险写操作必须记录操作者、计划、前后对象、原因和结果。日志展示遵循 REQ-004，不记录 Cookie、完整云端路径、分享密码或真实直链。

## 10. 非功能要求

- 115 写接口必须先完成契约验证。
- 所有写操作具备幂等键、租约和崩溃恢复。
- 单文件失败不阻塞其他独立文件。
- 配置、规则和任务支持并发冲突检测。
- 周期扫描使用分页和限流，不一次性加载整库。
- 所有操作受功能开关控制，可快速停止领取新任务。

## 11. 验收标准

- 五类标准样本能进入正确分类和地区目录。
- 电影、单集、多集和特别篇生成媒体服务器兼容名称。
- 同名不同年份、多候选接近和季集越界不会自动误移。
- 重复执行相同规则不会重复移动或重命名。
- 字幕、NFO、图片和音轨与主视频保持关联。
- 目标冲突、115 超时和服务重启不会静默覆盖或重复写入。
- 洗版只在新版本严格胜出时生成替换计划。
- 隔离文件可在保留期内恢复到正确位置。
- 永久删除默认关闭，自动化 Agent 无法绕过。
- 整理完成事件准确覆盖源目录和目标目录，并可被幂等消费。

## 12. 分期建议

1. 契约验证与只读目录索引。
2. 文件解析、TMDB 匹配和整理计划预览。
3. 人工确认后的安全移动和命名。
4. 分类、地区和伴随文件完善。
5. 洗版提示、隔离和恢复。
6. 自动洗版在观察期通过后按媒体库启用。
