## 1. 一句话定义

通过受控直链探测和媒体分析，获取真实容器、视频、音频、字幕和时长信息，并以分级证据识别标签虚标、无法解析和潜在损坏风险，为质量策略、洗版和媒体库体检提供依据。

## 2. 背景与问题

当前技术标签主要来自文件名和资源描述，可能存在缺失或虚标。REQ-018 默认不读取完整媒体内容，只能发现目录、清单和直链层面的异常，无法回答：

- 文件标记为 4K/Dolby Vision，实际视频轨是否符合。
- 文件是否能解析出有效时长、视频轨和音频轨。
- 内封字幕语言和默认/强制标记是否真实存在。
- 同一影片两个版本的编码、位深、HDR 和音轨哪个更符合质量策略。
- STRM 可以解析直链，但媒体文件头是否损坏或容器索引是否异常。

完整下载大型文件进行校验成本过高，因此必须区分快速元数据探测、分段抽样和完整验证，不能用有限抽样得出“文件完全无损”的结论。

## 3. 产品目标

- 使用真实媒体流提取标准化技术元数据。
- 对比文件名声明与实测结果并标记差异。
- 为 REQ-008 和 REQ-001 提供可信的洗版比较字段。
- 识别无法打开、无视频轨、时长异常、容器索引异常等风险。
- 支持按新入库、待洗版、体检异常和人工请求触发。
- 限制下载量、并发和直链暴露，避免影响 115 账号与带宽。
- 明确展示检测深度、证据范围和最后检测时间。

## 4. 非目标

- 不默认完整下载或播放整部影片。
- 不做转码、修复、重新封装或音视频内容修改。
- 不承诺快速探测能发现所有中段数据损坏。
- 不进行画面质量、美学评分或版权内容识别。
- 不把外部字幕正文和媒体样本长期保存。
- 不让 Agent 获取真实直链或任意读取云端文件。

## 5. 用户场景

### 5.1 文件名标签虚标

文件名包含 `2160p DV Atmos`，实测为 1080p HDR10 且没有 Atmos。系统显示字段差异，质量策略使用实测值，并阻止自动洗版直接采信文件名。

### 5.2 新资源快速探测

整理完成后，系统在限额内读取媒体头和必要索引，提取时长、分辨率、编码、HDR、音轨和字幕轨摘要，结果写入库存。

### 5.3 疑似损坏

探测器无法解析容器或发现时长为零。资源标记为 `suspect`，进入体检问题清单，不自动删除，也不自动替换现有正常版本。

### 5.4 深度抽样

用户对重要版本发起抽样验证。系统在多个时间点执行有限读取，任何一个采样失败都记录位置摘要；全部采样成功只表示“抽样通过”，不表示完整文件已验证。

## 7. 检测等级

### 7.1 L1 快速元数据探测

目标是以最小读取量获取容器和轨道信息：

- 优先使用 Range 请求读取文件头、尾部索引和工具明确需要的区段。
- 获取容器、时长、轨道、编码、分辨率、帧率、位深和 HDR 摘要。
- 设置单文件最大读取量和总超时。
- 无法通过 Range 完成时返回 `insufficient_data`，不得自动升级为完整下载。

### 7.2 L2 分段抽样验证

- 在开头、中段和尾部等多个时间点读取受限片段。
- 验证容器可 seek、轨道可解码到基本帧或数据包边界。
- 记录采样点数量、成功数量和失败原因，不保存媒体片段。
- 结果只能标记为“抽样通过”或“抽样发现异常”。

### 7.3 L3 完整校验

Could 能力，需要显式启用、容量预算和独立工作目录。可以完整读取流、计算校验或执行全文件解码检查。V1 不把 L3 作为自动入库前置条件。

## 8. 技术元数据模型

### 8.1 容器与文件

- 容器格式、文件大小、时长和总体码率。
- 可 seek 状态、索引状态和探测工具版本。
- 检测等级、读取字节数、耗时和完成时间。

### 8.2 视频轨

- 编码、Profile、Level、分辨率和显示比例。
- 帧率、扫描方式、位深和色度采样。
- HDR10、HDR10+、HLG、Dolby Vision 及可识别 Profile。
- 默认轨、语言和标题摘要。

### 8.3 音频轨

- 编码、Profile、声道布局、采样率和码率。
- Dolby Atmos、DTS:X 等可验证对象音频标记。
- 语言、默认、强制和描述音轨标记。

### 8.4 字幕和其他轨道

- 字幕编码、语言、默认、强制和听障标记。
- 章节数量和附件摘要。
- 不保存字幕正文、字体附件内容或媒体帧。

## 9. 状态与原因码

检测状态：

- `metadata_verified`：L1 成功提取主要元数据。
- `sampled_ok`：L2 采样点全部通过，仅代表抽样范围。
- `suspect`：发现可解释异常，需要复查。
- `failed`：无法获取直链或探测任务终态失败。
- `unknown`：未检测、证据不足或结果已过期。

主要原因码：

- `direct_link_unavailable`
- `range_not_supported`
- `container_unrecognized`
- `header_parse_failed`
- `no_video_track`
- `duration_invalid`
- `seek_failed`
- `sample_decode_failed`
- `declared_metadata_mismatch`
- `probe_timeout`
- `read_budget_exceeded`
- `tool_incompatible`

不得提供没有检测深度和证据的笼统“文件正常”。

## 10. 文件名与实测字段对比

- 保存“声明值”和“实测值”，不得直接覆盖原始解析结果。
- 实测值存在且探测可靠时，质量策略优先使用实测值。
- 字段冲突显示中文差异，例如“文件名标记 2160p，实测为 1080p”。
- 无法实测不代表文件名声明为假，状态保持未知。
- Dolby Vision、Atmos 等必须由对应轨道证据确认，普通 Dolby Audio 不等同 Atmos。
- 对比规则和探测工具升级后，旧结果按版本标记是否需要重检。

## 11. 任务与资源控制

- 新入库资源默认只触发 L1，L2 由质量策略、异常或人工请求触发。
- 检测队列独立于资源搜索和 115 整理写队列。
- 按账号、媒体库和全局限制并发、每小时读取量和每日读取量。
- 115 限流、needs_auth 或直链异常时暂停新任务并退避。
- 相同文件 ID、修改版本、检测等级和工具版本使用幂等键。
- 任务超时只终止本次探测，不删除文件或自动重试高成本检测。
- 临时数据写入受限目录，任务结束或崩溃恢复时安全清理。

## 12. 业务联动

- **REQ-001/008**：洗版和质量排序优先使用实测技术字段；未知字段遵守保守策略。
- **REQ-002**：通过受控播放解析器获取短期直链，不向检测调用方暴露真实 URL。
- **REQ-010**：库存保存检测版本、状态和技术摘要。
- **REQ-014**：内封字幕轨摘要用于判断是否缺少指定语言字幕。
- **REQ-018**：把探测失败、标签冲突和过期结果纳入体检，并生成复检计划。

`suspect` 只能阻止自动洗版或进入人工确认，不能直接触发永久删除。

## 13. 界面与 API

媒体详情展示：

- 检测等级、状态、最后时间、读取量和工具版本。
- 容器、视频、音频、字幕和章节摘要。
- 文件名声明与实测差异。
- 异常原因、影响和建议下一步。
- “快速重检”和具备权限时的“分段抽样”。

批量页面支持按未检测、结果过期、疑似损坏、标签冲突和检测失败筛选。API 只接受内部文件 ID和检测等级，不接受任意 URL或绝对路径。

## 14. 安全与隐私

- 真实直链只在服务端短期内存中使用，不写数据库、日志、任务结果或消息队列。
- 探测进程使用无网络回连、只读工具和资源限制的隔离环境。
- 工具输入只能来自受管 115 文件 ID和经过验证的直链解析器。
- 限制 CPU、内存、临时磁盘、运行时间、读取字节和子进程数量。
- 不保存媒体片段、截图、字幕正文或附件内容。
- 工具 stderr 经过长度限制和脱敏，不直接展示第三方原始输出。

## 15. 日志与指标

遵循 REQ-004，记录：

- 检测任务创建、领取、完成、取消、超时和失败。
- 检测等级、工具版本、读取量、耗时和状态计数。
- 直链失败、Range 不支持、解析异常和标签冲突的原因码。
- 账号级限流、任务积压和临时目录清理结果。

日志不记录真实直链、完整文件名、路径、媒体内容或工具完整原始输出。

核心指标包括成功率、P50/P95 耗时、平均读取量、各原因码占比、标签冲突率和 L2 异常发现率。

## 16. 验收标准

- MKV、MP4、TS/M2TS 等标准样本可以提取约定的容器和轨道字段。
- 1080p/2160p、HDR10、Dolby Vision、Atmos 和普通 Dolby Audio 样本能正确区分。
- 文件名声明与实测不一致时保留两者并产生明确差异。
- L1、L2 和 L3 结果在界面和 API 中不会混淆。
- L2 全部采样成功只显示“抽样通过”，不显示“完整文件无损”。
- 无视频轨、无效时长、无法 seek 和采样解码失败样本能生成稳定原因码。
- 相同文件和工具版本不会重复创建相同等级任务。
- 达到读取预算、并发或 115 限流时任务安全延后，不影响播放和整理主流程。
- 探测失败不会删除、移动、隔离或自动替换媒体文件。
- 数据库、日志、导出和任务结果中不存在真实直链或媒体片段。

## 17. 分期建议

1. 验证 115 直链 Range、工具安全边界和读取成本。
2. 实现 L1 快速探测、技术元数据模型和单文件页面。
3. 接入库存、质量策略、洗版和字幕轨摘要。
4. 实现 L2 分段抽样、体检问题和批量重检。
5. 根据真实成本决定是否建设 L3 完整校验。

## 18. 风险与依赖

| 风险 | 缓解措施 |
|---|---|
| 115 直链不支持稳定 Range | Phase 0 契约验证，失败则只保留可行等级 |
| 探测消耗大量带宽 | 字节预算、分级检测、限流和缓存 |
| 恶意媒体触发工具漏洞 | 隔离进程、版本锁定、资源限制和安全更新 |
| 抽样结果被误解为完整性 | 明确等级、证据和禁止“完全正常”文案 |
| 实测字段误导洗版 | 保存证据和版本，未知/冲突进入确认 |
| 直链泄漏 | 内存短期使用、统一脱敏和禁止出现在任务输出 |

## 19. 待确认项与建议默认值

| 决策项 | 建议默认值 |
|---|---|
| 新入库自动检测 | L1 快速探测 |
| L2 抽样 | 异常、洗版候选或人工触发 |
| L3 完整校验 | 关闭 |
| 自动删除 | 禁止 |
| 质量字段优先级 | 可靠实测值优先，保留声明值 |
| 媒体片段持久化 | 禁止 |
| 真实直链输出 | 禁止 |
