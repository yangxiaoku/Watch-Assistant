# REQ-019：Webhook 与自动化接口

| 字段 | 内容 |
|---|---|
| 版本 | V1.0 |
| 状态 | 待评审 |
| 优先级 | P2 |
| 依赖 | REQ-004、REQ-012、事件 Outbox |

## 1. 一句话定义

把系统中的受控业务事件以签名 Webhook 可靠发送给家庭自动化和其他服务，并提供有限、版本化的自动化 API。

## 2. 目标与非目标

目标：

- 用户可订阅资源、任务、整理、STRM、存储和安全事件。
- Webhook 具备签名、重试、去重和投递记录。
- 事件 Schema 稳定并可版本化。

非目标：

- 不向任意内网地址发送请求。
- 不发送 Cookie、Token、完整路径、磁力或真实直链。
- 不允许 Webhook 回调直接绕过计划审批。
- 不建设通用工作流引擎。

## 3. 功能范围

| 编号 | 功能 | 优先级 |
|---|---|---|
| WH-001 | Webhook 端点配置和验证 | Must |
| WH-002 | 事件订阅和 Schema 版本 | Must |
| WH-003 | HMAC 签名和重放保护 | Must |
| WH-004 | Outbox、重试和死信 | Must |
| WH-005 | 投递日志和测试事件 | Must |
| WH-006 | 受限自动化 API | Should |

## 4. 事件载荷

统一包含：事件 ID、事件码、版本、时间、资源类型、内部资源 ID、状态、请求/关联/任务 ID和脱敏摘要。

事件示例：

- 订阅发现资源。
- workflow 等待确认、完成或失败。
- 整理完成。
- STRM 增量完成或清理被阻止。
- 存储达到阈值。
- 安全状态和凭据失效。

## 5. 安全规则

- 端点只允许 HTTPS，LAN 明确配置除外。
- 使用出站域名/IP 白名单，解析后阻止回环、链路本地和未授权私网地址。
- 每个端点使用独立 Secret 进行 HMAC 签名。
- 包含时间戳和事件 ID防重放。
- 重定向默认禁止或重新执行目标安全校验。
- Secret 只显示一次并可轮换。

## 6. 可靠投递

- 业务事务写入 Outbox 后异步投递。
- 相同事件和端点使用稳定幂等 ID。
- 2xx 视为成功，其他状态按策略重试。
- 指数退避，超过次数进入死信。
- 可手动重试死信，但不重新生成事件。

## 7. 界面要求

- 创建端点、选择事件、测试、暂停和删除。
- 展示最后成功、失败率、下一次重试和死信数。
- 查看脱敏请求摘要与响应状态，不展示 Secret 和完整第三方正文。

## 8. 验收标准

- 签名可验证，篡改载荷验证失败。
- SSRF 测试中的非法目标被拒绝。
- 服务重启后未投递事件不丢失。
- 重试使用相同事件 ID，接收方可幂等。
- 一个端点失败不阻塞其他端点。
- Payload 不包含任何敏感字段。
- Schema 升级遵循版本兼容策略。

## 9. 分期建议

1. Schema、签名和单端点投递。
2. Outbox、重试、死信和管理页。
3. 事件选择、Secret 轮换和受限 API。

## 10. 待确认项与建议默认值

| 决策项 | 默认值 |
|---|---|
| 协议 | HTTPS |
| 重试次数 | 8 次 |
| 请求超时 | 10 秒 |
| 重定向 | 禁止 |
| Secret | 每端点独立 |
| Payload | 仅内部 ID和脱敏摘要 |

## 11. 当前实现证据（2026-07-31）

- 已实现管理员保护的单端点测试投递入口；测试事件使用版本化 `webhook.test` 事件码，
  进入同一持久 Outbox，不直接发送请求。
- 禁用端点拒绝测试排队；投递仍复用现有 HMAC、重试、死信和投递查询。
- `watchctl webhook test <endpoint-id>` 已接入同一测试投递 API，复用 Agent 认证、Scope、错误码和统一 JSON/JSONL envelope。
- `watchctl webhook list`、`webhook deliveries` 和 `webhook retry` 已接入端点、投递查询和服务端死信重试 API；重试资格仍由服务端状态机判断。
- 真实接收端篡改/重放/重启恢复和完整业务事件矩阵仍未验收，不能宣称 REQ-019 已完成。
