# 2026-08-15 订阅、季度搜索与自动清理设计

## 背景

用户反馈以下问题与需求：

1. 切换剧集季度后资源列表为空或报错。
2. 希望在影视资源搜索/详情界面直接看到“订阅”按钮。
3. 订阅需要更智能：自动查询当前剧集集数，若整季已齐全则自动暂停订阅。
4. 需要实现自动清理垃圾文件和空文件（仅回收站，不永久删除）。

## 目标

- 修复季度搜索空结果/报错体验。
- 在详情页标题操作区提供订阅入口。
- 订阅检查时自动判断整季是否齐全，任一来源满足即自动暂停。
- 在受管且扫描完整的前提下，自动把广告/垃圾小文件和空目录移入 115 回收站。

## 非目标

- 不永久删除任何文件。
- 不清理未受管目录或扫描不完整的范围。
- 不改变现有 115 写操作的安全门禁。
- 不实现“自动洗版/自动升级”。

## A. 剧集季度搜索

### 现状

- 后端按 `(media_type, tmdb_id, season_number)` 独立缓存和搜索。
- 切换季度会触发该季度的新搜索；如果该季度没有独立结果，可能因缓存过期/搜索失败而显示错误或空白。
- 前端已有按季度传参逻辑，但空结果提示不明确。

### 设计

1. 后端：
   - 季度搜索返回正常 `ready + 0 条`，不因“该季无独立结果”而报错。
   - 保持现有 fail-closed 行为：只有搜索源全部不可用或内部异常才返回错误。
   - 继续使用 `build_search_queries(media, season_number)` 生成“剧名 + 第X季 / SXX”查询，不把关键词变成单集。

2. 前端：
   - 当 `season_number` 已选择且资源 `total === 0` 时，资源区显示明确空态：
     - “当前季度暂无独立资源”
   - 空态保留“刷新资源”入口，允许用户手动重试。
   - 不自动回退展示其他季资源（用户已确认保持空并提示）。

3. 测试：
   - 后端：季度搜索无结果时返回 `ready + total=0`，不抛错。
   - 前端：季度空态文案显示；切换季度不出现“资源分页暂不可用”的误导错误。

## B. 详情页订阅按钮

### 现状

- 订阅管理在独立 `SubscriptionView`，详情页没有订阅入口。

### 设计

1. 在详情页标题/操作区（`MovieView.vue`）增加“订阅”按钮：
   - 电影：订阅 `tmdb_id + media_type=movie`，`season_number=null`。
   - 剧集：若当前已选择季度，订阅 `tmdb_id + media_type=tv + season_number=当前季度`；否则订阅整剧（`season_number=null`）。

2. 进入详情时查询是否已存在同范围订阅：
   - 未订阅：按钮文案“订阅”。
   - 已订阅：按钮文案“已订阅”，点击后跳转订阅管理页；若订阅为 `paused`，显示“已暂停”并允许跳转恢复。
   - 创建订阅后按钮即时更新为“已订阅”。

3. 后端：
   - 复用现有 `POST /api/v1/subscriptions` 创建接口。
   - 新增只读查询能力：`GET /api/v1/subscriptions?tmdb_id=...&media_type=...&season_number=...` 或前端拉全量订阅后本地匹配。优先使用现有全量列表接口，避免新增 API。

4. 移动端同样显示（按钮随详情头部响应式布局）。

5. 测试：
   - 前端：详情页显示订阅按钮；点击创建成功后变为已订阅；剧集随季度变化切换订阅范围。
   - 后端：创建订阅的重复/冲突行为保持现有逻辑。

## C. 智能订阅暂停

### 现状

- `SubscriptionService.check()` 只记录 `MATCHED/NO_MATCH`，不会自动暂停。
- 已有 `episode_completeness.build_episode_matrix` 可判断集数完整性。
- 已有本地库存快照能力 `verified_latest_scan` 和库存身份（含 tmdb_id/season/episode）。

### 设计

1. 在 `SubscriptionService.check()` 中，当订阅为 TV 且 `season_number` 非空时，增加完整性评估：
   - 获取 TMDB 当前季集数作为 baseline（复用 `SeasonMetadataService` 或 TMDB season 接口）。
   - 从本次搜索命中的资源名解析集数范围，使用 `build_episode_matrix` 判断“所有已播出集是否都有覆盖”。
   - 从最近一次完整扫描的库存快照中筛选 `tmdb_id + season` 的文件身份，同样判断集数覆盖。
   - 两个来源任一判定“齐全”即触发自动暂停。

2. 自动暂停语义：
   - 状态设为 `PAUSED`（可手动恢复，不进入终态 `COMPLETED`）。
   - 写审计事件 `subscription.auto_paused`。
   - 发送站内通知（可行动，跳转订阅管理）。
   - 幂等：若已暂停，后续 check 不再重复暂停/通知；若用户手动恢复且仍齐全，下次 check 再次暂停。

3. 边界：
   - 非 TV 订阅不参与集数完整性判断。
   - TMDB 季集信息不可用时，不做自动暂停，保持原逻辑。
   - 库存快照不存在或过期时，只使用搜索资源完整性判断，不阻塞检查。

4. 测试：
   - 单测：搜索资源齐全 → 自动暂停；本地库齐全 → 自动暂停；两者都不齐 → 保持原状态。
   - 集成：订阅 check 后状态与通知事件正确。

## D. 自动清理垃圾/空文件

### 现状

- 已有 `small_file_cleanup`、`empty_directory_cleanup_plan`、`media_parser` 广告/垃圾识别。
- 自动整理调度（`OrganizationAutomationService`）已支持小文件/空目录清理，但依赖整理流程触发，且未单独提供“广告垃圾文件自动清理”。

### 设计

1. 新增“自动清理”执行路径，可在完整扫描通过后独立运行：
   - 输入：受管媒体库范围、最近一次完整扫描快照。
   - 识别：
     - 广告/宣传垃圾文件：使用现有 `media_parser` 的广告特征判定，且无媒体特征。
     - 小文件：低于设置阈值 `small_file_threshold_mb` 的文件（可复用现有小文件清理）。
     - 空目录：目录内无任何受管文件（可复用现有空目录清理）。
   - 执行：全部移动到 115 回收站（`fs_delete`），不永久删除。

2. 安全门禁（必须全部满足才执行）：
   - 扫描完整且为最新修订。
   - 目录属于系统受管范围。
   - 没有 `uncertain` / 范围未验证 / 身份冲突。
   - 仅处理系统受管清单内的对象。
   - 永久删除开关保持关闭。

3. 设置：
   - 保留现有“未识别小文件自动删除（MB）”和“整理后清理空文件夹”。
   - 新增“自动清理广告垃圾文件”开关，默认关闭；开启后在完整扫描通过后自动执行。
   - 三个开关相互独立，但都受同样的安全门禁约束。

4. 审计与通知：
   - 每次自动清理写审计事件 `library.auto_cleanup.applied`（含小文件数、空目录数、广告文件数）。
   - 清理结果通过站内通知汇总；失败/跳过不伪造成功。

5. 测试：
   - 单元：广告垃圾识别、空目录识别、小文件阈值。
   - 集成：受管完整快照下自动清理预览/执行；不安全条件（扫描不完整/范围未验证）拒绝执行。
   - 契约：清理只走回收站，不触发永久删除。
