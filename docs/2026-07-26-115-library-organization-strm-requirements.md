# 115 影视库自动整理与增量 STRM 输出需求报告

文档版本：V1.0
日期：2026-07-26
状态：待产品、技术与运维评审
适用项目：Watch Assistant
目标读者：项目管理、产品、研发、测试、运维

## 1. 执行摘要

本需求拟在现有“影视发现、资源聚合、115 推送”能力之上，建设两条新的核心主线：

1. **115 影视库自动整理**：对进入指定 115 目录的影视文件进行自动识别、TMDB 元数据匹配、分类归档、标准化命名和可控洗版，将“转存来的资源”自动整理成可被 Emby、Jellyfin、Plex 稳定识别的影视库。
2. **115 STRM 全量与增量输出**：为整理后的 115 影视库生成基于 pickcode 的 STRM 文件，并建立“整理完成、增量检测、STRM 更新、元数据同步、失效清理”的持续维护闭环。

两条能力共同构成完整链路：

```mermaid
flowchart LR
    A[115 入库目录] --> B[变化检测]
    B --> C[文件名解析]
    C --> D[TMDB 匹配]
    D --> E[分类与地区归档]
    E --> F[命名标准化]
    F --> G[洗版决策]
    G --> H[整理结果提交]
    H --> I[目录脏标记]
    I --> J[增量 STRM 更新]
    J --> K[元数据同步]
    K --> L[失效项与空目录清理]
    L --> M[Emby / Jellyfin / Plex]
```

一句话定位：**把转存到 115 的资源自动变成结构规范、持续更新、可直接接入媒体服务器的影视库。**

## 2. 背景与现状

### 2.1 当前基础能力

项目已经具备以下可复用基础：

- TMDB 电影、电视剧元数据查询及季度信息。
- PanSou 资源聚合、磁力去重、质量评分和内容检测。
- 115 磁力或分享推送相关适配能力与任务状态机。
- SQLite 持久化、后台任务、失败重试、设置中心和脱敏日志。
- 单用户、自托管、局域网或 Tailscale 访问模式。

### 2.2 当前缺口

现有链路主要结束在“资源已推送或已转存到 115”，尚未覆盖后续影视库建设：

- 进入 115 的文件仍需要人工判断片名、年份、媒体类型和剧集集号。
- 目录结构与文件名不统一，媒体服务器识别率不稳定。
- 同一影片或剧集存在多个版本时，缺少统一、可解释的洗版规则。
- 115 目录变更后，STRM 需要人工全量重建，更新成本高。
- STRM、字幕、封面、NFO 等文件之间缺少一致性维护和失效清理。

### 2.3 需求性质说明

本报告描述的是**拟新增的目标能力**，不应在正式上线和验收完成前对外表述为当前已具备能力。

## 3. 产品目标与非目标

### 3.1 产品目标

- 将 115 指定入库目录中的影视资源自动整理到规范媒体库目录。
- 降低电影、剧集、动漫、纪录片和综艺的人工识别与分类成本。
- 提高 Emby、Jellyfin、Plex 的媒体识别成功率。
- 通过可配置洗版规则减少重复资源，保留更符合用户偏好的版本。
- 支持 115 整库 STRM 全量生成，并在文件变化后只更新受影响目录。
- 保证整理和 STRM 任务幂等、可重试、可审计、可恢复。
- 保证 115 Cookie、直链和其他敏感信息不进入 STRM 文件、日志或前端。

### 3.2 非目标

首期不包含：

- 视频转码、媒体内容编辑或封装格式转换。
- 替代 Emby、Jellyfin、Plex 的媒体库和播放能力。
- 公网多用户、角色权限、配额和商业化计费。
- 对低置信度 TMDB 匹配进行无确认的强制自动整理。
- 删除不属于本系统管理范围的本地文件或 115 文件。
- 将有时效的 115 真实直链静态写入 STRM。

## 4. 用户与核心场景

### 4.1 目标用户

- 在 115 中保存电影、剧集、动漫、纪录片或综艺的个人用户。
- 使用 Emby、Jellyfin 或 Plex 管理和播放个人影视库的用户。
- 希望资源转存后自动完成归档、命名和 STRM 更新的自托管用户。

### 4.2 核心场景

**场景 A：新电影转存后自动入库**
用户将一部电影推送到 115 入库目录。系统识别文件名，匹配 TMDB，归档到“电影/地区/片名 (年份) {tmdb-id}”，完成标准化命名，并增量生成 STRM 与元数据。

**场景 B：电视剧持续更新**
剧集目录新增一集。系统识别 SxxExx，只处理变化目录，将文件移动到对应季度，更新该集 STRM，不重扫整库。

**场景 C：同集出现更合适版本**
同一集已有普通版，后来新增杜比版。若配置“杜比优先”，系统将新版本设为主版本，把旧版本移入隔离区并更新 STRM 指向。

**场景 D：整理过程中目录再次变化**
某目录正在生成 STRM 时又新增文件。系统不并发重复处理同一目录，而是标记为 dirty；当前任务结束后自动再次入队。

**场景 E：无法可靠识别**
文件名缺少年份、剧集编号或存在多个相近 TMDB 结果。系统不自动移动文件，而是进入待确认队列，展示候选结果和匹配依据。

## 6. 主线一：115 影视库自动整理

### 6.1 目录与触发模型

系统必须区分以下目录角色：

- **入库目录**：接收磁力离线下载、115 分享转存或人工上传的原始资源。
- **媒体库目录**：完成识别和整理后的正式目录。
- **待确认目录**：低置信度、字段缺失或冲突资源的暂存区域。
- **隔离目录**：洗版淘汰、命名冲突或回滚保护文件的暂存区域。

支持一个或多个入库目录映射到一个或多个媒体库目录。系统不得处理配置范围之外的 115 目录。

触发方式：

- 推送或转存任务确认完成后触发定向扫描。
- 定时扫描入库目录，补偿外部上传和漏事件。
- 用户在管理页面手动发起目录扫描。
- 系统重启后恢复未完成任务，并重新核对可能发生变化的目录。

目录扫描必须保存游标或快照，优先按目录 ID、文件 ID、pickcode、修改时间等稳定字段判断变化，避免每次全量读取。

### 6.2 文件发现与候选集合

系统必须识别：

- 视频文件及视频所在文件夹。
- 独立字幕、图片、NFO、音轨和其他允许同步的伴随文件。
- 单文件电影、电影文件夹、单集剧集、季度包、多季度合集。
- 样片、预告片、花絮和非正片文件。

默认视频扩展名至少包括：`mkv`、`mp4`、`avi`、`mov`、`ts`、`m2ts`、`wmv`、`flv`、`webm`。

样片、预告片和花絮不得参与正片洗版。系统应使用文件名标记、目录位置、时长或体积等信息进行识别；无法判断时保留并标记待确认。

### 6.3 文件名解析

解析器应尽可能提取：

- 片名、原名和别名。
- 上映年份或首播年份。
- 季、集、集范围和特别篇编号。
- 分辨率：720P、1080P、2160P 等。
- 来源：BluRay、REMUX、WEB-DL、HDTV 等。
- 视频编码：H.264、H.265/HEVC、AV1 等。
- HDR、HDR10+、Dolby Vision 等动态范围信息。
- 音频编码、声道、杜比全景声等音轨信息。
- 语言、字幕、版本组和发布组信息。

解析结果必须保留原始文件名和解析依据，便于审计和人工纠错。

### 6.4 TMDB 自动识别与刮削

#### 6.4.1 匹配流程

1. 使用解析出的片名、年份和媒体类型查询 TMDB。
2. 对中文名、原名、别名、年份和媒体类型进行综合评分。
3. 剧集必须进一步校验季号和集号是否落在 TMDB 已知范围内。
4. 选择最高分候选，并记录第二候选与分差。
5. 达到自动匹配阈值才允许进入自动整理；否则进入待确认队列。

#### 6.4.2 置信度要求

- **高置信度**：自动整理。
- **中置信度**：默认进入待确认，可由用户配置为自动整理。
- **低置信度或无结果**：禁止移动或覆盖，进入待确认。
- 同名不同年份、电影和剧集同名、季集越界、多个候选分差过小均应降低置信度。

置信度阈值必须可配置，但系统需提供安全默认值。

#### 6.4.3 人工纠错

待确认页面至少支持：

- 查看原文件名、解析字段、候选海报、年份、类型和匹配分数。
- 选择正确的 TMDB 条目。
- 手工修改季号、集号或媒体类型。
- 标记忽略、稍后处理或永久排除。
- 保存“名称别名到 TMDB ID”的匹配规则，供后续同类文件复用。

### 6.5 五大主分类自动归档

目标主分类：

1. 电影
2. 剧集
3. 动漫
4. 纪录片
5. 综艺

分类必须基于 TMDB 媒体类型、Genre、Keyword、原产国家和可配置规则共同判断，不得只依据文件名关键字。

默认分类优先级建议如下：

1. TMDB 纪录片 Genre 命中时归入“纪录片”。
2. TMDB 动画 Genre 命中且符合用户配置的动漫范围时归入“动漫”。
3. Reality、Talk、News 等配置的电视 Genre 命中时归入“综艺”。
4. 其余 TV 类型归入“剧集”。
5. 其余 Movie 类型归入“电影”。

分类规则要求：

- 分类优先级和 Genre 映射可配置。
- 用户人工纠正后的分类优先于自动规则。
- 已确认条目在后续重扫时不得因 TMDB 字段轻微变化被自动改类。
- 动画电影是否进入“动漫”由配置决定，默认进入“动漫”。

### 6.6 地区二级归类

五大主分类下支持二级地区目录：

- 国产
- 欧美
- 日韩
- 其他

默认国家映射建议：

- 国产：中国大陆、香港、澳门、台湾。
- 日韩：日本、韩国。
- 欧美：北美、欧洲及用户配置的欧美国家集合。
- 其他：未命中以上规则或 TMDB 国家信息缺失。

地区判断使用 TMDB 原产国家或制作国家。多国合拍时按配置的国家优先级选择一个主地区；默认使用 TMDB 返回的首个有效原产国家。人工选择结果必须可锁定。

示例目录：

```text
影视库/
  电影/
    国产/
    欧美/
    日韩/
    其他/
  剧集/
  动漫/
  纪录片/
  综艺/
```

地区二级归类应允许整体关闭。关闭后直接写入主分类目录。

### 6.7 命名标准化

系统必须分别提供目录模板和文件模板，并支持预览。模板字段至少包含：

- 中文名、原名、年份、TMDB ID。
- 季号、集号、集标题。
- 分辨率、来源、视频编码、HDR/Dolby Vision、音频标记。
- 版本组或发布组。

推荐默认模板：

```text
电影目录：{title} ({year}) {tmdb-id}
电影文件：{title} ({year}) {tmdb-id}{technical-tags}.{ext}

剧集目录：{title} ({year}) {tmdb-id}
季度目录：Season {season:02d}
单集文件：{title} - S{season:02d}E{episode:02d} - {episode-title}{technical-tags}.{ext}
```

其中 `{tmdb-id}` 输出为媒体服务器兼容的固定格式，例如 `{tmdb-12345}`。实际格式应在兼容性验证后冻结。

命名要求：

- 清理目标文件系统不支持的字符，统一空格和标点。
- 保留文件扩展名，不改变媒体内容。
- 多集文件支持 `S01E01-E03` 等稳定格式。
- 字幕、音轨、NFO 和图片应随主文件同步改名或移动。
- 同名冲突不得静默覆盖；进入冲突处理流程。
- 重复执行相同规则不得再次改名，即操作幂等。
- 用户可选择是否保留技术标签；默认保留分辨率、来源、HDR/DV 和音频标签。

### 6.8 洗版覆盖策略

#### 6.8.1 洗版对象

系统只在以下逻辑对象相同的资源之间比较版本：

- 电影：相同 TMDB ID。
- 单集剧集：相同 TMDB ID、季号和集号。
- 多集文件或季度包：覆盖集范围一致，或经过逐集覆盖分析后才可比较。

无法确认逻辑对象相同的文件不得自动洗版。

#### 6.8.2 用户策略

每个媒体库可配置：

- 杜比策略：杜比优先 / 非杜比优先 / 不参与比较。
- 体积策略：大文件优先 / 小文件优先 / 不参与比较。
- 策略优先级：先比较杜比，再比较体积；或先比较体积，再比较杜比。
- 最低差异阈值：新版本必须明显优于旧版本才触发替换。
- 处置方式：仅提示 / 移入隔离区 / 自动删除。

首期默认：**杜比不参与比较、体积不参与比较、仅提示**。用户启用自动洗版后，默认采用“移入隔离区”，不直接永久删除。

#### 6.8.3 决策规则

- 仅当新资源在已启用规则下严格胜出时替换。
- 规则结果相同则保留现有主版本，避免反复切换。
- 体积比较基于正片视频总大小，不把字幕、花絮和样片计入。
- “杜比”必须区分 Dolby Vision、Dolby Atmos 和普通 Dolby Audio，具体参与比较的标记可配置。
- 不得因单个缺失字段推断为较差版本；字段未知时进入待确认或按保守策略保留旧版。
- 多集资源不能因为部分集更优就删除其他未覆盖集。
- 洗版完成后必须触发相关目录的 STRM 增量更新。

#### 6.8.4 安全与回滚

- 隔离文件保留期默认 7 天，可配置 1 至 30 天。
- 隔离记录保存原路径、目标路径、规则版本、比较字段和操作时间。
- 隔离期内支持一键恢复；恢复前检查目标路径冲突。
- 永久删除必须单独启用并进行二次确认。

### 6.9 整理任务状态

建议状态机：

```text
discovered -> parsing -> matching -> planned -> organizing -> organized
                         -> needs_review
                         -> skipped
                         -> failed
organizing -> uncertain
```

状态语义：

- `discovered`：发现新文件或目录。
- `parsing`：解析文件名和技术标签。
- `matching`：查询并匹配 TMDB。
- `planned`：已生成整理计划，尚未执行 115 写操作。
- `organizing`：正在移动或重命名。
- `organized`：整理提交成功，已发出 STRM 脏目录事件。
- `needs_review`：需要人工确认。
- `skipped`：被规则排除或用户忽略。
- `failed`：确认未产生目标变更，可安全重试。
- `uncertain`：115 返回超时或服务崩溃，无法确认操作结果；必须先核对远端状态，不得直接重做。

## 7. 主线二：115 STRM 全量与增量输出

### 7.1 STRM 输出目录

每个 115 媒体库映射一个本地 STRM 根目录。输出目录结构默认镜像整理后的 115 目录结构。

系统必须维护“115 文件 ID / pickcode / 云端路径 / 本地 STRM 路径”的受管清单。后续更新和清理只能操作清单内或带有系统管理标记的文件，避免误删用户自行维护的内容。

### 7.2 115 STRM 全量生成

用户可对指定媒体库执行全量生成：

1. 扫描媒体库范围内的所有目录和视频文件。
2. 读取文件 ID、pickcode、文件名、路径、大小和修改时间。
3. 根据云端相对路径创建本地目录。
4. 为每个视频原子生成一个 `.strm` 文件。
5. 下载或生成配置范围内的伴随元数据。
6. 对比受管清单，清理已失效 STRM 和空目录。
7. 输出成功、跳过、失败、清理和待重试数量。

全量任务支持取消和断点续跑。取消不得留下半写入 STRM 文件。

### 7.3 pickcode 类型 STRM 与动态直链

STRM 不直接保存有时效的 115 下载 URL，也不得包含 115 Cookie。STRM 内容应指向 Watch Assistant 提供的稳定播放入口，并以 pickcode 作为远端文件标识，例如：

```text
http://watch-assistant.local/api/v1/strm/play?pickcode=<pickcode>&token=<play-token>
```

示例仅表示产品契约，最终路径和鉴权方式由技术设计冻结。

播放入口要求：

- 接收合法 pickcode 后按需向 115 请求最新直链。
- 优先使用低延迟接口，成功后以 HTTP 重定向返回真实直链。
- 支持媒体服务器常用的 `HEAD`、`GET` 和 Range 播放场景。
- 对短期重复请求使用安全、短时缓存，避免每次播放都请求 115。
- 直链过期、Cookie 失效或文件不存在时返回明确错误，并记录脱敏事件。
- play token 可单独撤销，不复用 Web 密码、会话 Cookie 或 115 Cookie。
- 不允许通过接口请求配置媒体库范围之外的任意 115 文件。
- 日志不记录完整 token、Cookie 或带签名的 115 直链。

### 7.4 整理后的自动增量同步

整理任务成功后必须发送“受影响目录”事件，STRM 模块只更新本轮实际变化目录。

变化类型及预期动作：

| 115 变化 | STRM 动作 |
|---|---|
| 新增视频 | 创建对应 STRM，更新清单 |
| 视频重命名 | 原子创建新 STRM，删除旧受管 STRM |
| 视频移动 | 在新目录创建 STRM，清理旧路径 |
| 视频删除或移入隔离区 | 删除对应受管 STRM |
| pickcode 变化 | 更新清单，重写对应 STRM |
| 新增或修改元数据 | 下载或覆盖对应本地元数据 |
| 删除元数据 | 按清理策略删除对应受管本地文件 |
| 目录分类或地区变化 | 增量迁移该目录的 STRM 和元数据 |

增量更新不应触发无关目录扫描。一次整理事务涉及多个目录时，应同时把源目录和目标目录标记为 dirty。

### 7.5 元数据增量下载

系统支持同步以下伴随文件：

- 字幕：`srt`、`ass`、`ssa`、`sub`、`vtt` 等。
- 封面与背景图：`jpg`、`jpeg`、`png`、`webp` 等。
- NFO：电影、剧集、季度和单集 NFO。
- 独立音轨：`mka`、`aac`、`ac3`、`eac3`、`dts`、`flac`、`mp3` 等。
- 用户配置的其他扩展名。

同步规则：

- 扩展名允许列表、单文件体积上限和总并发可配置。
- 优先同步 115 中与主视频同目录、同名或媒体服务器约定名称的文件。
- 由 TMDB 刮削得到的 NFO、poster、fanart 可按模板生成；与 115 已有文件冲突时遵循配置的来源优先级。
- 元数据写入使用临时文件加原子替换，失败时保留旧版本。
- 使用文件 ID、大小、修改时间或内容摘要判断变化，未变化文件不得重复下载。
- 同名字幕的语言和 forced/SDH 标记应保留在文件名中。
- 大体积独立音轨默认关闭自动同步，需要用户明确启用。

### 7.6 失效 STRM 与空目录清理

清理范围仅限系统受管清单中的文件和由系统创建的空目录。

清理条件：

- 云端文件已删除、移出媒体库或进入隔离区。
- 云端文件路径变化后旧 STRM 已被新路径替代。
- STRM 中 pickcode 已无法在允许目录范围内解析到文件。
- 受管元数据在云端已删除，且配置允许镜像删除。

安全要求：

- 默认先生成清理计划，再执行实际删除。
- 不删除含有非受管文件的目录。
- 不删除媒体库根目录、STRM 根目录或用户配置的保护目录。
- 清理操作写入审计日志，并可配置本地回收站或延迟删除。
- 全量扫描发生上游分页错误或扫描不完整时，禁止执行删除阶段。

### 7.7 目录级去重与脏标记重试

任务去重键采用“媒体库 ID + 稳定云端目录 ID”，不得只使用可变化的目录路径。

同一目录状态机：

```text
clean -> queued -> running -> clean
                   |   ^
                   v   |
                 dirty-+
running -> failed -> retry_wait -> queued
```

行为要求：

- 同一目录同一时刻最多有一个 STRM 更新任务。
- 目录已在 `queued` 时再次变化，只更新变更版本号，不重复入队。
- 目录处于 `running` 时再次变化，标记 `dirty`。
- 当前任务完成后若发现 `dirty` 或版本号前进，立即再执行一次。
- 失败任务采用指数退避并限制最大重试次数。
- Cookie 失效、限流等全局错误应暂停同类任务，避免大量无效重试。
- 系统重启后恢复 `queued` 和 `retry_wait`；遗留 `running` 必须重新核对输出与清单。
- 多个子目录变化可合并为最小公共受影响范围，但不得扩大为无条件整库扫描。

## 8. 管理界面需求

### 8.1 影视库配置

设置中心新增“影视库整理”和“STRM 输出”模块，至少支持：

- 配置入库、媒体库、待确认、隔离和本地 STRM 目录。
- 开关地区二级分类及配置国家映射。
- 配置分类优先级和动漫、综艺识别范围。
- 编辑并预览电影、剧集、季度、单集命名模板。
- 配置 TMDB 自动匹配阈值。
- 配置杜比与体积洗版策略、比较优先级和隔离保留期。
- 配置元数据类型、体积限制和来源优先级。
- 配置扫描周期、任务并发和失败重试参数。
- 生成并撤销 STRM play token。

保存配置前必须验证 115 路径、本地路径、模板字段和目录重叠风险。

### 8.2 整理工作台

至少包含：

- 最近发现、待整理、处理中、待确认、失败和已完成数量。
- 每个任务的原路径、目标路径、TMDB 匹配结果、分类、地区和洗版决策。
- “仅预览”模式，不执行任何 115 写操作。
- 批量确认高置信度计划。
- 人工选择 TMDB、修改季集号、分类和地区。
- 单项或批量重试。
- 隔离区查看和恢复。

### 8.3 STRM 工作台

至少包含：

- 各媒体库最近全量时间、最近增量时间和当前队列状态。
- STRM 总数、有效数、失效数、元数据数量和失败数量。
- 正在处理的目录、完成比例、最近错误和下一次重试时间。
- 手动全量生成、目录重建、仅校验、清理预览和失败重试。
- 查看 dirty 目录及其最近变更原因。

### 8.4 通知

Should 范围支持通过现有或新增通知渠道发送：

- 整理任务需要人工确认。
- 批量整理完成或失败率超过阈值。
- 115 Cookie 失效。
- STRM 增量持续失败或积压超过阈值。
- 清理计划包含异常数量的删除项。

## 9. 规则优先级与幂等原则

所有规则按以下优先级执行：

1. 用户对具体媒体项的锁定与人工覆盖。
2. 媒体库级自定义规则。
3. 系统默认规则。
4. 无法判定时进入待确认，不猜测。

幂等要求：

- 相同源文件、相同规则版本和相同目标状态重复执行，结果不得变化。
- 已整理文件不得被入库扫描重复识别为新文件。
- 同一 pickcode 在同一媒体库只对应一个当前有效 STRM。
- 配置变更必须增加规则版本；是否重整历史文件由用户显式发起。

## 10. 数据与审计要求

建议维护以下逻辑数据，不限制最终数据库表结构：

- 媒体库及目录配置。
- 云端目录、文件 ID、pickcode、路径和快照版本。
- 文件名解析结果和 TMDB 候选。
- 已确认的媒体身份、分类、地区和人工覆盖。
- 整理计划、操作步骤、前后路径和任务状态。
- 版本比较记录和洗版决策。
- STRM 受管清单、输出路径、内容摘要和最后同步版本。
- dirty 目录、队列租约、重试次数和错误代码。
- 元数据同步记录和清理记录。

审计记录至少保留 90 天。隔离记录保留时间不得短于对应隔离文件保留期。

日志禁止记录：

- 115 Cookie。
- 完整 play token。
- 带鉴权参数的真实直链。
- 非必要的完整分享密码或磁力链接。

## 11. 异常处理要求

| 异常 | 系统行为 |
|---|---|
| TMDB 无结果 | 进入待确认，不移动文件 |
| TMDB 多候选接近 | 展示候选并等待人工选择 |
| 115 Cookie 失效 | 暂停写操作和直链解析，提示重新授权 |
| 115 限流 | 降低并发，按退避策略重试 |
| 移动或重命名超时 | 标记 uncertain，先读取远端核对结果 |
| 目标路径冲突 | 不覆盖，生成冲突任务 |
| STRM 写入失败 | 保留旧文件，任务进入重试队列 |
| 元数据下载失败 | 不影响有效 STRM，单独记录并重试 |
| 全量扫描不完整 | 允许生成新增项，禁止删除失效项 |
| 目录处理中再次变化 | 标记 dirty，当前任务完成后再次执行 |
| 系统重启 | 恢复持久任务，核对遗留运行态 |

## 12. 非功能需求

### 12.1 安全

- 所有 115 写操作必须经过已验证的接口契约，不直接修改第三方数据库。
- 新目录配置必须限制在明确允许的 115 根目录和本地 STRM 根目录内。
- 防止路径穿越、非法文件名、符号链接逃逸和任意 pickcode 访问。
- STRM 播放入口仅允许局域网/Tailscale，或使用可撤销 play token。
- Cookie 与密钥只在服务端保存，沿用现有 Secret 和日志脱敏机制。

### 12.2 可靠性

- 整理计划必须持久化后再执行远端写操作。
- 任务必须支持崩溃恢复、幂等重试和 uncertain 核对。
- STRM 与清单更新必须保证最终一致性。
- 删除阶段必须晚于完整扫描和新增更新阶段。
- 任意单文件或单目录失败不得阻塞整个媒体库的其他独立任务。

### 12.3 性能目标

以下作为首期验收目标，最终需根据 115 API 限制和服务器配置校准：

- 100 个以内文件变化的增量任务，95% 在触发后 5 分钟内完成。
- 未变化目录不得重复下载元数据或重写 STRM。
- 同一目录并发数固定为 1，不同目录并发可配置。
- 全量扫描使用分页和限流，不一次性加载整库到内存。
- 播放入口在直链缓存命中时应在 500ms 内返回重定向；未命中目标由真实 115 接口压测后冻结。

### 12.4 可观测性

- 输出扫描、识别、待确认、整理、洗版、STRM、元数据和清理的结构化指标。
- 每个任务具备关联 ID，可从整理任务追踪到 STRM 增量任务。
- 设置中心展示队列积压、失败率、最后成功时间和 Cookie 健康状态。

## 14. 验收标准

### 14.1 自动整理验收

- 给定标准电影文件名，能匹配正确 TMDB 条目并归入正确主分类和地区目录。
- 给定标准剧集文件名，能正确识别季号、集号并生成媒体服务器兼容名称。
- 动漫、纪录片和综艺样本能按冻结规则进入对应分类。
- 同名不同年份或多候选样本不会被自动错误移动。
- 分类与命名规则重复执行不产生二次移动或二次改名。
- 字幕、NFO、图片和音轨能与主视频保持目录及命名关联。
- 目标冲突、115 超时和服务重启均不会导致静默覆盖或重复整理。
- 自动洗版启用后，新版本只有在规则严格胜出时才替换；旧版本进入隔离区并可恢复。

### 14.2 STRM 全量验收

- 对指定 115 媒体库完成全量扫描，并为全部支持的视频生成对应 STRM。
- STRM 只包含稳定播放入口与 pickcode，不包含 115 Cookie 或静态真实直链。
- Emby、Jellyfin、Plex 能扫描 STRM，至少完成开始播放、拖动和续播验证。
- 字幕、封面、NFO 按配置同步到正确目录。
- 全量扫描不完整时不会误删现有 STRM。

### 14.3 STRM 增量验收

- 新增、移动、重命名和删除视频只更新受影响目录。
- 整理完成后无需人工触发即可生成对应增量 STRM。
- 同一目录连续触发不会并发重复执行。
- 目录运行中再次变化会在当前任务后自动再执行一次。
- 云端文件失效后，对应受管 STRM 被清理，含非受管文件的目录不会被删除。
- 元数据未变化时不会重复下载；失败可独立重试。
- 服务重启后 queued、dirty 和 retry_wait 状态可以恢复。

### 14.4 安全验收

- 日志、数据库普通展示字段、STRM 和前端响应中均不存在 115 Cookie、完整 play token 或真实签名直链。
- 非法路径、越权 pickcode 和媒体库范围外文件请求被拒绝。
- 永久删除默认关闭；清理和洗版操作具备计划、审计及隔离保护。

## 15. 成功指标

上线后建议观察：

- 自动匹配率：无需人工确认的资源占比。
- 自动匹配准确率：抽样确认的正确匹配比例。
- 待确认率及主要原因。
- 入库到整理完成的中位耗时。
- 整理完成到 STRM 更新完成的 P50/P95 耗时。
- 增量任务占比与避免的全量扫描次数。
- STRM 有效率和播放入口成功率。
- 元数据同步成功率。
- 洗版替换数、隔离恢复数和误替换数。
- 每千个文件的 115 API 请求量和限流次数。

首期核心成功标准：**整理准确优先于自动化率，零静默误删优先于清理速度。**

## 16. 风险与依赖

| 风险或依赖 | 影响 | 缓解措施 |
|---|---|---|
| 115 接口不稳定或版本变化 | 移动、重命名、直链失败 | 前置契约测试、能力开关、版本锁定、降级为只读 |
| pickcode 稳定性与直链限制不明确 | STRM 播放失败 | 验证移动/重命名/复制场景，短时缓存和明确错误码 |
| 文件名高度非标准 | 错误 TMDB 匹配 | 置信度阈值、候选分差、待确认和别名规则 |
| 分类规则存在主观差异 | 动漫、纪录片、综艺误分 | 可配置优先级、人工锁定和规则版本化 |
| 自动洗版具有删除风险 | 误删有效资源 | 默认仅提示、隔离期、可恢复、永久删除单独开启 |
| 大型 115 目录分页和限流 | 全量任务缓慢或不完整 | 分页、限流、断点续跑、不完整扫描禁止清理 |
| 媒体服务器对 STRM 行为不同 | 扫描或播放兼容性问题 | Emby/Jellyfin/Plex 三端验收，冻结播放入口契约 |
| STRM 目录存在用户文件 | 清理误伤 | 受管清单、保护目录、非受管文件阻止删目录 |

## 18. 项目管理建议

该需求不应作为一个不可拆分的大版本一次性交付。建议按“契约验证、整理 MVP、STRM 全量、增量闭环、自动洗版”五个里程碑推进，每个里程碑都需提供：

- 冻结的能力边界和接口契约。
- 可复现的脱敏测试样本。
- 单元、集成和端到端测试。
- 真实 115 账号下的低风险验收记录。
- 功能开关和回滚方案。

其中 Phase 0 是强制门槛。未验证 115 移动、重命名、删除、pickcode 和动态直链接口前，只允许开发只读索引、规则预览和测试替身，不启用真实整理或清理。
